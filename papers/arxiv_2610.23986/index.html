BlenderWorld: Benchmarking Visual Agents for 3D Creation from Real-World References

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 评估多模态大语言模型作为智能体在Blender中完成真实世界3D创建任务的能力

领域标签： 3D创建 / 多模态大语言模型 / 基准测试 / Blender / 智能体评估

快速理解

背景与任务： 现有基准对真实场景中开放式的3D创建与编辑任务覆盖不足，缺乏系统评估。

核心工作： 作者构建了包含223个任务和2651条二元评估标准的BlenderWorld基准，并评测了十三个前沿模型，发现模型在3D空间一致性和结构复现上仍存在明显短板。

中文摘要

多模态大语言模型（MLLMs）的最新进展使其能够充当自主智能体，通过代码或直接操作软件来创建和编辑3D模型。在实际工作流程中，这些模型必须从多样化的参考中推断物体形状、材质、空间布局和光照，同时严格遵守指令以重建、修改或设计3D内容。然而，现有基准对这些跨真实场景的开放式请求覆盖有限。为弥补这一空白，我们推出了BlenderWorld，这是首个专门用于评估前沿模型在真实3D创作任务上表现的综合性基准。BlenderWorld包含223项任务，涵盖建筑、产品、自然环境和科学可视化，由文本、图像、视频和结构化规格输入驱动。为严格评估这些复杂交付成果，我们建立了统一的评估协议：从多个视角渲染提交的Blender项目，并依据2,651条任务特定的二元评分标准以及整体视觉质量评分对其进行评估。对十三个前沿模型的基准测试显示，GPT-6-Astra取得了最高的综合融合得分79.9，其次是Opus-5（73.0）和GPT-5.6-Sol（67.7）。最终，我们的研究揭示了一个关键瓶颈：尽管当前模型能够解析宽泛指令，但在Blender中仍深陷于细粒度3D空间一致性和准确结构复现的困境，这为未来的3D原生智能体留下了巨大的提升空间。

详细分析

1. 任务输入、输出、功能和边界（约100字）

BlenderWorld 的每个任务输入为 \(x=(q,I,F)\)：自然语言请求 \(q\)、可选的图像/视频参考 \(I\)、可选的规格文件 \(F\)（Markdown/YAML/JSON）。输出是可编辑的 Blender 工程 \(B\)、渲染图 \(R\)、动画或视频 \(V\)、辅助文件 \(X\)，以及最终的评估分数。它不要求唯一标准答案，允许多种合法三维实现；评估通过多视角渲染、场景内部检查和任务特定二元标准进行，而不是只比对单一 ground-truth 资产。

2. 研究动机：要解决的问题与核心 insight（约300字）

多模态大语言模型（MLLM）智能体已经能通过代码或 Blender 的 MCP 接口操作三维软件，实际工作流要求它们从文本、图像、视频和规格文件中推断物体形状、材质、空间布局与光照，并完成重建、修改或设计。但现有基准覆盖不足：面向单物体的基准无法衡量场景级任务；面向场景编辑的基准任务过窄；多数基准使用固定视角或纯几何指标，无法反映开放式真实需求。评估还面临三个困难：环境需要同时支持创建、编辑和检查；任务需要覆盖多种参考源和设计目标；开放式任务没有唯一解，必须同时检查视觉外观和内部结构。

核心 insight 是：要可靠评估三维智能体，不能只看“某一视角像不像”，而应把每个任务转换成一组任务特定的二元验收标准，并分别用渲染证据和场景结构证据来判定；再用整体视觉质量维度补充二元标准无法刻画的连续属性。论文据此构建 BlenderWorld，并发现当前模型能解析宽泛指令，却往往依赖二维视觉捷径，只让当前视角看起来正确，缺乏真正稳固的三维空间一致性和结构复现能力。

3. 核心贡献（约300字）

  • 提出了 BlenderWorld，一个包含 223 个真实三维创建任务、22 个子类、16 个应用场景的基准，覆盖建筑、产品、自然环境、科学可视化等领域，输入模态包括文本、图像、视频和规格文件。
  • 建立了统一的评估协议：任务条件下的多视角自动渲染，配合 2,651 条任务特定二元标准；二元标准由“视觉语言模型判定器”和“场景检查智能体判定器”双通道验证，并加入整体视觉质量维度评分。
  • 在共享任务和协议下评测了 13 个前沿模型。GPT-6-Astra 取得最高融合分 79.9，但只在 42.2% 的任务上通过全部二元标准，说明完整满足任务要求仍很困难。
  • 通过轨迹与失败分析揭示了当前三维智能体的关键瓶颈：过度依赖视角相关的二维几何捷径、细粒度三维空间一致性不足、物理接触约束薄弱，以及“看了渲染图但无法转化为有效结构修改”的问题。

4. 推理阶段整体流程与基模（约400字）

推理时使用的基础模型有两类角色。生成侧基模是待测的 MLLM 智能体，例如 GPT-6-Astra、Opus-5，它们通过 Codex 或 Claude Code 调用 Blender 的 Python API/MCP 工具；评估侧基模是 GPT-5.6-terra，负责自动渲染与最终判定。生成阶段智能体看不到评分细则，只能根据用户简报和工具反馈工作。

  1. 输入解析：输入是用户简报，包括文本请求、图像/视频参考和规格文件。基模智能体解析这些多模态材料，形成初始场景编辑计划。输出：一系列 Blender 操作意图。
  2. 执行与观察：输入是编辑计划。智能体调用 Blender Python/MCP 工具创建几何、设置材质、导入资产、渲染或查询场景信息，得到新工作区状态和视口截图。输出：更新后的场景状态和视觉观察。
  3. 比对与决策：输入是当前视觉观察和原始简报。智能体判断哪些结构缺失、错误或不一致，决定继续修改还是保存交付。输出：下一动作或“交付”信号。
  4. 迭代修订：输入是上一动作及反馈。智能体不断重复“执行—观察—比对”，直到交互预算耗尽或满足交付条件。输出：最终工作区。
  5. 交付归档：输入是最终工作区。智能体保存 .blend 工程、渲染图、动画/视频和辅助文件，形成提交物包。输出：完整交付物。
  6. 自动评估：输入是交付物和评分细则。GPT-5.6-terra 自动选择并渲染多张视角；场景结构类标准由智能体判定器检查工程内部状态，视觉类标准由视觉语言模型判定器看图；最后给出 8 个质量维度分数。输出：Rubric、Dimension 与融合分数。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Task Definition（任务定义）

BlenderWorld 将任务建模为交互式三维创建过程。每个任务输入为 \(x=(q,I,F)\)，其中 \(q\) 是自然语言请求，\(I\) 是可选图像或视频参考，\(F\) 是可选规格文件。智能体 \(\pi\) 从初始工作区状态 \(s_0\) 出发，每个时间步根据观察 \(o_{\le t}\) 选择动作 \(a_t=\pi(x,o_{\le t})\)，环境通过 Blender 更新状态：

\[ a_{t}=\pi(x,o_{\le t}),\qquad s_{t+1}=\mathcal{E}_{\mathrm{B}}(s_t,a_t) \]

动作包括场景检查、Python 执行、资产导入和渲染。最终输出为可编辑工程 \(B\)、渲染 \(R\)、动画或视频 \(V\)、辅助文件 \(X\)。任务不要求唯一三维真值，而是允许多种合法实现。

3.2 Benchmark Construction（基准构建）

构建流程同时覆盖任务多样性、参考使用方式和真实应用场景。任务设计改变目标领域、场景复杂度、用户专业程度和请求长度；参考图像按“复现”“修改”“参考设计”三种角色组织，并用 MLLM 评估其清晰度和结构复杂度。每个任务被放入具体应用场景中编写，例如施工报告强调结构关系，产品展示强调外观可见性；复杂任务附带 Markdown、YAML 或 JSON 规格文件，记录尺寸、材质、相机和资产预算。

随后进行双轨验证：结构检查确认文件可解析、元数据一致、请求同时要求渲染输出和可编辑工程；语义审查由独立模型检查图文一致性、约束一致性和任务可行性。Rubric 生成阶段从简报中提取可核验要求，生成带来源链接的二元标准，分配类别、权重（主要 3、次要 2、细节 1）和证据类型（render 或 scene_summary）。至少两个独立审查模型交叉检查覆盖率和可评估性，再由编辑消解问题，最终冻结标准。

3.3 Dataset Statistics（数据集统计）

BlenderWorld 包含 223 个任务，覆盖 9 个大类、22 个子类和 16 个应用场景。其中 145 个任务（65.0%）包含图像或视频参考：130 个含图像，15 个含视频；59 个任务（26.5%）附带规格文件。评估使用 2,651 条二元标准，分布在 13 个类别中，每个任务 6 到 22 条，平均 11.9 条；功能和几何类合计占 41.7%。所有标准中 83.3% 为“主要”权重；41.8% 分配给渲染视图，58.2% 分配给场景检查；来自规格文件的显式要求贡献了 500 条标准（18.9%）。

Figure 3：BlenderWorld 的数据集统计。(a) 11 个最大的应用场景（223 个任务中的 213 个）。(b) 具有各参考或规范类型的任务百分比；类型可共存。(c) 按评分细则类别（内环）和重要性（外环）统计的标准数量。

4.1 Evaluation Protocol（评估协议）

评估协议分为自动智能体渲染、证据路由判定和维度评分三部分。

自动智能体渲染（AaR）根据任务请求、评分细则、参考文件和交付物自动选择 8 个互补视角，用 Cycles 以 1024×1024 分辨率、64 样本渲染。它可调整相机和取景，但必须保留提交的几何、材质、光照、动画和颜色管理；无效视角最多重渲两次，但不允许修复提交作品中的缺陷。若无法得到新渲染视角，评估直接失败。

证据路由判定中，每条二元标准指定证据类型。场景检查型标准交给 Agent-as-Judge，它用 Blender 工具检查内部场景结构、拓扑、尺寸和原生文件属性；渲染类标准交给 VLM-as-Judge，它查看 AaR 视角、原始导出媒体和视频帧。若视觉证据冲突，原始导出媒体优先。每个标准输出“通过/不通过”，不支持的标准得零分。

维度评分由 VLM 给出场景保真度、物理合理性、风格与颜色、真实感、空间布局、比例与尺度、光照与材质、完整性 8 个维度，每个维度 1 到 10 分，并附证据和理由。

Figure 4：BlenderWorld 的评估流程。结构性与视觉证据支持二元评分细则判定，并与维度得分融合。

4.2 Metrics（指标）

给定 \(m\) 条二元标准判定 \(\hat{y}_j\in\{0,1\}\) 和权重 \(w_j\)，以及 \(K=8\) 个维度评分 \(d_k\in[1,10]\)，计算：

\[ S_{\mathrm{rubric}}=100\frac{\sum_{j=1}^{m}w_{j}\hat{y}_{j}}{\sum_{j=1}^{m}w_{j}},\qquad S_{\mathrm{dim}}=100\frac{\sum_{k=1}^{K}d_{k}}{10K} \]

融合任务分数为：

\[ S_{\mathrm{fused}}^{(q)}=\lambda S_{\mathrm{rubric}}^{(q)}+(1-\lambda)S_{\mathrm{dim}}^{(q)} \]

默认 \(\lambda=0.5\)，即功能要求满足度与整体审美质量等权。最终报告所有 223 个任务的平均融合分数；评估失败的任务记为零分，但仍保留在分母中。

6. 局限性和展望（约300字）

论文明确指出的限制包括：当前评估环境只使用 Blender，尚未覆盖 Maya、3ds Max 等其他数字内容创作工具；判定器没有计算机操作智能体（CUA）级交互，无法直接操作 rig、动画或模拟状态；二元细则对有机体等对象区分度有限；尚未引入工程图纸、尺寸公差、局部编辑、拓扑修复和外部资产库；也没有报告跨平台和重复运行的稳定性。附录还显示，GPT-5.6-terra 作为判定模型，在分数差距小于 10 的小差距样本上，与人类偏好的一致率降至 68.57%，说明自动判定在区分高质量近似交付物时仍不够稳定。

可以谨慎推断的限制是：223 个任务规模适中，每个智能体每个任务只测一次，可能存在随机性；不同模型使用不同工具链（Codex 或 Claude Code），模型能力与工具链效应无法完全分离；评分细则由模型辅助生成，即使经过多模型审查，仍可能遗漏某些合理但非典型的设计方案；8 个视觉质量维度由 VLM 打分，不能完全替代专业三维艺术家的验收标准。

未来工作因此集中在五个方向：给判定器加入可交互、参数化检查；扩展任务复杂度和专业工作流；引入专家校准和更细粒度评分；支持多 DCC 生态与外部资产库；以及覆盖更多模型、推理配置、智能体框架和操作系统，在共享资源预算下比较质量、成本与稳定性。
