Imagine3D-LLM: Teaching MLLMs to Imagine 3D Scenes Before Answering

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 训练多模态大语言模型从多视图图像中构建紧凑3D表示并用于回答

领域标签： 多模态大语言模型 / 3D场景理解 / 空间推理

快速理解

背景与任务： 多模态大语言模型难以从多视图图像整合出连贯的3D理解，与人类空间推理能力差距明显。

核心工作： 作者提出Imagine3D-LLM，通过可学习摘要令牌解码为3D高斯泼溅表示并联合训练，使模型先想象3D场景再作答。

中文摘要

从多视角图像推理3D世界仍然是多模态大语言模型（MLLMs）面临的基本挑战。虽然现代MLLMs能有效处理单图像输入，但它们在将跨视角证据整合为连贯的3D理解方面存在困难。越来越多的研究工作试图通过向MLLMs注入3D感知来弥合这一差距，要么增强细粒度的像素级跨视角对应，要么融合来自3D几何基础模型的特征，然而与人类推理之间仍存在显著差距。在这项工作中，我们重新审视人类空间推理，这表明人类并非依赖细粒度的几何线索，而是粗略地识别跨视图的常见物体，推断视角之间的相对几何关系，并组装出场景的粗略3D布局。受这一过程的启发，我们提出了Imagine3D-LLM，一种学习组装类似紧凑场景3D表示，并基于该表示来生成答案的MLLM。具体而言，我们在图像令牌之后附加一小部分可学习的摘要令牌，将其解码为紧凑的3D高斯溅射表示，并通过光度重建损失进行监督，同时与标准的下一个令牌预测目标联合训练。值得注意的是，尽管只有摘要令牌直接接收重建监督，但该目标也促使LLM底层图像特征中产生更强的跨帧对应，这表明学习重建会将3D感知信号传播到整个模型中。因此，Imagine3D-LLM在多个空间推理和3D理解基准上持续优于先前方法，这表明想象场景可能比被告知其像素级几何更有效。

详细分析

1. 任务输入、输出、功能和边界（约100字）

输入是同一场景的 K 幅多视图图像和一段自然语言指令（例如“椅子在桌子的哪一边？”）。输出是模型生成的自然语言回答；在回答之前，模型内部会用一组 3D 高斯原语形成一张紧凑的 3D 场景“草图”。功能边界是面向空间关系、3D 问答、视觉定位等推理任务，不追求精确三维重建或照片级新视角渲染；图像数量、token 数量和可表达的物体细节均受训练设置限制。

2. 研究动机：要解决的问题与核心 insight（约300字）

多模态大语言模型（MLLM）是指能同时把图像和文本作为输入、并生成文本回话的模型。面对单张图像时，它可以利用大量图文知识回答问题；但面对多张不同视角的图像时，它往往只把每张图当成独立图片，缺少跨视角的统一物体定位，因此 3D 空间推理明显偏弱。

近期工作试图给 MLLM 补充 3D 先验。一类方法把点云坐标、视觉标记或跨帧重建任务加进图像特征，强制网络寻找像素级对应；另一类方法把 3D 重建基础模型（如 CUT3R、VGGT）输出的稠密几何特征融合进语言模型。这些方法都把“精确的像素级 3D 信息”当作提升 3D 推理的途径，但论文指出，这与人类的空间推理方式并不一致。认知研究发现，人类从多个视角观察一个场景时，不会在脑中保存精准的深度图或逐像素对应，而是先识别出不同视角中反复出现的物体，以这些物体为锚点推断视角之间的相对关系，再在脑中拼出一张粗略的 3D 布局图。

由此得到核心洞察：MLLM 也应该在回答前“想象”一个紧凑的 3D 场景表示，而不是被“告知”像素级几何。为了让这种想象可学习，论文使用 3D 高斯溅射（3DGS）——一种用带位置、形状、颜色和不透明度的 3D 高斯原语表示场景的方法——并要求 MLLM 用少数几个摘要 token 去生成这些原语。token 数量远少于图像 token 数量，所以模型不得不把跨视图看到的同一物体合并到同一个 token 中，自然地形成人类那种物体级、视图一致的 3D 心理模型。

3. 核心贡献（约300字）

论文提出并验证了以下几点：

  • 一个新范式：给 MLLM 增加一个“想象 3D 场景”的中间表示，让模型在回答前把多视图输入压缩成一组紧凑 3D 高斯，再基于这个内部场景布局生成文本。
  • 一种具体机制：在输入序列中加入少量可学习的高斯摘要 token，让它们充当场景摘要；这些 token 被解码为 3D 高斯原语，并同时参与语言生成。
  • 一种联合训练目标：语言建模、图像重建、从紧凑高斯教师蒸馏三路并行，使摘要 token 既能支持问答，又能重建场景。
  • 一项分析发现：即使重建监督只作用在摘要 token 上，LLM 内部的图像特征也会变得更跨视图一致，并出现类似物体分组的结构。
  • 一系列实验证据：在 SQA3D、Real-3DQA、ScanQA、Scan2Cap、ScanRefer、Multi3DRefer 和 SPAR-Bench 共 7 个基准上，该方法一致超过基于像素级几何或 3D 基础模型特征的已有方法，尤其在中高难度、需要跨视图推理的 SPAR-Bench 题目上提升显著。

4. 推理阶段整体流程与基模（约400字）

在推理阶段，系统不依赖外部 3D 传感器或离线建库。基模是一个多模态大语言模型（MLLM），其视觉编码器把每张输入图变成一组视觉 token，语言 Transformer 负责融合整个 token 序列并自回归地输出文本；此外，一个 3D 高斯解码器和一个渲染器作为内部“想象”模块，把摘要 token 变成一张粗略 3D 场景布局。整体流程如下：

  1. 输入：用户给出的多视图图像和文本指令。

视觉编码器将每张图像编码为视觉 token；文本嵌入层将指令编码为文本 token；同时读取一组固定的高斯摘要 token。 输出/交给下一步： 按“图像 token → 高斯摘要 token → 文本 token”顺序拼接得到的完整 token 序列。

  1. 输入：完整 token 序列。

语言 Transformer 在序列上做自注意力，使图像 token、摘要 token 和文本 token 相互交换信息；它在计算中途把摘要 token 当前位置的表示取出来。 输出/交给下一步： 一方面将摘要表示交给高斯解码器，另一方面原始序列继续在 Transformer 中向前计算。

  1. 输入：取出的摘要 token 表示。

3D 高斯解码器把每个摘要 token 映射成若干个 3D 高斯原语；渲染器按输入视角渲染这些原语，得到一张内部场景草图。 输出/交给下一步： 内部场景草图作为模型对场景布局的估计；摘要 token 的表示继续留在 Transformer 的后续计算中，供文本 token 参考。

  1. 输入：Transformer 中继续前向的序列。

语言 Transformer 基于当前序列预测下一个文本 token；每预测出一个 token 就将其接回序列末端，并重复预测，直到生成结束符。 输出： 最终自然语言回答。

整个流程没有外部环境反馈；唯一的循环来自自回归文本生成，即新预测的 token 作为下一轮预测的输入。

flowchart TD A[多视图图像 + 文本指令] --> B[视觉编码与文本嵌入] B --> C[拼接 图像token / 高斯摘要token / 文本token] C --> D[语言Transformer 全局自注意力] D --> E[中途取出高斯摘要token表示] D --> F[文本token自回归预测] E --> G[3D高斯解码器] G --> H[渲染器生成内部场景草图] H --> I[紧凑3D场景表示] E -.-> F F --> J{生成结束?} J -- 否 --> K[新文本token接回序列] K --> F J -- 是 --> L[最终回答]

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Preliminaries: Multi-view MLLMs（多视图 MLLM 基础）

这一节说明基线模型的输入输出形式。多视图 MLLM 由视觉编码器 \(V_\psi\)、视觉-语言投影器 \(P_\phi\) 和语言模型 \(LM_\theta\) 组成。给定 K 帧图像 \(I_k\)，视觉编码器对每帧独立提取 patch 特征 \(\mathbf{z}_k\)，投影器将其映射到语言模型嵌入维度，得到视觉 token \(\mathbf{e}^{img}_k\)。所有帧的视觉 token 拼接成 \(\mathbf{e}^{img}\)，再与文本 token \(\mathbf{e}^{text}\) 拼接，输入语言模型按自回归方式生成文本。这个标准结构是后续插入高斯摘要 token 的基础。

3.2 Imagine3D-LLM（总体框架）

Imagine3D-LLM 的核心修改是在图像 token 和文本 token 之间插入 M 个高斯摘要 token，形成序列 \([\mathbf{e}^{img}; \mathbf{e}^{gs}; \mathbf{e}^{text}]\)。这些摘要 token 在 LLM 的自注意力中可以看到全部图像 token，从而汇总多视图信息。模型在某个中间层取出摘要 token 位置的隐藏状态，交给高斯头解码为 3D 高斯原语；同时语言模型继续执行文本生成。总体框架如下图所示。

3.2.1 Mental Reconstruction via Gaussian Summary Tokens（通过高斯摘要 token 进行心理重建）

这一小节是方法的核心：

  • 高斯解码：每个摘要 token \(i\) 不是只产生一个高斯，而是产生 G 个高斯原语 \(\{G_{i,j}\}_{j=1}^G\)。每个原语包含 3D 中心、不透明度、协方差矩阵和球谐系数（球谐系数用于表达随视角变化的颜色）。这些原语可通过标准 3D 高斯栅格化渲染到任意视角。
  • 重建损失：把预测的高斯渲染到输入视角 \(\pi_k\)，与原始图像 \(I_k\) 比较，用 MSE 和 LPIPS 的加权和作为损失 \(\mathcal{L}_{recon}\)。这迫使摘要 token 编码足够的场景布局和外观信息。
  • 信息瓶颈：M 远小于图像 token 总数 \(K N'\)。模型无法逐块记录像素，只能把多个视角中反复出现的同一物体或区域合并到同一个摘要 token，才能用有限容量重建场景。这种“瓶颈诱导的物体分组”是形成抽象 3D 布局的关键。
  • 中间层选择：提取摘要 token 状态时选择中间层 \(\ell\)，而不是最浅或最深。太早则摘要 token 还没有汇集完整视觉证据；太晚则剩余层数不足以让文本 token 与摘要 token 充分交互。论文在 28 层 LLM 中比较 \(\ell=7,14,21\)，中间层 \(\ell=14\) 最好。

3.2.2 Accelerating Convergence via Distillation from a Compact Gaussian Teacher（用紧凑高斯教师加速收敛）

纯光度监督在 LLM 中收敛很慢，因此论文引入一个冻结的紧凑高斯教师 ZipSplat。ZipSplat 本身能从多视图图像预测一组紧凑 3D 高斯，并且内部也使用 M 个查询 token，正好与学生的摘要 token 一一对应。

蒸馏包含两个信号：

  • token 级余弦损失：将学生的摘要 token 状态经过一个小投影头，与教师的查询 token 状态做余弦相似度，让学生的摘要表示贴近教师已经“会解码”的表示空间。
  • 参数级 L2 损失：让学生预测的高斯参数（中心、协方差、不透明度、球谐系数等）直接逼近教师预测的参数。

最终总目标为

\[ \mathcal{L}_{\mathrm{full}} = \mathcal{L}_{\mathrm{LM}} + \lambda_{\mathrm{recon}}\mathcal{L}_{\mathrm{recon}} + \lambda_{\mathrm{distill}}\mathcal{L}_{\mathrm{distill}}. \]

消融实验表明，去掉蒸馏后只靠重建损失也能提升性能，但需要更多训练轮数；蒸馏的主要作用是显著加速收敛，使系统在实际训练预算内达到稳定性能。

3.3 Analysis（分析）

这一节不是新模块，而是分析训练后模型内部发生了哪些有意义的变化：

  • 图像特征变得更 3D 一致：虽然重建损失只加在摘要 token 上，但 LLM 的图像特征本身被重塑。从某查询点出发的图像间注意力图，在联合重建训练后更集中地落在另一视角的对应位置；PCA 可视化显示同一物体在不同视角下颜色一致，说明图像特征开始按跨视图语义组织。
  • 摘要 token 自发形成物体分组：对摘要 token 做 K-means 聚类，同一聚类对应的 3D 高斯往往集中在同一个物体上。模型没有显式物体监督，却自发学会了“哪些 token 属于同一个物体”。
  • 逐层对应分数上升：训练过程中，从 LLM 中间层提取的图像特征跨视图对应分数持续提升，且在高斯解码层附近提升最明显，说明重建目标的信息传播主要发生在该位置。

图2：联合重建训练对 LLM 图像特征的影响。(a) 查询点（红点）与其它输入视图之间的图像到图像注意力图。我们的模型展现出比基线显著更强的跨视图对应关系，表明高斯摘要 token 隐式地促使图像特征在视图间对齐。(b) LLM 图像特征的 PCA 可视化（前三个分量以 RGB 显示）。我们的特征明显更干净、语义结构更清晰，对应物体（如椅子、桌子）在视图间以一致的颜色编码，反映了物体级抽象的出现。

图3：来自摘要 token 的聚类高斯可视化。我们通过 K-means 对一组高斯摘要 token 进行聚类，并可视化聚类得到的高斯（青色表示属于同一聚类的高斯）。相似的摘要 token 被映射到同一物体，无需任何显式聚类监督。

6. 局限性和展望（约300字）

论文明确说明或直接可读出的限制：

  • 重建结果是粗糙的。论文使用 \(M=2592\) 个摘要 token、每个 token 产生 32 个高斯，渲染出的图像只保留大致布局和主要物体，缺少精细几何。若下游任务需要精确位置或细粒度形状，这种紧凑表示可能不够。
  • 训练依赖一个已经训练好的紧凑高斯教师 ZipSplat 来加速收敛。没有教师或教师所处场景分布与目标域差异较大时，训练会更困难。
  • 训练成本仍然较高。论文在 16 块 GH200 GPU、有效 batch size 64 的设置下运行，虽然只训练 1 个 epoch，总计算量并不小。

可以谨慎推断的限制：

  • 实验集中在 ScanNet 为主的室内场景和 SPAR-Bench，对室外场景、动态物体、开放词汇等泛化尚未验证。
  • 输入视角数量在多数设置中固定为 32，摘要 token 数量也固定。更少或更多视角、物体更密集时，最优 token 数量可能变化，论文未系统讨论。
  • 3DGS 本身适合静态场景，直接扩展到动态场景需要额外的表示设计。

展望： 后续可以探索自适应摘要 token 数量、更强的紧凑 3D 表示，以及去除教师依赖的训练方式，并把“先想象再回答”的思想推广到机器人规划和具身智能等领域。
