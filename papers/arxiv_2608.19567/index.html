Block3D: Efficient Text-to-3D Generation via Block-Wise Diffusion

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 文本到三维生成中，对形状标记序列分块自回归生成并对当前块联合去噪。

领域标签： 文本到三维生成 / 离散形状标记去噪 / 块级扩散与置信度修正

快速理解

背景与任务： 现有文本到三维方法中，自回归解码无法修订错误，而全局扩散或流模型重复处理全表示导致高质量生成成本高。

核心工作： 提出Block3D框架，将离散形状标记序列分块生成，对块内标记联合去噪并用置信度引导修正，实现5.15倍加速且不牺牲几何保真度。

中文摘要

虽然文本到三维生成已经快速发展，但在低推理成本下实现高几何保真度仍然具有挑战性。现有的文本到三维方法要么自回归地解码离散形状标记，要么使用扩散模型或流模型迭代地细化全局三维表征。然而，自回归解码是顺序的且无法修正错误，而扩散和流匹配模型则反复处理完整表征，使得高质量生成的成本越来越高。在本文中，我们提出Block3D，一种分块扩散框架，它将离散形状标记序列划分为连续块，自回归地生成这些块，并对当前块内的所有标记进行联合去噪。为了减轻错误累积，我们引入了置信度引导的块内校正，在每块最终确定之前修正低置信度标记。在TRELLIS-500K的留出集上，Block3D将平均端到端生成时间从25.71秒减少到4.99秒，相比微调的自回归基线实现了5.15倍的加速，且不牺牲几何保真度。

详细分析

1. 任务输入、输出、功能和边界（约100字）

任务输入是自然语言文本提示，以及可选的边界框条件（论文报告实验中只用文本）。输出是由离散形状码解码得到的 3D 网格。功能是在保持几何保真度的同时降低 text-to-3D 生成的端到端时延。边界是固定使用 Cube 的 1024 码 VQ（向量量化）形状表示，不做场景级布局、纹理/材质生成或交互式编辑。

2. 研究动机：要解决的问题与核心 insight（约300字）

现有 text-to-3D 方法主要分两条路线。自回归方法逐个预测离散形状 token，优点是能利用已生成前缀的强条件，但只能串行解码，且已发射的 token 不可修改；一旦某一步出错，错误会沿着前缀继续传播。扩散或流匹配方法可以并行更新所有位置，但每一步都要重新处理完整的 3D 表示，表示越精细、去噪步数越多，计算成本越高。因此，高质量几何与低推理时延往往难以兼得。

Block3D 的核心观察是：长距离 token 依赖不一定要在单 token 粒度上完全串行。它把因果性从“单个 shape token”提升到“连续 latent block”：块与块之间保持从左到右的自回归生成，块内则用双向注意力并行去噪。这样既保留了全局因果结构，又把大量并行计算引入块内。为了缓解块内并行预测带来的误差累积，Block3D 在块被最终提交之前，用置信度引导的块内修正机制，同时支持从掩码恢复 token（M2T）和修正已填入 token（T2T）。其核心 insight 是：在块粒度上做因果分解、在块内部做并行去噪与可编辑修正，是兼顾几何保真与低延迟的中间点。

Figure 2：3D token 生成调度方式对比。(a) 逐 token 生成一次预测一个形状 token，且无法修正已输出的 token。(b) 全序列去噪并行更新所有位置，但会反复处理完整表示。(c) Block3D 从左到右逐个生成 block，并并行去噪当前 block 中的所有位置；已填充的 token 在其 block 最终确定前仍可被修正。

3. 核心贡献（约300字）

论文提出并验证了 Block3D，一个面向高效 text-to-3D 生成的块级自回归扩散框架。

第一，它把 Cube 中逐 token 的自回归先验改为 block-causal 先验：生成按块从左到右推进，当前块内所有 shape code 并行去噪。相比逐 token 解码，这显著缩短了顺序决策次数；相比全序列扩散，它又不需要在每一步反复处理完整表示。

第二，它提出置信度引导的块内修正（confidence-guided intra-block correction）。当前块尚未提交时，M2T 用模型预测填充掩码位置，T2T 用更可信的新候选替换已填错或低置信度的 token，从而在块被冻结成前缀之前修正块内错误。

第三，实验在 100 个留出的 TRELLIS-500K 对象上进行。Block3D 在 CD-L1、法向一致性、F@1% 上均优于对比方法，同时把端到端平均生成时间从 Cube 的 25.71 秒降到 4.99 秒，约 5.15× 加速，且 CLIPScore 保持有竞争力。论文还通过 block size、去噪步数和 T2T 的消融，说明了各设计对质量与时延的影响。

4. 推理阶段整体流程与基模（约400字）

推理时使用的基础模型有：CLIP ViT-L/14 文本编码器，负责把文本提示变成条件；Block3D 条件生成器，负责按块生成离散形状码；Cube 的 VQ 形状解码器，负责把完整码序列映射成最终网格。整个推理不需要梯度，也没有外部环境反馈。这里的 M2T 指用模型预测填充掩码位置，T2T 指用模型预测替换已填充的低置信度码。

推理主流程如下：

  1. 输入：用户文本提示。CLIP 文本编码器把提示编码为 77 个 token 级条件特征；若启用边界框条件则额外投影一个框 token（默认不用）。输出：条件特征，交给 Block3D 生成器。
  2. 输入：条件特征。系统把 1024 个 shape code 位置全部初始化为掩码 [M]，按每块 64 个码划分为 16 个连续 block，并从第一块开始生成。输出：初始掩码序列与当前块索引。
  3. 输入：当前块的掩码状态、条件特征、已提交前缀。Block3D 生成器对当前块内所有位置并行预测候选 shape code 与置信度；已提交前缀作为因果上下文，当前块内部可双向交互。输出：当前块所有位置的候选码和置信度。
  4. 输入：当前块候选码与置信度。系统根据置信度做块内修正：高置信度掩码位置被填入，已填入位置若出现更可信的新候选则被替换；修正后的状态回到第 3 步继续处理，直到达到固定更新步数或没有需要更新的位置。输出：当前块的最终候选状态。
  5. 输入：当前块最终状态。系统提交该块，将其作为不可变前缀加入缓存，然后移动到下一个块；重复第 3–5 步直到所有块完成。输出：完整的 1024 码序列。
  6. 输入：完整码序列。Cube 的 VQ 形状解码器把码序列映射为最终网格。输出：用户得到的 3D mesh。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Overview（概览）

该小节定义整个系统的模块边界和生成调度。Block3D 使用 Cube 的冻结 VQ 自编码器：每个 mesh 被表示为 \(N=1024\) 个离散 shape code，码本大小 \(V=16384\)。文本提示经冻结 CLIP ViT-L/14 编码为条件 \(C\)，可选边界框 token 可以附加到条件中，但论文实验只用文本。\(N\) 个位置被划分为 \(K\) 个连续 block。推理时当前 block 初始化为全掩码，生成器在条件和已提交前缀的约束下并行预测块内所有位置；M2T 填充掩码，T2T 修正已填充码；块提交后冻结，最终由冻结的 VQ 形状解码器输出网格。该总览说明了上游条件编码、中间生成器和下游解码器之间的固定接口。

3.2 Block-Causal Shape-Code Denoising（块因果形状码去噪）

该小节实现“块间自回归、块内双向去噪”的注意力规则。生成器保留 Cube 的 DualStream RoFormer，形状码 logits 写为 \(\ell=F_\theta(C,z;A,p)\)，其中 \(z\) 是可见形状状态，\(A\) 是注意力掩码，\(p\) 是逻辑位置。块 \(k\) 的位置集合为 \(I_k\)，只有最后一块可以小于块大小 \(B\)。推理依赖关系为：

\[ \hat{x}^{(k)}=\mathcal{G}_{\theta,T}(\hat{x}^{(<k)},C), \]

即当前块由已提交前缀和条件共同决定。训练时把干净序列 \(x\) 和损坏序列 \(\tilde{x}\) 拼接，在一个前向中并行学习所有块。注意力规则是：损坏块中的 query 可以看条件、自己块之前的干净前缀，以及自己块内的损坏 token；它不能看当前块的干净目标、未来块的干净 token，也不能看其他块的损坏 token。干净块中的 query 则只能看自己块及之前块的干净 token。该设计避免信息泄漏，同时让所有块共享一次前向计算。Figure A 给出了 block 级可视化。

Figure A：训练注意力掩码的 Block 级可视化。绿色单元格表示可见的 query-key 组对。损坏的 query 可读取条件、其干净的 teacher-forced 前缀以及自身 block 的损坏副本；它不能读取该 block 的干净目标、后续 block 或另一个损坏的 block。为便于阅读，图示将每个 block 表示为单个组；对应的 token 级规则见公式 A.3–A.5。

3.3 Edit-Aware Corruption and Training（面向编辑的损坏与训练）

该小节让生成器不仅学会从掩码恢复 token，还学会修正模型自己产生的错误 token。对每个训练样本的每个 block，采样损坏率 \(\tau_k\sim\mathcal{U}(0.45,0.95)\)，每个位置独立按该概率被损坏。样本级变量 \(a\sim\mathrm{Bernoulli}(0.5)\) 选择初始损坏流：M2T 把被损坏位置置为 \([M]\)，T2T 把被损坏位置替换为均匀随机错误码 \(u_i\)。初始状态为：

\[ \tilde{x}^{(0)}_i= \begin{cases} [M], & e_i=1,\ a=0,\\ u_i, & e_i=1,\ a=1,\\ x_i, & e_i=0. \end{cases} \]

受 LLaDA2.1 多轮前向增强启发，Block3D 做一次无梯度的模型 rollout：从初始损坏状态出发，用 M2T/T2T 更新规则推进一步得到 \(\tilde{x}^{(R)}\)。随后在 \(\tilde{x}^{(R)}\) 上做带梯度的前向，只对 rollout 后仍不等于真实码的“残差位置”计算损失：

\[ \mathcal{L}=-\frac{1}{|\mathcal{D}|+\epsilon}\sum_{(n,i)\in\mathcal{D}} \log \pi^{(R)}_{\theta,n,i}(x_{n,i}), \]

其中 \(\mathcal{D}\) 是 rollout 后仍未恢复正确码的位置集合。这样，模型被显式监督去修复自己上一轮生成出的错误，而非只修复随机掩码。

3.4 Bounded Confidence-Guided Decoding（有界置信度引导解码）

该小节规定推理时如何在固定步数内完成每个 block。每个 block 初始化为全掩码，设去噪步数上限为 \(T\)。若启用 classifier-free guidance，条件分支和无条件分支分别产生 logits，并按线性衰减系数组合：

\[ \gamma_s=g\frac{T-s}{T},\qquad \ell_s^g=(1+\gamma_s)\ell_s^+-\gamma_s\ell_s^-. \]

候选码由 guided logits 的 argmax 得到，置信度则由条件分支 softmax 给出：

\[ \hat{z}_{s,i}=\arg\max_v \ell^g_{s,i,v},\qquad \alpha_{s,i}=\mathrm{softmax}(\ell^+_{s,i,0:V-1})[\hat{z}_{s,i}]. \]

每一步分配确定的最少揭示配额 \(q_s=\lfloor n_k/T\rfloor+\mathbf{1}[s<n_k\bmod T]\)，保证所有掩码在 \(T\) 步内被移除。M2T 选择高置信度掩码位置并配合 TopK 配额，T2T 选择新候选不同于旧值且置信度超过阈值的位置。更新是同时进行的，已提交前缀永不重开。默认超参数为 \(B=64\)、\(T=4\)、\(\eta_M=0.95\)、\(\eta_T=0.9\)、\(g=3.0\)，因此最多 \(KT\) 次活跃块调用即可完成全部 \(K=16\) 个块。

6. 局限性和展望（约300字）

论文明确说明的限制主要有三点。第一，Block3D 的 block 划分完全沿用 Cube 的一维 code 顺序，不感知语义部件或空间层级；因此它只能修正块内错误，不能根据物体结构进行更有意义的部件级生成。第二，已提交的 block 被冻结后不可重开，所以跨 block 的误差传播仍然存在；块级自回归暴露偏差并未被消除，只是被限制在每个 block 内部的可修正范围内。第三，固定推理步数保证了有界时延，但不意味着所有被保留的 token 都一定语义正确。

从机制上可以谨慎推断：T2T 只接受置信度超过阈值的新候选，因此那些低置信度但实际错误的 token 可能被保留下来，并被后续块继续当作条件使用。另外，论文实验以文本条件、几何指标和 TRELLIS-500K 数据为主，对更广泛的形状类别、纹理/材质以及边界框条件的效果仍待进一步验证。论文提出的未来方向是跨 block 细化，即允许已提交块在某种受控方式下被重新审视，以及扩展到更广泛的形状表示和数据集。
