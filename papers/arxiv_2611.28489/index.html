Open Vision Banana: An Open Framework for Unified Visual Perception through Generation in RGB Space

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 研究开放扩散生成器能否通过RGB生成统一完成深度估计与多种分割任务。

领域标签： 计算机视觉 / 统一视觉感知 / 扩散生成模型

快速理解

背景与任务： 闭源图像生成器经指令微调可将感知输出绘制为RGB图像并成为通用视觉模型，但其能否迁移至开放生成器尚不清楚。

核心工作： 作者提出Open Vision Banana框架，用共享低秩适配器将Qwen-Image-2.1统一用于深度与分割，并系统分析开放模型的失败模式与检查点选择问题。

中文摘要

Vision Banana 表明，一个经过指令微调、可将感知输出绘制为 RGB 图像的闭源图像生成器，会成为通用视觉模型。这一结论能否推广到开源生成器？如果不能，失败在哪里？我们以 Open Vision Banana（OVB） 作出回答：这是一个开放框架，使用单个共享低秩适配器和公开数据，将 Qwen-Image-2.1 的 7B 扩散生成器适配为一个由指令驱动的模型，用于度量深度、语义分割、实例分割和指代分割。每个任务都是一个任务契约（task contract），其 RGB 编码器、指令和解码器共享同一规范，并在训练前接受检查。通过研究来自两次 10 万次更新运行的 42 个经外部评估的检查点、六次精确的权重空间合并以及八次受控的较短运行，我们发现与闭源系统之间的差距是具体且可测量的。几何很早就被学习，而绝对尺度不是：在整个训练过程中，中位数对齐的 NYUv2 δ₁ 保持在 0.89–0.93，而未对齐的 δ₁ 在 0.11 到 0.50 之间波动。尺度并不是由单个样本确定的：十种子集成无需重新训练即可将未对齐的 δ₁ 从 0.348 提升到 0.516。深度和 2D 分割争夺共享适配器，权重合并沿着这一权衡移动，但无法摆脱它。最后，验证流损失更低的同时，Cityscapes 准确率也更低（损失下降与 mIoU 之间的 Spearman ρ≈−0.9），因此该损失无法用于选择检查点。我们发布代码、契约、训练数据和所有评估输出。

详细分析

1. 任务输入、输出、功能和边界（约100字）

输入是一张源图像和一段任务指令（instruction；referring 任务还含 query）；输出是生成器绘制的 RGB 图，再由任务契约解码为度量深度（metric depth）、类别 ID 图、实例掩码或二值掩码。功能是用一个共享适配器统一四类视觉感知。边界：不输出自然语言，不使用相机内参或专用深度头，ReasonSeg 用原始 query，不能把封闭系统数字当作严格可比结果；生成/编辑质量未测量。

2. 研究动机：要解决的问题与核心 insight（约300字）

Vision Banana 表明：把一个封闭的图像生成器指令化，让它“画出”感知结果对应的 RGB 图像，就能成为一个通用视觉模型。论文追问两个问题：这套范式能否迁移到开放生成器？如果不能，究竟哪里失败、为什么失败？作者认为第二个问题更有价值：只复现一个数字对社区帮助有限，定位失败模式才能告诉下一个模型该修什么。

核心 insight 是：RGB 只是载体，预测只有在目标编码器、指令和解码器对单位、颜色编码、掩码约定完全一致时才有意义；三者不一致时，训练损失仍可能下降，但解码后的预测会整体失效。因此 OVB 把每个任务写成“任务契约”，从同一 specification 派生 encoder、instruction 和 decoder，并在首次更新前检查。开放设置还允许研究封闭系统无法提供的粒度：多个检查点、精确权重合并、受控短跑，从而把与封闭系统的差距拆成绝对深度尺度、采样方差、共享适配器下的任务竞争等可测量问题。

3. 核心贡献（约300字）

论文提出、构建并验证了三件事。第一，构建 Open Vision Banana（OVB）：在公开的 Qwen-Image-2.1 编辑式扩散生成器上，用同一个共享低秩适配器和公开数据，把 metric depth、semantic、instance、referring segmentation 统一成 instruction 驱动的 RGB 生成任务；任务切换只改 instruction。第二，提出任务契约机制：每个任务的 RGB encoder、instruction、decoder 由同一 specification 派生，并在首次更新前检查单位、颜色、掩码、instruction 和解码一致性，避免“损失下降但解码整体失效”。第三，做诊断性验证：外部评测 42 个检查点、6 个精确权重合并、8 个受控短跑，定位开放配方与封闭系统的差距：深度几何早已学会而绝对尺度未承诺；十 seed 集成把 unaligned NYUv2 δ1 从 0.348 提到 0.516；深度与 2D 分割共享适配器时相互竞争，权重合并只沿 trade-off 移动；验证 flow loss 与 Cityscapes mIoU 的 Spearman ρ≈−0.9，不能用于选检查点。δ1 是预测/真值比值在 1.25 内的像素比例；unaligned 直接用度量深度，median-aligned 每图用真值中位数校一个尺度。论文还发布代码、契约、训练数据、评测协议和全部评测输出。

4. 推理阶段整体流程与基模（约400字）

推理时使用已就绪的 OVB 系统：Qwen-Image-2.1 的编辑式扩散生成主干是黑箱生成器，负责在源图像和 instruction 条件下生成目标 RGB 图；固定权重的共享适配器让同一生成器服务四种任务，切换任务只改 instruction。

  1. 输入：用户源图像和任务 instruction（referring 任务还含 query）→ 系统按 instruction 选择任务契约，确定输出应是深度图、类别图、实例掩码还是二值掩码，并确定对应解码规则 → 输出：源图、instruction 和契约配置，交给生成器。
  2. 输入：源图、instruction 与契约配置 → 黑箱生成器（Qwen-Image-2.1 冻结主干 + 固定共享适配器）在源图与文本 instruction 条件下从噪声生成目标 RGB 图 → 输出：一张 RGB 预测图，交给解码器。
  3. 输入：RGB 预测图与任务契约 → 确定性解码器按该任务的颜色/掩码约定把 RGB 图还原为结构化预测 → 输出：metric depth 图、类别 ID 图、实例掩码或二值掩码，交给后处理。
  4. 输入：结构化预测与用户图像/标注的原始分辨率 → 后处理工具按输出类型重采样（标签用最近邻，深度用双线性）→ 输出：与用户图像对齐的最终预测，交给输出层。
  5. 输入：最终预测 → 系统按任务返回可视化图和/或结构化结果；不额外做查询重写或外部环境交互 → 输出：用户可见的最终感知结果。

5. 核心方法：按论文 Method 小节总结（约600字）

论文 Method 即第 3 节，全部内容按原小节组织如下。

3.1 Task Contracts（任务契约）

目的是让“画出 RGB”这件事可解码、可检查。OVB 把所有预测都表示成 RGB 图，因此 RGB 只是载体；若 encoder、instruction、decoder 对单位、颜色、掩码约定不一致，损失可下降但解码整体失败。任务契约 \( \mathcal C_q=(E_q,p_q,D_q;S_q) \) 将三者绑定到同一 specification \(S_q\)。给定源图 \(x\) 和任务 \(q\)，生成器输出 \( \hat r_q=G_{\theta,\delta}(x,p_q) \)，再由 \( \hat y_q=D_q(\hat r_q) \) 解码；训练目标由 \(r_q=E_q(y_q)\) 得到。深度任务使用 metric units、幂变换和 cube-edge 色图；语义任务用有序调色板并取最近颜色；实例任务用黑色背景、每个实例一种颜色并经过五阶段颜色聚类；referring 任务用白前景黑背景并阈值化解码。深度编码为 \(u(d)=1-(1+d/10)^{-2}\)，解码为 \( \hat d=10((1-\hat u)^{-1/2}-1) \)。训练前检查目标是否落在声明的 code 上、instruction 是否匹配协议、适配器是否覆盖读取 instruction 的注意力投影、监督与划分是否干净。这样任务差异主要落在契约上，而不是另造一套架构。

Figure 2：任务契约、契约检查与训练。(a) 每个任务是由 specification S_q、encoder E_q、instruction p_q 和 decoder D_q 给出的显式、可解码 RGB code；depth card 显示沿 RGB cube 边缘的 colormap path，每个顶点标注其在 Eq. (2) 下编码的 metric depth。(b) 在首次更新前对 training manifest 和 configuration 运行的检查。(c) 训练：annotation 由冻结 autoencoder 编码为 RGB target，再编码为 latent b；conditional flow matching 更新共享 adapter，而 backbone 保持冻结。Run A 使用峰值 lr 3×10^-5（图示），Run B 使用 1×10^-5；包含 editing replay，意图是保留 generation，但我们尚未测量（Sec. 6）。

3.2 Backbone and Shared Adaptation（主干与共享适配）

目的是用一个共享低秩适配器把冻结的编辑式生成器改造成多任务感知器。Qwen-Image-2.1 原生接受源图像：\(x\) 作为视觉 token 和参考 latent，\(p_q\) 作为文本条件，目标在 \(c(x,p_q)\) 下从噪声生成。训练采用条件流匹配： \[ \mathcal L=\mathbb E_{t,\epsilon}\left\|v_{\theta,\delta}(z_t,t,c(x,p_q))-(b-\epsilon)\right\|_2^2,\quad z_t=(1-t)\epsilon+t b, \] 其中 \(b\) 是 RGB 目标经冻结自编码器得到的 latent。所有任务（含编辑回放）都用该损失、单位权重、无辅助项。Transformer、自编码器、文本编码器冻结；冻结 Transformer 是一个融合检查点：两个来自同一父检查点的适配器以 0.6 和 0.4 合并。其上只训练一个零初始化的 rank-stabilized LoRA（\(r=64,\alpha=64\)，scale 8），覆盖注意力投影和前馈层；它是唯一被更新的参数集，切换任务只改 instruction。主运行训练 100k updates，AdamW、全局 batch 32、分辨率 512、2k warmup、余弦衰减、梯度裁剪、conditioning dropout 0.05、适配器 EMA 0.9999；两次运行只差峰值学习率 \(3\times10^{-5}\) 与 \(1\times10^{-5}\)。验证 flow loss 每 2,500 updates 评估一次，“best”取 EMA 适配器在新低点保存的检查点。

Figure 1：Open Vision Banana 概览。源图像 x 和任务 instruction p_q 作为条件输入一个冻结的生成 backbone（所有实验中使用 Qwen-Image-2.1；backbone 是配置选择），该 backbone 带有一个新初始化的 rank-64 LoRA adapter δ，由所有任务共享。源图像以 visual tokens 和 reference latents 进入，instruction 作为 text condition，target latent 在 50 个 flow steps 中从噪声生成。生成的 RGB 图像 r̂_q 由无参数 decoder D_q 转换为结构化预测 ŷ_q：metric depth、class-ID map、instance masks 或 binary mask。底部：任务契约 C_q=(E_q,p_q,D_q;S_q) 将 encoder、instruction 和 decoder 绑定到一个 specification，并在训练前验证。场景是渲染插图；其 RGB tiles 由 contract encoders 从精确 annotations 生成，并非模型预测。

3.3 Training Data and Target Construction（训练数据与目标构造）

目的是用公开数据构造与契约一致的 image–instruction–target 记录，并控制任务混合。训练池含 1,098,435 条记录；每次更新采样概率为 metric depth 0.35、semantic 0.20、instance 0.20、referring 0.20、编辑回放 0.05，任务内记录均匀采样。深度记录 407,278 条，来自 TartanAir、Hypersim、LingBot-Depth、ARKitScenes、SUN RGB-D（排除 NYU 派生样本）和 DIODE；新准备目标做原生深度准入检查，无效深度像素编码为黑色，有效性掩码用于数据准入但不掩蔽损失。分割池含 146,027 条语义记录和 233,133 条实例记录，包括从 COCONut 注释重建的类别条件目标；每图最多 12 个类别、最多 3 个类别特定实例视图，未选区域按背景处理；语义图例有四种格式，颜色以 0.5 概率重映射。referring 记录 295,505 条，其中 RefCOCO 家族 270,195 条、Rea2Seg 11,812 条（排除其 ReasonSeg 类别）、LLM-Seg 13,498 条，统一转成白前景黑背景。目标均按任务契约存为无损 RGB。这样数据由同一契约编码器生成，混合比例决定共享适配器的容量分配，准入与图像标识去重控制目标有效性和评测泄漏。

6. 局限性和展望（约300字）

论文明确说明的限制：所有 benchmark 上 OVB 都低于封闭的 Vision Banana，且其基模、内部数据和人类评测不公开，无法复现其数字；所有结论只在 Qwen-Image-2.1 一个 backbone 上，框架虽支持配置其他生成器，但不声称这些发现会迁移；检查点和合并配方在评测 benchmark 上检查过，P5/P6 权重是在看到 Table 5 后固定，因此最佳分数按构造偏乐观，结论应看成六个合并的效应符号而非单个配方；绝对深度尺度的稳定 per-image bias 尚未解决，十 seed 集成只是诊断、推理成本为 K 倍，不是提出的方法；可选尺度损失未评估；flow loss 不能选检查点；全量微调会抹掉 referring 能力；编辑回放意图保留生成能力，但生成/编辑质量未测量；ReasonSeg 因 query 重写与参考不可比。

可谨慎推断的限制：单 backbone、公开数据、四个任务和 512 推理画布可能限制外推；共享适配器的任务竞争可能需要任务路由、更大容量或分离参数，但论文未验证这些方案。展望：按论文建议同时报告 unaligned 与 median-aligned 深度及 seed 波动；用解码指标在留出集选检查点；在尺度被决定的位置监督尺度并评估已给出的可选损失；在其他开放生成器、更多数据和人工评测上复验；把任务竞争作为明确目标研究。
