RoomTokens: Masked Diffusion over Structured Tokens for Indoor Scene Synthesis

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 三维室内场景生成：以结构化令牌和掩码扩散合成家具布局。

领域标签： 三维室内场景合成 / 结构化令牌表示 / 掩码离散扩散

快速理解

背景与任务： 三维室内场景合成需在生成家具布局时保持物体语义、实例、朝向及房间几何约束。

核心工作： 作者将场景表示为含语义、实例颜色和朝向的结构化网格令牌，提出共享跨切片主干的掩码离散扩散模型，并以户型令牌为约束联合去噪生成布局。

中文摘要

生成三维室内场景需要一种表示，能够捕捉对象语义、实例身份、高度结构和朝向，同时尊重房间几何。将场景建模为对象向量序列的方法隐式学习空间约束，把碰撞和越界留给损失函数或后处理；语义图方法显式表达占用，但坍缩了实例和方向结构。我们引入 RoomTokens，一种切片式结构化 token 表示，其中每个 token 存储语义类别、实例颜色身份和朝向场。该表示允许将场景生成为离散网格，同时保留用于实例分组、朝向估计和三维范围预测的线索。为学习 RoomToken 分布，我们提出 MDIRT（Masked Diffusion over RoomTokens），一种掩码离散扩散模型，它使用共享的跨切片主干网络联合去噪语义/实例颜色/朝向通道。建筑 token 被钳制为显式的平面图约束，因此模型采样的家具布局既尊重房间几何，又保留实例和对象属性结构。在 3D-FRONT 上的实验表明，RoomTokens 与 MDIRT 相结合，在布局保真度和物理一致性上优于基于序列/向量和基于地图的方法，表明结构化空间 token 是离散三维场景合成的一种实用选择。

详细分析

1. 任务输入、输出、功能和边界（约100字）

输入是房间类型 \(r\) 与建筑掩码（墙、门、窗等固定户型结构）；输出是对象级 3D 室内家具布局，并进一步检索 3D-FUTURE 资产实例化为可渲染场景。功能是在给定户型内部生成尊重房间边界、保留实例分组与朝向线索的家具布局。边界是：生成发生在固定高度切片的离散网格上；token 合法与不出界不保证最终网格资产无碰撞，也不保证功能上完全合理。

2. 研究动机：要解决的问题与核心 insight（约300字）

已有室内场景生成方法主要有两类表示。第一类把场景写成对象向量或对象序列，每个对象包含类别、包围盒、朝向等属性；这种表示紧凑，但空间占用是隐式的，两个预测框是否重叠、是否穿墙、是否堵门并不由表示本身保证，只能靠损失项、拒绝重采样或后处理修补。第二类把场景画成俯视语义图，每个格子直接给语义标签，因而占用和边界是显式的；但单层俯视图会丢失垂直高度信息，同类别相邻实例在连通域解码时容易合并，而且每个格子只有一个语义标签，无法提供物体朝向线索。论文的核心 insight 是：不必在“对象向量”和“语义图”之间二选一，可以把场景表示成按高度切片的离散网格，每个格子存一个结构化 RoomToken，同时携带语义类别、实例颜色身份和朝向字段。实例颜色不是任意对象 ID，而是用少量颜色区分平面上相邻的同类别实例；朝向字段用 body/front 标记物体主体与前半部分，从而在离散占用图中保留实例分组、朝向估计和三维范围预测的线索。再在这种表示上使用掩码离散扩散，在固定建筑 token 的条件下联合补全家具 token 的三个字段。

Figure 1：上。室内场景生成的场景表示比较。对象序列 (a) 编码对象属性，但缺乏显式空间关系信息。语义图 (b) 使空间结构显式，但缺乏垂直、实例和朝向信息。我们提出 RoomTokens (c)，通过在切片空间网格中编码语义占用、实例身份和朝向线索来解决这些缺失因素。下。我们引入 MDiRT (d)，一种在 RoomTokens 上的掩码离散扩散模型，它在保持建筑 token 固定的同时去噪缺失 token 场，使生成场景尊重房间边界。

3. 核心贡献（约300字）

论文提出并构建了三件事。第一，提出 RoomTokens：把房间表示为高度切片网格，每个格子是一个三字段 token，分别记录语义类别、实例颜色身份和 body/front 朝向；它把空间占用显式化，同时保留实例分离、朝向和垂直范围线索。第二，提出 MDiRT：一种在 RoomTokens 上的单阶段掩码离散扩散模型，去噪时把建筑 token 固定为户型约束，并联合预测语义、实例颜色和朝向三个通道；建筑/背景 token 不携带实例与朝向属性，家具 token 才携带，从而用合法性规则约束三字段组合。第三，在 3D-FRONT 上验证该表示与生成模型的有效性：相比语义图扩散基线 SemLayoutDiff，MDiRT 的 FID 为 50.14 对 71.18（越低越好），对象对关系指标 Pair-Rel 为 12.09 对 20.65（越低越好），碰撞率 COL 为 12.64 对 16.24（越低越好），门窗开口净空 OC 为 82.31 对 56.02（越高越好），最终资产放置后越界率为 0；消融进一步验证类别平衡、多通道联合预测、语义优先采样、实例颜色字段、朝向字段和跨切片注意力的作用。

Figure 4：在 3D-FRONT 上以建筑掩码为条件的定性比较。我们使用语义正交视图将比较聚焦于布局评估。基线方法显示边界违规、碰撞或门窗开口被遮挡，而 MDiRT 保持清晰的开口、房间几何结构和结构化对象线索。

4. 推理阶段整体流程与基模（约400字）

推理时使用的基模是 MDiRT，它是一个现成可用的掩码离散扩散生成器，负责从被遮住的室内 RoomToken 网格中逐步补全语义、实例颜色和朝向字段；资产检索与放置模块负责把 token 解码出的对象记录变成最终 3D 场景。

  1. 输入：用户给出房间类型 \(r\) 和建筑掩码（墙、门、窗等固定结构） → 初始化模块：把建筑位置标为固定建筑 token，把室内待生成位置的三个字段都置为未知掩码 → 输出/下一步：得到一张待补全的 RoomToken 网格，交给 MDiRT。
  2. 输入：待补全网格、房间类型和建筑掩码 → MDiRT 黑箱生成器：反复从当前网格预测并填入语义、实例颜色、朝向字段，同时保持建筑 token 不变 → 输出/下一步：得到完整的三字段 RoomToken 网格，交给实例解码。
  3. 输入：完整 RoomToken 网格 → 分组与几何解码模块：按相同语义和相同实例颜色把连通 token 组成对象实例，读取 body/front 线索，并用实例级特征估计高度、垂直偏移和朝向 → 输出/下一步：得到对象记录（类别、水平中心与尺寸、高度、yaw），交给资产检索。
  4. 输入：对象记录 → 资产检索与放置模块：按类别在 3D-FUTURE 资产集合中寻找三维尺寸最接近的资产，并按记录进行缩放、旋转、平移 → 输出/下一步：得到每个对象的 3D 资产实例与位姿，交给场景组装。
  5. 输入：所有资产实例与位姿 → 场景组装模块：合成最终 3D 室内场景；论文不使用额外裁剪、手工修正或环境反馈循环 → 输出/下一步：输出最终 3D 场景。

上述流程中，资产检索与放置是与外部 3D 资产集合交互的工具步骤；论文没有额外的环境反馈环。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Sliced RoomTokens（切片式 RoomTokens）

目的：把 3D 室内场景转成离散但保留实例、朝向和垂直信息的 token 体积。机制：将地板平面离散成 \(H\times W\) 网格，并选 \(S\) 个高度切片 \(\mathcal Z=\{\zeta_1,\ldots,\zeta_S\}\)。token 索引为 \(i=(u,v,s)\)，每个位置存 \(\mathbf x_i=(y_i,c_i,f_i)\)：语义类别 \(y_i\)、实例颜色 \(c_i\)、朝向 \(f_i\)。实例颜色取 \(C\) 个颜色之一或空值 \(\varnothing_c\)；朝向取 body、front 或空值 \(\varnothing_f\)。合法性要求建筑/背景 token 不携带实例颜色和朝向，家具 token 才携带二者： \[ \mathrm{valid}(y_i,c_i,f_i)\Longleftrightarrow \begin{cases} c_i=\varnothing_c\ \text{and}\ f_i=\varnothing_f, & y_i\in Y_{\mathrm{arch}},\\ c_i\in\{0,\ldots,C-1\}\ \text{and}\ f_i\in\{\mathrm{body},\mathrm{front}\}, & y_i\in Y_{\mathrm{furn}}. \end{cases} \] 高度切片不是随便等距取：论文在训练集家具高度区间上做贪心覆盖，候选高度 \(h\) 覆盖某物体当且仅当物体垂直区间与 \([h-\tau,h+\tau]\) 相交，\(\tau=0.10\) m；从地板和天花板锚点开始，反复加入能覆盖最多尚未覆盖物体的高度。主实验用 \(128\times128\) 网格、每格 0.10 m、\(S=8\) 个高度切片、39 个语义类别、3 个实例颜色加空值；四色定理在这里是“少量颜色足以分离平面相邻实例”的依据，实际主实验比较后采用 3 色。关系：该小节定义后续扩散模型要生成和保持的离散状态；建筑 token 是可固定的条件，家具 token 是待补全变量。

Figure 2：RoomToken 数据表示。(a) 3D 场景表示为在选定垂直高度处取得的水平切片。(b) 每个切片编码三个对齐的 2D 通道：语义类别、实例颜色身份和朝向场。将所有高度上的这些通道堆叠形成切片 token 体积。(c) 堆叠切片得到的 3D 表示（RoomTokens）存储语义、实例和朝向信息，高度由切片索引导出。

3.2 Masked Diffusion over RoomTokens（RoomTokens 上的掩码扩散）

目的：只生成未知的室内家具 token，同时把已知建筑结构固定住。机制：前向过程不逐步加高斯噪声，而是把未固定格子的字段替换成掩码 token。对语义用保持指示 \(m_i\)，对实例颜色和朝向用 \(n_i\)，二者按保持概率 \(\alpha(t)\) 独立采样；只有当语义可见时，实例颜色和朝向才可见。设 \(a_i=1\) 表示固定建筑格，\(a_i=0\) 表示待生成格，则 \[ z_{t,i}^{y}= \begin{cases} y_i, & a_i=1\ \text{or}\ m_i=1,\\ [M]_y, & \text{otherwise}, \end{cases} \quad z_{t,i}^{\rho}= \begin{cases} \varnothing_\rho, & a_i=1,\\ x_i^{\rho}, & a_i=0\ \text{and}\ m_i=n_i=1,\\ [M]_\rho, & \text{otherwise}, \end{cases} \] 其中 \(\rho\in\{c,f\}\)。反向过程以 \(\kappa=(r,\mathbf a)\) 为条件，网络预测三字段概率并采样提案 \(\hat{\mathbf z}_s\)，再恢复固定建筑 token，并用 \(\Pi_{\mathrm{valid}}\) 把生成 token 投影到合法支持上： \[ \mathbf z_{s,i}= \begin{cases} \mathbf x_i, & a_i=1,\\ \Pi_{\mathrm{valid}}(\hat{\mathbf z}_{s,i}), & a_i=0. \end{cases} \] 该投影只删除非法的语义—属性组合，不合并实例、不改变放置。采样时采用语义优先：每一步先更新语义标签，再基于更新后的语义重新计算实例颜色和朝向；已揭示标签保留，语义仍被掩码时属性也保持掩码，建筑/背景被揭示时属性置空。关系：该小节把 3.1 的合法 token 状态变成可采样的生成过程，并为 3.3 的网络定义输入、输出和约束。

3.3 Multichannel Denoising Network（多通道去噪网络）

目的：在一个共享表示中同时预测语义、实例颜色和朝向，而不是先预测语义再单独预测属性。机制：每个格子的三字段分别嵌入后相加： \[ \mathbf e_{t,i}=E_y(z_{t,i}^y)+E_c(z_{t,i}^c)+E_f(z_{t,i}^f), \quad \mathbf h_\theta=U_\theta(\mathbf e_t;t,\kappa), \quad \boldsymbol\ell_i^\rho=D_\rho(\mathbf h_{\theta,i}),\ \rho\in\{y,c,f\}. \] 共享 UNet \(U_\theta\) 处理跨高度切片的求和字段嵌入，三个预测头 \(D_y,D_c,D_f\) 输出各通道 logits。跨切片一致性通过跨切片注意力实现：在注意力分辨率上，把同一平面位置 \((u,v)\) 的 \(S\) 个切片特征视为 \(S\) 个 token，沿切片维做注意力并残差写回，使同一物体在不同高度的范围与 body/front 线索互相印证。跨通道一致性让实例颜色和朝向预测依赖语义特征：属性分支受语义特征分支通过学习的门控和偏置调制。训练目标同时监督 token 去噪和下游几何量： \[ \mathcal L=\lambda_y\mathcal L_y+\lambda_{\mathrm{cls}}\mathcal L_{\mathrm{cls}}+\lambda_c\mathcal L_c+\lambda_f\mathcal L_f+\lambda_{\mathrm{occ}}\mathcal L_{\mathrm{occ}}+\lambda_{\mathrm{attr}}\mathcal L_{\mathrm{attr}}. \] 其中 \(\mathcal L_y\) 是语义掩码交叉熵；\(\mathcal L_{\mathrm{cls}}\) 是按训练集对象计数做逆平方根加权的类别平衡语义损失，建筑/背景权重为 1，先对每个真实对象的格子语义交叉熵取平均，再对对象取平均，以提升稀有类别和小实例影响；\(\mathcal L_c,\mathcal L_f\) 是可见家具格上的实例颜色和朝向掩码交叉熵；\(\mathcal L_{\mathrm{occ}}\) 是由语义 logits 导出的前景占用二分类交叉熵；\(\mathcal L_{\mathrm{attr}}\) 对实例池化特征回归 yaw 的 \((\cos\theta,\sin\theta)\)、高度和垂直偏移。关系：该小节实现 3.2 的反向去噪器，把三通道联合预测落到共享骨干和三个头上，并把 3.1 的切片结构用于跨切片推理。

Figure 3：MDiRT 概览。给定选定高度切片和建筑掩码，我们保持固定房间结构不变，并用带跨切片注意力的共享 UNet 去噪被掩码的内部 RoomTokens。去噪器在语义门控有效性约束下预测语义、实例颜色和朝向切片：建筑/背景 token 不携带实例颜色或朝向线索，而家具 token 携带。随后将有效 RoomToken 网格分组为对象记录，其类别、尺寸和位姿用于检索并放置匹配的 3D 资产。

3.4 Inference and Scene Assembly（推理与场景组装）

目的：把生成的三字段离散网格恢复成对象级布局，并实例化为最终 3D 场景。机制：推理时建筑格从输入建筑掩码固定，MDiRT 只对室内家具区域采样三字段切片，建筑 token 不会被覆盖，因此家具被限制在合法室内区域。采样完成后，将同语义且同实例颜色的连通 RoomToken 分组成对象实例；token 给出类别、水平中心和水平尺寸，body/front 标签给出朝向线索。MDiRT 内的 MLP 头用每个实例掩码内平均的去噪特征预测连续高度和垂直偏移；当 body/front 不足以确定朝向时，yaw 头提供朝向。随后按类别在 3D-FUTURE 中检索三维范围最接近的资产，沿各轴缩放到估计尺寸，按预测 yaw 旋转，再平移到恢复位置。该流程在资产放置后不做裁剪、额外优化或手工场景修正。关系：该小节承接 3.2 的采样和 3.3 的预测头，把离散 token 转成对象记录和最终资产；它也是第 4 节推理流程的方法依据。需要注意，token 网格内的合法与不出界不等于最终网格资产无碰撞：旋转和缩放本身可能引入新的对象—对象或对象—墙相交。

Figure 6：旋转和缩放对资产放置的影响。两个原始 MDiRT 场景均具有无碰撞的家具放置，且未测得边界违规。橙色圆圈标记对象–对象相交，红色标记对象–墙相交，如图 4 所示。(a) 固定偏航角时，沙发和电视柜与咖啡桌碰撞，并分割可行走地面，降低 NAV。地面叠加层以青色显示最大连通可行走区域，以紫色显示被家具截断的区域。(b) 采用 MDiRT 放置时，间隙将电视柜分开。若不缩放，较高的柜子会与较矮的柜子重叠。虚线轮廓描绘部分隐藏的柜子，橙色阴影标记重叠。该碰撞提高 COL，而可行走地面仍保持连通。

6. 局限性和展望（约300字）

论文明确说明的限制有：固定网格和固定高度切片可能漏掉细节和窄缝；3D-FRONT 训练集规模较小且类别、房间类型分布不均；RoomTokens 与合法性投影不能阻止后续分组、连续位姿估计、缩放和资产检索造成的网格碰撞；最终场景可能仍出现不合理布局、对象相交或门洞被遮挡。论文建议用更大更多样的数据、更强的场景组装、自适应分辨率切片和几何感知细化来改善分布匹配、细节与碰撞。

可以谨慎推断的限制是：0.10 m 的平面分辨率天然难以表达小于格子的薄结构或窄间隙；固定切片集合对非常规高度物体不够灵活；方法没有显式物理或功能仿真，token 合法和边界内放置并不保证家具可访问、门洞真正可用或功能布局合理。Figure 5 的失败案例正说明：即使 RoomToken 合法且对象在边界内，仍可能出现不合理布局、对象相交和门洞遮挡。未来可把结构化占用 token 扩展到室外场景、带部件物体和其他语义占用任务，但需要同时处理分辨率、资产放置和功能可行性验证。
