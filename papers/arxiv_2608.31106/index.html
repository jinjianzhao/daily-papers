DreamX-Creator: Democratizing Native Audio-Video Generation at 2K Resolution

一句话主题： 构建原生联合音频-视频生成模型DreamX-Creator，实现文本和首帧条件下的音视频同步生成。

领域标签： 音视频生成 / 联合扩散模型 / 2K高清生成

快速理解

背景与任务： 现有视频生成常忽略音频或分阶段合成，难以建模视觉动态与声学事件之间的交互关系。

核心工作： 作者提出紧凑的7B联合生成器、音视频数据系统、渐进训练与强化学习流程，并借助自回归单步2K精炼实现原生同步音视频生成。

中文摘要

近期视频生成器通常省略音频或在独立阶段合成音频，限制了对视觉动态与声学事件的交互建模。我们提出 DreamX-Creator 1.0，一个以 7B 生成器为核心的紧凑型原生联合音视频生成系统。在首帧和文本提示的条件下，生成器联合去噪模态特化的音频流和视频流。这些流在网络前半部分独立处理，在后半部分通过门控跨模态注意力（Gated Cross-Modal Attention）耦合，其令牌级和头级输出门控调节每个活跃的跨模态注意力头输出。统一的音视频数据系统构建并过滤时间连贯的片段，生成结构化多模态标注，并将片段组织为面向能力的数据池。渐进式联合训练包括两个音视频预训练阶段，随后进行高质量微调。音视频强化学习进一步利用模态感知多模态反馈对生成器进行后训练，将视频、音频和跨模态反馈路由到相应流。对于高分辨率输出，我们的自回归 1 步 2K 精炼流程将双向多步教师适应为自回归多步精炼器，并将其蒸馏为一个每时间块只需一次去噪评估的学生模型。总体而言，DreamX-Creator 1.0 实现了原生、同步的音视频生成，性能可与最先进的开源系统相媲美。通过发布我们紧凑的 7B 生成器和 2K 精炼器，我们旨在推动原生音视频生成的普及，并为未来统一音视频生成建模研究提供可访问的基础。

详细分析

1. 任务输入、输出、功能和边界（约100字）

输入为一张首帧图像 \(I\) 与一段文本提示 \(c\)；输出为与文本语义匹配、视听同步的 2K 短视频及对应音频。系统使用原生联合音视频生成，不做“先视频后音频”或“先音频后视频”的单向级联；内部可切换 A2V、V2A、Joint 三种交互模式。边界是必须同时提供首帧与文本，且音频不参与 2K 精炼。权重开放，可在本地运行。

2. 研究动机：要解决的问题与核心 insight（约300字）

当前视频生成常省略音频，或把音频作为后置环节，也就是“先生成视频再补音轨”或“用音频驱动视频”。这类单向公式把一种模态固定为条件、另一种模态作为输出，限制了视觉动态与声学事件之间的双向耦合：物体碰撞及其声音、语音与口型的关系、环境氛围与镜头运动的关联，都需要两个模态同时演化才能准确决定。论文指出四个未解决问题：第一，原始音视频数据噪声大且存在跨镜头污染，片段切分、多模态质量过滤、同步评估和联合标注都很困难；第二，跨模态交互强度应随层、注意力头、token 和样本变化，简单拼接或全连接容易淹没模态特有表示；第三，流匹配或似然目标无法直接优化感知质量、提示遵循、跨模态语义一致与细粒度时间同步；第四，联合生成与 2K 高分辨率精炼的计算需求不同，直接生成 2K 成本过高。

核心 insight 是：不靠超大主干，而是用一个紧凑 7B 生成器搭配双路专用表示、门控跨模态注意力、面向能力的数据组织以及高效 1 步精炼，在联合音视频生成、同步质量和本地 2K 可运行性之间取得平衡；同时公开权重，降低该方向研究与复现门槛。

3. 核心贡献（约300字）

  • 音频-视频数据系统：整合多源公共数据集与内部数据，经过场景分段、静音与低质量剔除、视觉/音频多维质量评估、Synchformer 与 SyncNet 同步过滤，再通过 Qwen3-Omni 联合分析、ASR 转录与 Qwen3.6-27B 融合生成结构化标注；最后按“语音对话、动作拟音、氛围音乐、通用电影”四个能力池组织数据，为不同训练目标提供定向监督。
  • 原生联合音视频生成：提出 7B 双流联合生成器。视频与音频流前半独立处理，后半通过门控跨模态注意力实现 A2V 与 V2A 双向交互；三阶段渐进式训练包括 LoRA 预训练、全参数预训练与高质量微调，全程混合 A2V/V2A/Joint 模式。
  • 音频-视频强化学习：提出模态感知多模态反馈，将视频、音频、跨模态优势分离并路由到对应流；同步相关局部视频 token 被赋予更高权重，深层跨模态模块承担更多梯度，以保护预训练能力。
  • 自回归 1 步 2K 精炼：用退化课程训练双向多步精炼教师，再把它强制转换为自回归多步 refiner，最后用 DMD 蒸馏为 1 步学生；推理时每个时间块只需一次去噪评估，输出 2K 视频且不改音频。
  • 开源 7B 生成器与 2K Refiner：按论文表 1 的公开信息，这是最小的同时满足“权重可下载、原生联合音视频、官方本地 2K 路径”的生成主干。

4. 推理阶段整体流程与基模（约400字）

推理时使用两个模型：7B 联合生成器负责以第一帧和文本为条件，联合去噪输出低分辨率视频流与音频流；自回归 1 步 2K Refiner 负责在低分辨率视频上逐时间块恢复 2K 细节，并保持音频不变。

5. 核心方法：按论文 Method 小节总结（约600字）

2 Audio-Video Data System（音视频数据系统）

该模块把原始视频整理为训练可用片段。图 3 给出数据系统全流程。

图3：DreamX-Creator 1.0数据系统概览，包括异构数据收集、片段构建与过滤、结构化多模态标注以及面向能力的数据组织。

2.1 Data Collection（数据采集）

整合 Koala-36M、VGGSound、AudioSet、OpenHumanVid、SpeakerVid-5M、Action-100M、Talker-T2AV 与内部采集数据，覆盖不同内容域和音视频交互类型。

2.2 Data Filtering（数据过滤）

先用 PySceneDetect 按场景切分并裁剪边界帧，去除近静音与低质量片段；再用 Q-Align 评估视觉质量、光流评估运动幅度、Audiobox Aesthetics 评估音频质量；Synchformer 评估通用音视频对齐，SyncNet 在可见语音片段上做唇音同步过滤。

2.3 Data Annotation（数据标注）

用 Qwen3-Omni-30B-A3B-Instruct 联合分析视频和音频，得到含主体、动作、场景、语音、音乐、音效及时间顺序的结构化描述；Qwen3-ASR-1.7B 提供语音转写；Qwen3.6-27B 将前者与 ASR 转录合并为一条连贯提示，保留时间结构与口述内容。

2.4 Capability Taxonomy（能力分类）

按主导跨模态监督信号将片段分为四池：语音与对话、动作与拟音、氛围与音乐、通用电影。前两者分别强化 A2V 与 V2A 方向，后两者兼顾 Joint；数据分布中语音约 45.0%、事件音约 33.4%，其余为音乐、自然声与混合内容。

3 Native Joint Audio-Video Generation（原生联合音视频生成）

3.1 Architecture Overview（架构概览）

双流架构各自保留 token 率、位置编码与 Transformer 主干；前半独立，后半加入 A2V 与 V2A 跨模态路径。方向掩码决定激活哪条路径：A2V 时 \(\sigma_v>\sigma_a\)，V2A 时 \(\sigma_a>\sigma_v\)，Joint 时两者相等。跨模态更新为 \[ \Delta h^v=m_{a\to v}\mathrm{Attn}(Q(h^v),K(\hat h^a),V(\hat h^a)),\quad \Delta h^a=m_{v\to a}\mathrm{Attn}(Q(h^a),K(\hat h^v),V(\hat h^v)). \] A2V/V2A 对条件流使用 stop-gradient，Joint 不使用。

3.2 Gated Cross-Modal Attention（门控跨模态注意力）

每条路径在共享多头空间计算 Q、K、V，添加时间 RoPE 与掩码。每个注意力头输出 \(C_{i,h}\) 先经过 token 级、头级 sigmoid 门控再拼接投影： \[ g_{i,h}=\operatorname{sigmoid}([W_x\mathrm{LN}(x_i)]_h+\mathbf{w}_c^\top \mathrm{LN}(C_{i,h})+b_h). \] 门控调节每个头的信息量，方向掩码决定整个残差是否加入。

3.3 Progressive Joint Training（渐进式联合训练）

Stage 1 冻结两主干前半，后半加 rank-256 LoRA，交叉模态模块直接训练；Stage 2 合并 LoRA 后全参数联合训练；Stage 3 用同步分数、视觉/音频美学分数、分辨率、时长与 OmniShotCut 过滤后的高质量子集微调。

3.4 Optimization Details（优化细节）

视频与音频各用独立采样的高斯噪声做流匹配，计时表为 1000 步、shift=5，并按 A2V/V2A/Joint 模式控制噪声顺序。总损失为 \[ \mathcal{L}_{\mathrm{AV}}=\lambda_v\mathcal{L}_{\mathrm{FM}}^v+\lambda_a\mathcal{L}_{\mathrm{FM}}^a. \] 预训练两路权重均为 0.5，高质量微调改为 0.5 与 0.1。优化器使用 AdamW、bfloat16 与梯度裁剪 1.0；Stage 1 与 Stage 2 采用分组成员的学习率，微调逐步降低。

4 Audio-Video Reinforcement Learning（音视频强化学习）

4.1 Overview（概览）

流匹配不直接优化感知质量、提示遵循、语义一致与时间同步。RL 阶段把多维度奖励分开，避免某一模态的进步掩盖另一模态的退化。

图6：面向联合音视频生成的模态感知强化学习。视频和音频特定奖励被路由到对应流，而共享的音视频同步奖励联合优化两个流及其跨模态交互。

4.2 Modality-Aware Multimodal Feedback（模态感知多模态反馈）

定义视频优势 \(A_v\)、音频优势 \(A_a\)、跨模态优势 \(A_{av}\)，路由为 \[ \tilde A_v=A_v+A_{av},\qquad \tilde A_a=A_a+A_{av}. \] 同步关键区域由 V2A 注意力响应估计，帧内归一化后转成 token 权重 \(w_i^{(e)}\)，\(\alpha_e\) 随训练步从 0 渐增。深层交互块允许更多梯度回传，浅层梯度被衰减，以保护预训练表示。

4.3 Training（训练）

从预训练基础模型初始化策略，在 1000 对首帧-提示上每组生成 \(G\) 个候选，用视频质量、音频质量、提示一致性与同步奖励评分；奖励在组内归一化得到优势，再按上式计算路由。完整目标为 \[ \mathcal{L}_{\mathrm{RL}}=\lambda_v\mathcal{L}_v(A_v+\lambda_{av}^vA_{av})+\lambda_a\mathcal{L}_a(A_a+\lambda_{av}^aA_{av})+\lambda_{\mathrm{reg}}\mathcal{L}_{\mathrm{reg}}(\pi_\theta,\pi_{\mathrm{base}}). \] 周期用当前策略刷新 rollout 模型，形成在线更新。

5 Autoregressive 1-Step 2K Refinement（自回归1步2K精炼）

5.1 Bidirectional Refiner（双向精炼器）

训练双向 DiT 教师，以低分辨率视频为条件做流匹配。退化课程从轻到重，包含模糊、噪声、压缩伪影、重采样、几何畸变与时间相关闪烁，使教师学会修复生成视频的伪影而非只能做空间锐化。

5.2 Autoregressive Refiner（自回归精炼器）

双向教师多步推理成本高，因此将其强制转换为自回归多步 refiner：当前块以低分辨率视频与真实历史 HR 块为条件去噪，使其时间结构与最终部署一致。

5.3 DMD Distillation（DMD 蒸馏）

用 DMD2 把自回归多步 refiner 蒸馏为 1 步学生。蒸馏时使用学生自己的生成块作为历史上下文，避免曝光偏差；目标为分布匹配损失、DISTS 感知损失与 \(\ell_2\) 重构损失之和。推理时每个时间块只做一次去噪评估，完成 2K 精炼。

6. 局限性和展望（约300字）

论文明确说明的限制：与 LTX-2.3（22B）和 MiniMax-H3（33B）相比，7B 模型在音频美学（CE/CU/PQ）、ImageBind 语义一致性以及唇同步 LSE-C 上仍有差距，VQ 与低 DeSync 属于权衡优势而非整体超越。用户研究也指出，该对比未充分覆盖动态复杂场景；在样本子集上音频保真与跨模态对齐是对抗更大系统时的主要短板。此外，2K Refiner 只处理视频，音频保持生成器输出不变，因此音频分辨率不会从精炼中受益。

可谨慎推断的边界：自回归 1 步精炼逐块使用先前块的输出作为上下文，在长时间、强运动场景中可能存在块间一致性风险，论文未报告对应的长时连贯指标；自动评估器可能被 RL 奖励模型利用，因此需要受控的时间偏移测试与人工对比来验证真实同步改善；数据系统依赖 Qwen 系列模型做标注，其错误或风格偏差会传导到下游生成。

展望上，后续可扩展主干规模或使用稀疏激活，把音频精炼纳入 2K 路径，并用更细粒度的同步奖励与更公平的评测缩小与更大开源模型的差距。
