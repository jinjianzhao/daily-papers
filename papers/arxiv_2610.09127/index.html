CADFather: Autonomous CAD Reconstruction through Coordinated Tool Use

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 利用多工具协调的自主智能体实现CAD程序重建

领域标签： CAD重建 / 智能体系统 / 计算机辅助设计

快速理解

背景与任务： 从3D形状重建可编辑CAD模型困难，现有方法单一来源的候选操作在不同几何和阶段效果不佳。

核心工作： 提出CADFather，通过视觉-语言助手协调互补工具，自动选择扩展程序、调用工具并优化参数，无需额外训练即可提升重建质量与有效性。

中文摘要

从三维形状重建可编辑的CAD模型仍是一项具有挑战性的工程任务。现有方法能够提出CAD操作，但没有任何单一的提议来源能在不同零件几何形状和重建阶段中同样奏效。我们提出了CADFather，一个自主智能体系统，它协调互补工具从三维网格中恢复参数化CAD程序。视觉-语言助手检查目标和中间重建的渲染图，然后决定扩展哪些候选CAD程序、调用哪些工具、生成多少提议以及何时结束。学习型和算法型工具提出CAD操作，而数值优化则优化现有程序的参数。提出的或优化后的程序会被执行和评估，为后续决策提供反馈。该智能体为每个目标零件维护多个备选候选程序，并在整个重建过程中保留最佳有效结果。CADFather使用预训练的生成模型和助手模型，无需额外训练。我们在完整的DeepCAD、Fusion360和MCB测试集以及CADENA-Bench、CADBench和BenchCAD上评估重建质量和执行有效性。我们还分析了计算成本以及成本与重建质量之间的权衡。

详细分析

1. 任务输入、输出、功能和边界（约100字）

任务输入是一个目标网格 \(M^\star\)，输出是一个可执行的 CAD 程序 \(p\)，其执行几何 \(\mathcal{E}(p)\) 尽量匹配目标。功能上，CADFather 以逆向工程方式恢复建模操作与参数，使结果可编辑。边界：面向单个零件而非装配体；依赖 CadQuery DSL 支持的操作；不恢复原始设计历史、制造意图或工程约束。

2. 研究动机：要解决的问题与核心 insight（约300字）

网格只描述形状，不编码用于构造该形状的建模操作和特征参数。要从网格恢复可执行的 CAD 程序，需要同时决定“用哪些操作”和“这些操作的参数是多少”。已有方法能提出 CAD 操作，但没有任何单一来源在不同零件几何和重建阶段都表现良好：学习式生成器可以提出合理的建模操作，但可能漏掉某个特征或给出不准确的尺寸；算法式构造可以直接从目标几何中导出操作，适合补充学习式方法遗漏的结构；数值参数优化则能修正已有程序的尺寸，但不能改变操作序列。

核心 insight 是：与其绑定单一操作来源，不如把“选哪个候选程序继续、调用哪种工具、生成多少提议、何时结束”作为一个决策问题，交给一个能同时观察目标渲染、中间重建渲染和数值反馈的视觉语言助手。系统同时维护多个候选程序，而不是只编辑单条轨迹；每个工具的提议都先执行、度量、渲染，再由助手决定是否接受。这样，学习式提议、算法式提议和参数优化可以互补，并且系统始终保留当前最佳的有效结果。CADFather 没有训练新的生成器或助手，而是通过协调现有工具来获得更稳定、更完整的重建。

3. 核心贡献（约300字）

论文提出并验证了 CADFather，一个从目标网格自主重建可执行 CAD 程序的智能体系统。贡献主要有三点：

第一，提出了一个基于视觉与执行反馈的网格到 CAD 重建智能体。视觉语言助手在每一步观察目标网格、候选程序渲染、候选表和执行历史，选择要延续的候选、要调用的工具、学习式提议的采样数量，或者决定结束。这种决策方式把工具选择从固定流程变成由当前重建状态驱动的主动选择。

第二，构建了一个共享重建框架，把三类互补工具统一到同一套程序表示中：学习式操作提议、算法式几何拟合提议、数值参数优化。所有工具产生的候选程序都进入同一个候选池，可以被其他工具继续扩展或精修；系统保留多个替代候选，并始终维护受保护的最佳有效结果。

第三，在六个数据集上进行了系统评估，包括 DeepCAD、Fusion360、MCB、CADENA-Bench、CADBench 和 BenchCAD。论文还通过消融实验分别移除算法式提议、参数优化或两者，来分析各工具对重建质量和有效性的贡献。实验表明，额外的工具多样性和候选搜索能显著提升几何保真度和程序有效性。

4. 推理阶段整体流程与基模（约400字）

推理时使用两个现成基模：视觉语言助手 Qwen3.8-27B 负责做高层决策；学习式操作生成器 CADENA-RL 负责从已有程序继续采样下一操作。算法式提议与参数优化是另外两类工具，不依赖学习模型；执行、度量与候选池管理由环境完成。图1给出系统总览。

Figure 1: CADFather 总览。给定目标网格和来自现有 CAD 候选的反馈，视觉助手选择要继续的候选程序、要应用的工具以及要生成的提议数量。学习式和算法式提议产生替代延续方案，参数优化则细化现有候选。所得程序被执行和评估，助手在进入候选池之前通过视觉接受或拒绝它们。其渲染结果和分数为后续决策提供信息。* 在图中，“stepwise”表示学习式提议，“deterministic”或“det”表示算法式提议。

  1. 输入与初始化：输入目标网格 \(M^\star\)。初始化模块建立候选池，根为空程序；渲染目标，并生成候选表，表中包含当前可继续候选、可用工具、剩余预算和已有分数。输出候选表与渲染，交给助手。
  2. 助手决策：输入目标/候选渲染、候选表和重建历史。视觉语言助手输出函数调用动作：选择某个候选、调用某种工具、指定学习式提议的采样数，或者发出 finish 结束零件。动作交给执行组件。
  3. 工具执行：输入动作。学习式生成器为指定父程序采样 \(n\) 个下一操作提议；算法式提议通过几何拟合生成下一操作；参数优化工具调整已有候选中的数值参数。输出若干新的程序提案。
  4. 执行、度量与视觉接受：输入程序提案。环境运行程序，验证是否能构建、是否水密、是否为正体积，并计算与目标网格的度量；随后渲染新候选。助手查看渲染和度量，决定接受或拒绝。接受者加入候选池，拒绝者不入池；候选表和渲染随之更新。
  5. 循环：助手再次看到更新后的候选表、渲染和历史，重复步骤 2–4，直到发出 finish 或达到步骤、时间、执行次数上限。过程中受保护的最佳有效结果始终被保留。
  6. 输出：系统输出受保护的最佳有效 CAD 程序，而不是助手最后处理的那个候选。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Problem Formulation and System Overview（问题定义与系统总览）

给定目标网格 \(M^\star\)，CADFather 寻找可执行程序 \(p\)，使执行几何 \(\mathcal{E}(p)\) 匹配目标。候选程序采用 CADENA 的 CadQuery DSL；所有工具产生同一表示，因此一个工具生成的候选可以被另一个工具扩展或精修。系统维护候选池，视觉语言助手每步选择候选、工具、采样数或结束；执行组件负责运行、验证、度量和保护最佳结果。生成模型和助手模型无需额外训练。

3.2 Candidate Pool（候选池）

每个候选记录标识符、父节点、来源工具、程序、生成网格、操作数、有效性和度量。根为空程序；扩展候选会创建子候选，参数优化则改变已有参数，因此与追加操作区分。候选池保留早期候选，助手可以重新访问，不限于最新一代。代码级去重避免相同程序重复入池。

助手每步只看到有界候选表，而不是整个池。只有能构建、水密且仍存在合法动作的候选才会被列出，最多 12 个，按分数降序排列；受保护最佳和空起点若不在其中也会显示。每行包含候选 ID、来源工具、操作数、状态、总分数、第一操作分数以及仍可用的工具。第一操作分数帮助助手判断是延续当前分支，还是从空程序重新开始；工具耗尽后，该工具从对应行消失。

3.3 Assistant Decision Step（助手决策步骤）

每一步针对整个零件，而不是单个候选。助手输入由四部分组成：固定规则、历史记录、渲染图、候选表。历史记录只记录实际执行的动作，而不是请求了但被丢弃的动作。渲染图只显示目标、当前最佳、上一步产生的最佳候选（若上一步产生了新最佳，则同时显示其父候选）；早期渲染不保留。新提议是否进入候选池还需助手通过渲染做视觉接受。

助手通过函数调用回答：先写一句理由并记入历史，然后最多发出四个 act 调用，每个调用指明工具和候选；学习式提议还需指定样本数 \(n\)。finish 调用可以伴随 act 调用，表示该步是最后一步。图2展示一次完整决策步骤。

Figure 2: 一次助手决策步骤：图 3 中轨迹的第 3 步（MCB 链环）。最佳候选 c13 有一个板和一个柱，而目标各有两个。助手用学习式提议生成和算法式提议继续 c13；学习式提议生成添加了第二个柱（c15），两次调用的结果进入下一步的记录。摘自日志中的提示和答案：规则经过意译，记录和推理为摘录，表格显示 10 行中的 5 行，det 表示算法式提议，并显示四个渲染视图之一。

3.4 Reconstruction Tools（重建工具）

学习式提议生成：对父程序 \(p_i\)，一次请求生成 \(n\) 个下一操作提议，每个提议分别形成子候选。\(n\) 是备选数量，不是连续操作数；助手选择的上限由固定单次上限和剩余生成预算共同决定。

算法式提议生成：通过几何拟合构造操作，不依赖学习模型。在空起点上，它从目标网格直接提出第一操作：回转体先回转轮廓，然后通过截面寻找拉伸特征；已有候选上，它比较候选与目标，找出缺失材料和多余材料，分别生成拉伸和切割提议，每次调用返回下一个四条提议。该工具对“学习式首操作总产生开放曲面”的零件尤其重要。

参数优化：只修改已有候选的数值参数，不改变操作结构；自由参数包括草图坐标、半径和拉伸深度。它用有符号距离构造目标，用数值差分估计梯度，先在全部分上拟合，再在目标表面附近拟合，并在起始、粗、细参数中选择表面匹配最好的一组。精修后的程序仍要执行、度量并通过视觉接受。

3.5 Execution, Measurements, and Protected Best（执行、度量与受保护最佳）

工具输出只是提议，必须经过技术验证、度量和视觉接受后才能进入候选池。候选无效条件包括：程序无法构建、网格不是整体水密正体积实体、执行或度量超时。这比 CADENA 的评估更严格。

度量前，目标按包围盒中心和最大维度统一缩放；候选使用同一个固定变换，而不是按自身包围盒归一化，因此尺寸错误的候选会得到较低分数。度量包括 IoU 和 GMS，其中

\[ I_i=\frac{V(M^\star\cap\mathcal{E}(p_i))}{V(M^\star\cup\mathcal{E}(p_i))}, \]

GMS 原始值在 \([0,25]\) 上归一化为 \(H_i=1-\mathrm{GMS}_{\mathrm{raw},i}/25\)。候选分数为可用度量的平均：

\[ s_i=\frac{1}{|\mathcal{Q}_i|}\sum_{q\in\mathcal{Q}_i}q,\qquad \mathcal{Q}_i\subseteq\{I_i,H_i\}. \]

无效候选记 0 分。系统始终保留按该分数计算的最佳有效结果，最终输出也是这个受保护最佳，而不是助手最后操作的候选。

3.6 Budgets, Recovery, and Termination（预算、恢复与终止）

每个零件都有工具预算，候选表会显示剩余情况；超出预算的请求会被削减或拒绝，并告知助手。finish 会结束整个零件，理由是 shape 或 stalled；在至少存在一个有效候选之前，finish 会被忽略。固定的步骤数和运行时间上限保证终止。如果助手回复格式错误或只请求不可用动作，系统会要求重新决策；若再次失败，则对最佳候选执行最便宜可用动作，并告知助手。失败执行会反馈给助手，受保护最佳不会丢失。图3显示一条完整重建轨迹。

Figure 3: MCB 零件（链环）上的重建轨迹。该图追踪最终结果的谱系，每个助手步骤或步骤组一列：每个渲染图上方是这些步骤中调用的工具，生成所示候选的工具用粗体；其下方是候选 ID、IoU 和 GMS。算法式起点 c5 恢复了一个柱，一个热启动的算法式提议添加了下板（c13），学习式操作提议添加了第二个柱（c15）和上板（c20）；在相同步骤中，学习工具最先提出的操作只产生开放壳体，其他子候选得分较低。在第5–6步中增益变小；第7步的候选 c26 的 IoU 高于 c25，但 GMS 低于 c25；在第8步，助手以 finish(stalled) 结束该零件，输出是受保护的最佳候选 c25。

6. 局限性和展望（约300字）

论文明确说明的限制包括：CADFather 受其 CAD 表示和工具能产生的提议类型限制；参数优化只能修正参数，不能修正错误的操作序列；保留早期候选也无法弥补“从未生成过有用备选”的情况。搜索预算可能提前终止本可成功的轨迹，且助手依据不完整的视觉和数值证据做决策，因此不保证找到最优重建。评估只衡量几何重建和程序有效性，不衡量是否恢复原始设计历史、制造意图或工程约束，也只覆盖单个零件而非装配体。

Figure 4: BenchCAD 上体素 IoU 与每零件估计 token 成本的关系（对数刻度）。CADFather 在随机抽取的 1000 个零件上评估；每个点是完整预算运行中前 k 个助手步骤之后的均值（k=1,2,3,4,6,8,12,24），虚线标记其完整预算水平。助手和生成器 token 均按 OpenRouter 对 Qwen3.8-27B 的费率定价（每百万输入和输出 token 分别为 $0.425 和 $2.55）。前沿曲线取自 BenchCAD 排行榜（BenchCAD Team, 2026）。

论文还列出典型失败案例：错误初始拓扑使后续操作无法恢复、体积匹配但表面结构缺失、资源限制导致提前终止。图7给出两类例子。

Figure 7: 完整测试集中的失败案例。每对图像在共同坐标系中显示目标和 CADFather 结果，IoU 和 GMS 在结果上方。左：高 IoU 但低 GMS，体积匹配但缺少滚花（MCB）和浅凹槽（Fusion360）。右：因挂钟时间限制（MCB，弹簧被重建为管状）和执行限制（Fusion360，带不完整肋的支架）而停止的零件。

可以谨慎推断，由于助手是现成模型而非针对该任务专门优化，其工具选择策略可能不是最优；若 DSL 增加更多操作类型，也需要扩展相应工具。高几何分数也不直接等同于参数可编辑性，因为度量不关心参数名称或特征语义。论文列出的未来工作包括与 CAD-Assistant、IterCAD 等智能体的直接对比，以及对助手工具选择策略的受控评估。
