WorldRuler: Interactive World Modeling under Configurable Rules

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 面向可配置规则的可交互世界建模与规则驱动视频生成

领域标签： 生成式世界模型 / 规则驱动交互建模 / 可执行3D规则图

快速理解

背景与任务： 现有生成式世界模型难以在保存加载和视觉生成中持续遵循用户自定义规则。

核心工作： 作者提出WorldRuler，以可执行3D规则图闭环连接规则执行、视频生成与感知反馈，并引入动态对象绑定、属性状态替换、反事实重建训练及RuleVerse数据集。

中文摘要

规则支配玩家动作如何改变交互世界。不同规则在相似场景和动作空间中创造不同的游戏玩法体验。对于可定制游戏玩法，生成式世界模型必须遵循超出真实世界行为的用户定义规则。然而，实现用户定义规则面临两个挑战：规则-状态持久化（Rule-State Persistence）与规则到视觉实现（Rule-to-Visual Realization）。前者要求在保存与加载过程中保留规则定义、依赖关系和世界状态，使恢复后的世界遵循既定规则。后者要求准确实现规则在指定对象与属性上引发的改变，尤其是当受影响对象不可见时。本文提出 WorldRuler，它将规则定义、依赖关系和对象状态组织为一个可执行的 3D 规则图，并以闭环方式连接规则执行、视频生成与感知反馈。该图支持规则与世界状态的联合保存与恢复，同时动态对象绑定将规则指定的实体绑定到视觉实例，并使用存储状态从这些对象首次出现起约束生成。我们进一步引入对象属性状态替换与反事实重建训练，实现准确的属性控制以及兼容的外观与运动变化，同时限制对无关内容的干扰。我们使用 GTA-V 和 Habitat 开发了一个自动化数据收集与标注流水线，以构建 RuleVerse，这是一个包含详细状态与事件标注的规则驱动交互数据集，其中包括规则在受影响对象变得可见之前就已生效的情况。大量实验表明，WorldRuler 在保存与加载过程中保持规则-状态一致性，以及在指定对象与属性上准确实现规则结果方面是有效的。

详细分析

1. 任务输入、输出、功能和边界（约100字）

WorldRuler 的输入是初始视觉观测 \(I_0\)、用户定义的规则集合 \(\mathcal{R}\) 以及玩家动作序列；输出是连续生成的交互视频，其中规则诱发的状态变化应出现在指定对象和属性上。系统功能包括规则与世界的联合保存/加载、规则到视觉的实现、以及跨窗口的感知反馈闭环；边界是不替代真实物理引擎，也不保证任意自然语言规则都能被自动形式化。

2. 研究动机：要解决的问题与核心 insight（约300字）

论文要解决两个相互耦合的问题。第一是 Rule-State Persistence：规则定义、规则依赖和世界状态必须在保存与加载后完整保留，包括当前视野之外的信息。例如“剑击败怪物→怪物掉落钥匙→钥匙开门”的规则链，若玩家在拾取钥匙前存档，恢复后必须仍保留被击败的怪物、地上的钥匙、关闭的门以及剩余规则。第二是 Rule-to-Visual Realization：规则诱发的改变必须落到指定对象和属性上，尤其当受影响对象尚未出现在画面中时。例如开关打开了视野外的门，玩家第一次看到门时它就应当已经是打开的，而不是等玩家再次触发。

核心 insight 是用一个可执行的 3D 规则图把规则定义、依赖、对象身份、属性状态和空间信息组织在一起，并让规则执行、视频生成和感知反馈形成闭环。动态对象绑定负责把规则实体关联到视觉实例，属性状态替换则在生成过程中把被控属性纠正到规则目标，从而同时支持持久性和视觉实现。

Figure 1：WorldRuler 能够实现持久、受规则支配的生成式世界。保存的规则和世界状态使玩家在加载后能够收集钥匙并打开门，展示了 Rule-State Persistence 与 Rule-to-Visual Realization。

3. 核心贡献（约300字）

论文提出并构建了 WorldRuler 框架：用可执行 3D 规则图联合维护规则定义、依赖、对象状态和空间绑定，支持规则与执行状态的联合保存与恢复；通过动态对象绑定把规则实体与 3D 实例及当前图像区域关联，并用感知反馈更新绑定和可观测状态；通过对象属性状态替换在生成过程中修正被控属性。

论文还提出反事实重建与属性交换的训练方式，使属性替换不仅能满足规则目标，还能产生与外观、运动相容的视觉变化，并尽量不干扰无关内容。为支持训练与评估，作者用 GTA-V 和 Habitat 构建了 RuleVerse 数据集，包含成对的“规则启用/禁用”交互视频、对象状态、触发条件、规则后果和事件时序标注，并覆盖“规则在受影响对象可见之前已经生效”的情况。论文在 RuleVerse 和 WorldState-Bench 上验证了规则持久性、规则到视觉实现以及恢复后的一致性。

4. 推理阶段整体流程与基模（约400字）

推理时，系统以 MiniMax-H3 Ref2VA Turbo 作为视频生成基模，负责根据初始图像、历史视频、动作和规则条件生成下一个视频窗口；Qwen 编码器把条件编码给生成器；SAM2 用于实例分割，DA3 用于几何估计；Qwen3.8-Max 等视觉模型用于从生成帧中估计对象身份、可见性和属性。规则执行器是符号模块，不负责像素生成。

  1. 玩家动作与规则执行：输入当前动作 \(u_t\)、3D 规则图 \(\mathcal{G}_t\) 和执行状态 \(X_t\) → 规则执行器检查动作条件、状态前置条件、空间条件和事件顺序 → 输出对象状态序列 \(S_n\) 与规则事件，交给条件构造和状态更新。
  2. 动态对象绑定：输入规则实体、3D 实例、当前帧和几何信息 → 绑定模块用语义、外观和空间一致性把规则实体对应到 3D 对象及图像区域，并用实例分割得到掩码 → 输出对象绑定 \(\mathcal{B}_t\) 和可控制区域，交给条件构造与属性替换。
  3. 生成条件构造：输入规则图、绑定、对象状态和空间信息 → 把规则状态转成全局布局描述和对象级属性目标 → 输出生成条件 \(C_n\)，交给视频生成器。
  4. 视频窗口生成：输入初始图像、历史视频、动作和条件 \(C_n\) → 视频生成器逐窗生成视频帧 → 输出当前窗口的初步视频，交给属性替换。
  5. 属性状态替换：输入被控对象的掩码、规则目标属性和当前去噪估计 → 读取局部特征，按目标属性进行校正，并把修正写回采样更新 → 输出修正后的视频窗口，交给感知反馈。
  6. 感知反馈与输出：输入生成帧和规则事件 → 感知模块独立估计对象身份、可见性、属性和动作完成度 → 输出更新后的绑定、局部几何和可观测状态，反馈给后续窗口；最终视频窗口作为系统输出。

Figure 2：WorldRuler 概览。规则执行更新持久对象状态，动态绑定将规则实体与 3D 实例及其当前图像区域关联，局部属性替换修正去噪估计以用于下一次采样更新。规则、状态、执行进度和绑定被联合保存与恢复。独立的感知反馈为后续窗口提供信息。场景与点云图像来自演示可视化，其余流程和门状态比较用于说明该机制。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Problem Formulation and Overview（问题形式化与概览）

本小节定义生成目标：给定初始观测 \(I_0\)、规则 \(\mathcal{R}\) 和动作序列，生成遵循规则的视频。系统维护可执行 3D 规则图 \(\mathcal{G}_t\)、执行状态 \(X_t\)（对象属性与规则进度）和绑定 \(\mathcal{B}_t\)（规则实体与 3D 对象/视觉实例的对应）。生成按窗口进行，第 \(n\) 个窗口先用执行器根据动作 \(U_n\) 产生对象状态 \(\mathcal{S}_n\)，再与图和绑定共同构成条件 \(C_n=\operatorname{Condition}(\mathcal{G}_n,\mathcal{B}_n,\mathcal{S}_n)\)，送入生成器： \[ \widehat{V}_n \sim p_{\theta,\phi}(V_n\mid I_0,H_n,U_n,C_n). \] 该小节建立了“规则执行→条件构造→视频生成→感知反馈”的总体结构，后续小节分别展开规则图、绑定、属性替换和训练。

3.2 Executable 3D Rule Graph and Persistence（可执行 3D 规则图与持久化）

规则图用对象节点、规则节点和类型化边组织对象身份、空间信息与交互逻辑。对象节点携带持久身份、语义描述、3D 支持和属性状态；规则节点包含触发器、状态前置条件和效果赋值；边区分动作主体、动作目标、前置对象和效果目标，因此效果可以发生在触发器之外。执行状态 \(X_t=(S_t,q_t)\) 包含对象属性和事件历史、规则激活记录、过渡进度与待处理效果，按 \[ X_{t+1}=\operatorname{Execute}_{\mathcal{R}}(X_t,u_t,e_t) \] 演化。未知属性保持显式未知，不能通过否定满足前置条件；有持续时间的变化记录当前值、目标和进度，避免“半开的门”提前满足开门条件；不可见对象上的效果保留在状态中。检查点 \[ \mathcal{C}_t=\operatorname{Save}(\mathcal{G}_t,X_t,\mathcal{B}_t),\quad \operatorname{Load}(\mathcal{C}_t)=(\mathcal{G}_t,X_t,\mathcal{B}_t) \] 联合序列化图、执行状态和绑定，从而恢复规则定义、对象身份和执行进度。该模块为 3.3 提供持久状态，为 3.4 提供规则目标。

3.3 Dynamic Object Binding and Perceptual Feedback（动态对象绑定与感知反馈）

本小节解决“规则说的对象在画面哪里”的问题。绑定先确定规则指向哪个场景实例，再确定该实例在当前视图中的可控制区域。语义、外观和空间一致性用于关联候选实例；相机投影和实例分割给出时空掩码 \(M_i\)，并受可见性和遮挡限制。同类对象保持不同身份，视角变化、遮挡和重新出现时绑定尽量保持。若规则在对象不可见时已改变其状态，则存储状态会在该对象首次出现的窗口中作为条件，使其从第一次出现就呈现规则结果。感知模块独立估计身份、可见性、视觉属性和动作完成度，不接收规则期望作为答案提示；通过校验的证据更新绑定、局部几何和可观测状态，并供给需要视觉确认的后续规则。规则规定状态与观察结果分开记录：若门被要求打开但画面仍显示关闭，规定状态保留，差异用于后续窗口修正。该模块为 3.4 提供编辑支持区域。

3.4 Object Attribute State Replacement（对象属性状态替换）

对象绑定确定编辑位置后，本小节在去噪过程中把对象属性调整到规则目标。设 \(z_\sigma\) 为噪声水平 \(\sigma\) 下的视频潜变量，生成器预测速度 \(v_\theta\)，清洁估计为 \[ \widehat{z}_0=z_\sigma+\sigma v_\theta(z_\sigma,\sigma,C_n). \] 对对象掩码做池化得到局部特征 \(a_i=\operatorname{Pool}_{M_i}(\widehat{z}_0)\)，冻结的仿射读取器估计当前属性 \(\widehat{s}_i=A_i a_i+b_i\)，规则执行给出目标 \(s_i^\star\)，差异为 \(\delta_i=s_i^\star-\widehat{s}_i\)。替换算子 \[ a_i'=T_\phi(a_i,s_i^\star)=a_i+B_i\delta_i+\gamma(\delta_i)Q_i f_\phi(a_i,h_i,\widehat{s}_i,s_i^\star,\sigma) \] 其中 \(B_i=A_i^\top(A_iA_i^\top)^{-1}\) 把属性差异映射回特征空间，\(Q_i=I-B_iA_i\) 把额外调整限制在读取器零空间。由于 \(A_iB_i=I\)、\(A_iQ_i=0\)，替换后满足 \(A_i a_i'+b_i=s_i^\star\)。差异为零时两项修正均消失，保留已满足目标的特征；多个属性联合求解以避免顺序写入冲突。修正后的局部特征按 \[ \widehat{z}_0'=\widehat{z}_0+\sum_i\operatorname{Scatter}_{M_i}(a_i'-a_i),\quad v_\theta'=v_\theta+\frac{\widehat{z}_0'-\widehat{z}_0}{\sigma} \] 写回采样更新。写入排除固定历史边界、不可见区域和未授权属性。该模块依赖 3.3 的掩码，并为 3.5 提供可训练的替换算子。

Figure 3：局部属性替换与配对训练。(a) 冻结的读取器估计当前属性，规则目标确定其差异。属性校正和兼容调整在插入采样更新之前修改局部特征。(b) 反事实重建监督两个目标状态及其与共享生成特征的差异。双向交换从真实配对特征开始，并监督用另一状态进行替换。所有分支共享替换算子 T_φ。虚线链接表示监督。

3.5 Counterfactual Reconstruction and Attribute Swapping（反事实重建与属性交换）

本小节训练 3.4 的替换算子，使其产生的属性变化视觉连贯且不干扰无关内容。训练使用按场景、动作上下文和规则事件对齐的视频对 \((V^{(0)},V^{(1)})\)，两支共享场景、相机和动作上下文，仅规则指定属性状态不同。编码后得到局部目标 \(a^{(k)}\) 和属性 \(s^{(k)}\)，未知、不可见和填充样本被排除。先拟合正则化仿射读取器并检查属性可辨识性，然后冻结读取器、视频生成器和视觉编码器，只优化写入器参数 \(\phi\)。

反事实重建从去噪轨迹取局部估计 \(\bar{a}_\sigma\)，分别用目标 \(s^{(0)}\) 和 \(s^{(1)}\) 经过共享替换算子： \[ \widetilde{a}^{(k)}=T_\phi(\bar{a}_\sigma,s^{(k)}), \] 并用重建损失和差异损失 \[ \mathcal{L}_{\mathrm{rec}}=\mathbb{E}\left[\frac12\sum_{k\in\{0,1\}}\|\widetilde{a}^{(k)}-a^{(k)}\|_2^2\right],\quad \mathcal{L}_{\mathrm{diff}}=\mathbb{E}\left[\|(\widetilde{a}^{(1)}-\widetilde{a}^{(0)})-(a^{(1)}-a^{(0)})\|_2^2\right] \] 监督每个状态的视觉实现和状态间差异。双向属性交换从一支真实局部表示出发，写入另一支属性并重建对应目标： \[ \mathcal{L}_{\mathrm{swap}}=\mathbb{E}\left[\frac12\sum_{k\in\{0,1\}}\|T_\phi(a^{(k)},s^{(1-k)})-a^{(1-k)}\|_2^2\right]. \] 总目标为 \[ \mathcal{L}=\mathcal{L}_{\mathrm{rec}}+\lambda_{\mathrm{diff}}\mathcal{L}_{\mathrm{diff}}+\lambda_{\mathrm{swap}}\mathcal{L}_{\mathrm{swap}}. \] 重建学习每个状态的样子，差异监督约束规则诱发的视觉变化，交换目标借助配对中无关内容的一致性同时监督属性改变和局部内容保持。

6. 局限性和展望（约300字）

论文明确说明的限制包括：实验主要在 RuleVerse 和 WorldState-Bench 上进行，规则复杂度和场景多样性仍受数据集约束；RuleVerse 由 GTA-V 和 Habitat 自动采集，GTA-V 的屏幕录制与引擎日志之间存在同步不确定性；在 WorldState-Bench 上，WorldRuler 相对 SWM 的提升较有限（PairFollow 与 PairStrict 各高 2 个百分点），论文也将其描述为“competitive performance”而非全面领先。

可以谨慎推断的限制有：规则图需要预先定义对象、属性和规则结构，对任意开放自然语言规则的自动形式化能力有限；感知反馈若估计错误，可能通过绑定和状态更新传播到后续窗口；首次出现控制依赖空间落地，对象长期不可见或定位不可靠时效果会受影响；多模块闭环带来较高推理成本。未来可探索更开放的规则表达、真实场景泛化、更长时程的一致生成，以及更鲁棒的感知与绑定机制。
