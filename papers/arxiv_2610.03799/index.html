StepCAD: Mesh-to-CAD Code Generation via LLM Policy and Geometry-Guided Search

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 从3D网格重建CAD程序代码

领域标签： CAD重建 / 生成式优化 / 几何引导搜索

快速理解

背景与任务： 从3D网格恢复可执行CAD程序因建模组合性和参数交互而困难。

核心工作： 作者提出结合策略预测与IoU引导树搜索的StepCAD，并构建ARCADE-1.5M数据集。

中文摘要

从3D网格恢复可执行的CAD程序具有挑战性，因为CAD构建具有组合性，且离散建模选择与连续参数之间存在交互。许多基于学习的方法单次预测完整程序，并主要依赖草图-拉伸表示，限制了操作多样性以及在重建过程中纠正几何误差的机会。我们提出StepCAD，一种生成优化方法，结合了状态条件CAD策略与几何引导搜索。给定输入网格，策略根据目标几何和中间几何预测构造动作，并通过IoU引导的树搜索对结果程序进行局部编辑以细化。我们还引入ARCADE-1.5M，一个包含150万个可执行CAD程序的大规模数据集，涵盖多样操作、最大长度超过150个计数操作的程序序列，以及1250万个中间状态-动作转移。在多个CAD重建基准上的实验表明，StepCAD实现了最先进的几何重建精度和一致的高有效性，相较于最强评估基线，相对IoU提升高达87.2%，在复杂形状上尤其提升显著。项目页面：https://ghadinehme.com/stepcad.github.io/

详细分析

1. 任务输入、输出、功能和边界（约100字）

任务输入是任意 3D 网格（可来自扫描、拓扑优化或生成式 3D 模型），输出是一段可执行、可编辑的 CadQuery 参数化 CAD 程序，其执行后的实体几何与输入网格高度重合。功能是几何驱动的逆向工程：从无结构曲面恢复紧凑、忠实的构造序列。评价指标为体积交并比（IoU）、倒角距离（CD）与有效形状率（VSR）。边界：不声称恢复原始设计意图、约束或参数语义，只追求几何复现。

2. 研究动机：要解决的问题与核心 insight（约300字）

CAD 程序是长程、组合、强结构化的构造序列：离散建模选择（选哪种操作、布尔加减）与连续参数（深度、半径、草图尺寸）强耦合，且参数需要高精度估计。现有学习方法大多"单遍"预测完整程序，且主要依赖 sketch-extrude 表示。这带来两个问题：一是操作多样性受限，很多形状难以用纯拉伸表达；二是生成过程中看不到中间几何，误差沿长序列累积却没有任何纠正机会。

核心 insight：mesh-to-CAD 不应被当作一次性序列预测，而应重新表述为"策略驱动的、几何条件的程序合成 + 基于搜索的精化"。这分解为两个互补部件：一个条件于中间几何的学习策略，负责提出结构合理的候选序列、捕捉全局构造结构；一个由几何目标（IoU）引导的显式程序空间搜索，负责通过局部编辑纠正几何偏差。该范式在程序合成中有长期历史（学习模型提出程序、执行环境反馈结果、搜索按正确性标准精化），本文把它适配到 CAD 的独特约束：既要保证可执行性，又要处理连续参数精度。

实现这一范式还需要数据基础。现有数据集几乎只有 sketch-extrude 序列，且缺少中间状态-动作监督，无法训练状态条件策略。因此论文同时引入大规模、操作多样、带稠密轨迹监督的数据集，模型与数据协同解决。

3. 核心贡献（约300字）

论文提出、构建并验证了四件事：

  1. ARCADE-1.5M 数据集：150 万条可执行 CAD 程序，操作覆盖拉伸（extrude）、旋转（revolve）、扫掠（sweep）、放样（loft）、布尔运算、圆角（fillet）、倒角（chamfer）、抽壳（shell）、镜像（mirror）与阵列（pattern）；最长序列超过 150 个计数操作（均值约 40 个计数操作、8.5 个实体操作）；共 1250 万条中间状态-动作转移。通过 94 条启发式策略、工作流约束和双重验证生成，为状态条件策略提供稠密轨迹监督。
  2. 状态条件 CAD 策略 Π-StepCAD：以目标点云与当前中间几何点云为条件的自回归策略（Qwen2.5-Coder-1.5B 基座 + 共享 Point-MAE 几何编码器），在每一步执行后重新条件化，实现闭环生成。
  3. 几何感知程序优化：将重建表述为程序空间中的优化，用 IoU 引导的束搜索在四种局部编辑（连续参数精化、草图替换、补集切除、操作跳过）中精化候选程序。
  4. 验证：在 CADBench 五个子集上取得 SOTA，ABC Hard 上相对最强基线提升 87.2% IoU，形状越复杂增益越大；还验证了设计变体生成、image-to-CAD 集成与一对多程序分布等下游应用。

4. 推理阶段整体流程与基模（约400字）

在实际使用时，基模是 Qwen2.5-Coder-1.5B 语言模型，扮演"状态条件 CAD 策略"：它根据目标几何与当前中间几何的编码，逐动作地生成 CadQuery 构造代码。辅助模块包括点云编码器（Point-MAE）、CadQuery 执行器和 IoU 引导的树搜索。整个推理流程如下：

  1. 输入：用户提供的目标网格 m → 模块：从网格表面采样点云 Qm，并由点云编码器转换为几何条件向量 → 输出：目标几何编码，交给策略作为全局条件。
  2. 输入：目标几何编码与当前中间几何编码（初始为空状态 S₀） → 模块：LLM 策略自回归地生成下一个构造动作的 CadQuery 代码（例如"新建草图、画圆、拉伸、与主体并集"） → 输出：一段可执行代码，交给执行器。
  3. 输入：新生成的代码与已有程序前缀 → 模块：CadQuery 执行器执行代码，得到新的中间实体 St；若执行失败则丢弃该候选 → 输出：中间实体几何。
  4. 输入：中间实体 St → 模块：从 St 表面采样点云并编码，与目标几何编码合并为下一步的条件；同时检查终止条件（策略发出结束符、IoU 进入平台期或达到 12 个动作上限） → 输出：若不终止，把更新后的条件反馈给策略重复步骤 2–4；若终止，输出种子程序 p̂。
  5. 输入：种子程序 p̂ 与目标网格 m → 模块：几何感知树搜索对当前束中的每个候选施加四种局部编辑，逐一执行并按 IoU 排序，保留排名靠前的候选进入下一步 → 输出：束中 IoU 最高的精化程序。
  6. 输入：精化后的程序 → 模块：交付可执行的 CadQuery 代码与 STEP 几何 → 输出：供用户直接编辑、再执行或下游使用的最终 CAD 程序。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Problem Statement（问题陈述）

目的：给出 mesh-to-CAD 的数学形式化。设 \( \mathcal{M} \) 为网格空间、\( \mathcal{P} \) 为合法 CAD 程序空间；程序 \( p = (a_1,\dots,a_T) \in \mathcal{P} \) 是构造动作的有序序列，执行后产生几何 \( S(p) \)。给定输入网格 \( m \)，目标是求 \( \hat{p} = \arg\max_{p \in \mathcal{P}} \text{IoU}(S(p), m) \)。难点来自 \( \mathcal{P} \) 的组合结构、长程自回归依赖，以及"同一形状对应多个合法程序"的一对多性质。程序统一用 CadQuery 代码表示，为后续策略生成与搜索精化提供同一个可执行目标。

3.2 ARCADE-1.5M: Constraint-Guided Synthetic CAD Programs（约束引导的合成 CAD 程序）

目的：提供操作多样、长程、可执行且带稠密轨迹监督的训练数据。机制分四层：

  1. 约束引导图元生成：从 ABC 数据集提取 2D 草图环（线、弧、圆、样条），随机扰动、旋转、缩放后放到目标包围盒的随机面上；用随机的 extrude/revolve/loft/sweep 参数将其转为实体，并以一定概率施加 fillet/chamfer。
  2. 工作流启发组合约束：每个中间状态必须是体积为正的有效单实体（single-body solid）；加法操作需与主体受控重叠，减法操作需有足够体积交集，避免退化几何。
  3. 策略化层次构造：94 条启发式策略约束操作类型与大致序列长度，模拟加法构造、切削加工、抽壳、镜像、放样、扫掠与收尾特征等常见建模模式，生成 3 至 150+ 个计数操作（均值 40.3）。论文严格区分"计数操作""实体操作""策略动作"与"API 调用"：策略动作定义在几何更新边界上（实体操作 + 布尔组合 + 草图原语），保证下一步可基于新实体条件化。
  4. 验证与归一化：内存 CadQuery 实体校验 + 干净命名空间重执行的双重验证；形状归一化到 \([-1,1]^3\)，浮点字面量保留三位小数。

数据规模与操作覆盖（如 sweep 出现在 25.37% 程序中，平均 86 个面，1250 万中间状态）是它对已有数据集的主要增量。

3.3 StepCAD: Generative Optimization for Mesh-to-CAD Reconstruction（网格到 CAD 的生成式优化）

总体思想是两阶段：策略先产生结构合理的可执行程序，再由几何感知搜索精化，二者共享 IoU 目标。

3.3.1 Π-StepCAD: State-Conditioned CAD Policy（状态条件 CAD 策略）

  • 顺序生成：学习自回归策略 \( \pi_\theta(a_t \mid Q_{t-1}, Q_m, a_{<t}) \)，其中 \( Q_m \) 是目标网格点云，\( Q_{t-1} \) 是当前中间几何点云，\( a_{<t} \) 是已生成动作；整段程序的概率分解为各步条件概率之积。
  • 几何条件化：目标与中间几何用共享 Point-MAE 编码器 \( z_m = f_\phi(Q_m), z_{t-1} = f_\phi(Q_{t-1}) \)，作为条件 token 注入语言模型。
  • 策略架构：以 Qwen2.5-Coder-1.5B 为基座，直接在 token 空间预测可执行的构造动作。
  • 训练：用 ARCADE-1.5M 的稠密状态-动作轨迹做 teacher forcing，损失为负对数似然 \( L(\theta) = -\mathbb{E}[\log \pi_\theta(a_t \mid Q_{t-1}, Q_m, a_{<t})] \)；对每个中间构造步都施加监督，提升长程稳定性。
  • 闭环推理：从空状态开始，交替"预测动作→执行→采样新中间几何→重新条件化"，直到 IoU 平台期、结束符或 \( T_{\max}=12 \) 个动作上限，输出种子程序 \( \hat{p} \)。该模块是连接到搜索阶段的前端。

3.3.2 Geometry-Aware Program Optimization（几何感知的程序优化）

  • 目标：在种子程序局部邻域内最大化几何保真度：\( p^* = \arg\max_{p \in \mathcal{N}(\hat{p})} \text{IoU}(S(p), m) \)。
  • 搜索机制：直接在全部编辑组合上优化是指数复杂度，因此按执行顺序做几何感知束搜索：第 t 步对束中每个候选施加局部编辑、执行、按 IoU 排名，保留 Top-K；束宽 K=2、每步 4 种编辑，扩展数随程序长度 T 线性增长，而非指数增长。
  • 四种局部编辑：① 连续参数精化——用贝叶斯优化调整深度、半径、草图尺寸等连续参数；② 草图修改——用输入网格在该平面切片得到的几何替换原操作草图；③ 补集切除——自动生成草图化 cut-extrude，切除生成几何超出目标形状的部分；④ 操作跳过——删除冗余或有害操作。
  • 输出：束末 IoU 最高的程序 \( p^* \)。该阶段只以种子程序为输入，与策略解耦，实现细节见论文附录 I、J。

6. 局限性和展望（约300字）

论文明确说明的限制：

  • 计算与搜索：精化约 1 分钟/样本；固定局部编辑集合、有界参数邻域和有限束宽可能漏掉有效修正，也无法从很差的种子程序中恢复。
  • 长度上限：\( T_{\max}=12 \) 的动作上限限制了推理时容量；单个动作虽可包含多个计数操作，但训练中超过该上限的长序列不能等价地转化为推理能力。
  • 几何 vs 语义保真度：IoU/CD 衡量形状一致，不衡量原始尺寸、设计意图、约束或特征语义的恢复；例如删除一个参数不当的圆角可能因未找到更好半径而提高 IoU。
  • 选择与可编辑性：粗粒度选择器无法寻址任意独立实体；程序可执行、参数可编辑，但未建立约束保持或用户编辑成功性；紧凑性只是可编辑性的一方面。
  • 数据与泛化：合成训练数据与实际扫描/生成网格之间存在分布差异；替代性合法构造史使与参考 B-rep 的逐参数比较复杂化。

可谨慎推断的限制：四种局部编辑覆盖面有限，若目标形状对应超出训练分布的新操作组合，精化阶段可能退化为参数微调；搜索成本随程序长度与束宽线性增长，超长程序会显著放大耗时；"几何一致但构造史不同"的合法程序会被指标视为成功，因此高 IoU 不等同于语义正确的重建。

展望：论文提出未来工作应结合对齐的点云/B-rep 表征、实体级算子、特征感知目标、约束建模与用户研究，并提升搜索效率。社会影响方面，重建技术可能便利专有设计复制，需要归属标注与人工监督。
