CADMAGEDDON: High-Fidelity CAD Reconstruction with Local Inference

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 从网格重建可编辑CAD的本地推理智能体

领域标签： 计算机辅助设计 / CAD重建 / 本地智能体

快速理解

背景与任务： CAD从业者常处理不愿上传外部服务的专有零件，且本地部署受算力限制。

核心工作： 作者提出开源智能体CADMAGEDDON，将复杂重建分解为视觉决策并借助几何工具，在单GPU本地实现高保真可编辑CAD重建并集成FreeCAD。

中文摘要

CAD 从业者经常处理专有零件，他们不愿将这些零件与外部服务共享。对于个人和小公司而言，在内部完成这项工作也需要他们负担得起的计算资源。我们推出 CADMAGEDDON，这是一个开源智能体，可从网格重建可编辑 CAD，并能在单 GPU 系统和当代笔记本电脑上本地运行。该方法将这一复杂任务分解为一系列简单的视觉决策，即构建什么和修正什么。几何工具支持精确构建，使该智能体能够专注于视觉推理。使用中等规模的 Qwen3.8-27B 模型，CADMAGEDDON 在所有主要基准上的重建质量均优于先前方法，包括基于前沿模型的系统。CADMAGEDDON 与 FreeCAD 集成，将其重建结果带入从业者现有的 CAD 工作流。代码：https://github.com/kulibinai/cadmageddon

详细分析

1. 任务输入、输出、功能和边界（约100字）

输入是单个机械零件的三角网格；输出是可执行的 CadQuery 程序，也可输出原生 FreeCAD 程序，从而得到可编辑的特征化 CAD 实体。功能是把缺少特征树的 mesh 自动反求为可重建、可编辑的 CAD。边界是面向干净的单零件网格，可修复裂缝、重复面等网格缺陷，但不处理扫描噪声、缺失区域、装配体和真实扫描，且受检测工具能命名的几何限制。

2. 研究动机：要解决的问题与核心 insight（约300字）

工程中大量零件只以 mesh 形式存在，例如旧系统导出或供应商剥离特征树后的文件。mesh 只由三角面片组成，缺少草图、拉伸、旋转、孔等特征级结构和设计意图，因此难以参数化重设计；几何精度也受离散化限制。今天把 mesh 反求成可编辑 CAD 主要靠人工。自动方法需要同时做到：准确重建真实机械零件，以及在没有集群、没有外部 API 的单机上本地运行，因为零件常是专有资产，拥有者不愿上传。

现有单遍学习模型能把点云或图像翻译成 CAD 代码并在本地运行，但在真实机械零件上精度明显下降；分步生成能缓解却不能消除。原因包括程序数值被量化或取整、输入编码精度有限、语言模型直接预测数值不可靠。直接几何拟合能精确恢复参数，却可能误读操作分解和设计意图，论文报告约四分之一零件无有效重建。前沿 LLM 在沙箱中写代码的结果多为自报、输入是图像而非 mesh、子集不同且只能远程服务。

核心 insight 是把每个特征拆成两半：结构由视觉语言模型根据目标 mesh 上被命名的几何实体来决定，数值参数由几何拟合提供。这样把复杂重建变成一连串“构建什么、修正什么”的简单视觉决策，用几何工具保证精确构建，模型只做视觉推理；因此不需要前沿规模，也不需要专门的重建模型。

3. 核心贡献（约300字）

论文提出并构建了 CADMAGEDDON：一个开源的 mesh-to-CAD 智能体，把重建组织为对命名几何实体的一连串视觉决策。算法工具在目标 mesh 上检测这些实体并提供拟合参数；单个中型开放权重模型 Qwen3.8-27B 负责按名称组合每个特征、决定下一步构建或修正，不依赖专门的重建模型。系统可在本地单 GPU 环境运行，FP8 权重可放入单张 48 GB GPU；输出既可是 CadQuery 程序，也可是原生 FreeCAD 程序，因此能进入 FreeCAD 工作流。

论文验证了该方法在 DeepCAD、Fusion 360、MCB、BenchCAD、CADENA-Bench 五个主要基准上取得最高 IoU、最高 GMS 和最低 Chamfer 距离；在机械零件上 GMS 提升尤其明显，例如 MCB 从 CADFather 的 0.705 升到 0.818，CADENA-Bench 从 0.800 升到 0.909。BenchCAD 上以相同 64³ 体素 IoU 计分时达到 0.991，高于表中前沿模型自报条目，但论文明确说明输入模态和评测子集不同。BenchCAD-2 上 CadQuery 版本部分得分为 0.933，FreeCAD 版本为 0.925，说明原生 FreeCAD 输出可行。定性上，图 2 显示齿轮、链轮、锥齿轮、叶轮等零件上，基线常合并或漏掉齿和叶片，而本方法能恢复；穿孔带和梯状零件上基线会填充或简化开口，本方法把开口作为单独特征重建。

4. 推理阶段整体流程与基模（约400字）

推理时使用现成开放权重模型 Qwen3.8-27B（FP8，经 vLLM 以 OpenAI 兼容接口服务，温度 0.2）作为视觉语言决策器。它的角色不是一次性写出完整程序，而是每回合发出一个命令，主要按名称选择平面、层位、轮廓基元和操作，或根据残差决定修正；具体数值由几何工具拟合得到。

  1. 网格预处理：输入用户给的单个零件三角网格 → 预处理模块修复重复顶点、退化面、法线不一致和 T 型裂缝，把主导平面法线对齐坐标轴并缩放极小件 → 输出统一坐标系下的网格和可映射回输入坐标系的变换记录，交给几何分析。
  2. 几何检查与命名：输入统一网格和当前重建状态 → 几何工具按需运行 overview、survey、spectrum、section、faces、symmetry、residual 等，检测并命名层位、截面环/线/弧、解析面、同轴孔栈、螺旋、扫掠路径、阵列、对称面及缺失/多余体，并渲染目标与当前结果 → 输出短文本报告和必要图像，交给视觉语言模型。
  3. 结构决策：输入报告、图像、命令历史和当前残差 → 视觉语言模型每回合只选择一个命令，决定下一特征是拉伸、旋转、放样、扫掠、孔、混合还是修正，并主要用名称指定平面、层位、轮廓和操作 → 输出一条结构化命令给构建器。
  4. 精确构建与验证：输入命令及命名实体 → 构建器把名称解析为对目标网格拟合出的数值，生成并执行 CadQuery 或 FreeCAD 程序，检查几何有效性，计算缺失和多余体积残差，保存候选版本 → 输出新重建状态、残差文本和渲染反馈给视觉语言模型。
  5. 反馈修正与完成判断：输入残差、progress 视图、工具报告和剩余调用预算 → 视觉语言模型决定新增特征、撤销/丢弃/镜像/阵列修正，或声明 DONE；驱动程序按规则要求继续检查明显不匹配区域，并在预算或重试限制内收束 → 输出若干已保存候选版本。
  6. 版本选择与导出：输入候选版本和输入网格 → 驱动程序只按缺失加多余体积最小选择已保存版本，不读取真值，导出最终可执行程序 → 输出可编辑的 CadQuery 程序，或原生 FreeCAD 程序，供用户在其 CAD 工作流中打开和修改。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Preprocessing（预处理）

目的是把输入 mesh 变成后续工具和构建器都能共用的标准坐标与干净几何。具体机制包括：合并重复顶点，删除退化面和重复面，统一法线方向，闭合 T 型裂缝；把主导平面面的法线对齐到坐标轴；对非常小的零件重新缩放。输出程序会记录旋转和缩放，使导出的几何能映射回输入坐标系。该步骤为 3.2 的命名实体和 3.3 的几何工具提供统一坐标基准，3.4 中使用的坐标平面也依赖这一步的对齐。

3.2 Named geometric entities（命名几何实体）

目的是让视觉语言模型用短名称指代目标 mesh 上的几何，而不是直接生成坐标或数值。名称由实体类型前缀字母、索引、可选子索引和限定符组成。命名实体包括：沿某平面法向截面发生变化的层位，如零件端、边界、锥度端和转折点（E、B、K、T）；恒定截面平台（c）；拟合截面的闭合环及其顶点、线和弧（R、N、L、A）；mesh 的解析面，如平面、圆柱、锥、球、环面和回转面（F）；同轴孔栈（C）、螺旋（H）和扫掠路径（W）；检测到的阵列（P）和对称候选（S）；当前残差的缺失体和多余体（D、E）以及截面上的对应区域（M、X）。E 同时可表示零件端层位和多余体，具体含义由所在命令消歧。

名称的值来自拟合：截面折线在角点处切开，再递归分解为线和弧，容差由 mesh 离散程度估计；等半径圆被分组为螺栓圆或线阵列；相邻切片出现截面阶跃时用二分法细化位置；解析面从平面片生长并拟合到 mesh 顶点，容差同样由 mesh 导出。当前截面上下文中解析名称；若模型需要的位置没有现成名称，可用已有名称组合，例如两顶点或两层的中点。该小节承接 3.1 的对齐网格，产出的名称由 3.3 工具暴露给模型，并由 3.4 构建器解析为拟合参数。

3.3 Instruments（工具/仪器）

目的是让模型按需检查目标、获取命名实体、尺寸、视图和残差。每个工具打印短文本报告，必要时渲染图像给模型。overview 渲染四个等轴视图和六个正交视图，报告尺寸、体积、体数、螺旋、回转轴、近恒定截面的轴向跨度，并给出启发式构造类型（螺旋、回转、棱柱、阵列或自由曲面），该类型只是证据，不限制模型选择。survey 按沿三个主平面法向的棱柱性打分。spectrum 报告沿选定法向的近恒定截面区间和过渡。ortho 在四个正交侧视图上标出命名层位。section 提取轮廓并分解为命名环、线和弧；轮廓通常是命名层位处的平面切，也可以是命名面的外轮廓、投影、回转体子午线或拟合规律，并汇总相邻层位间的截面积、环数和孔数。faces 列出解析面和孔栈，symmetry 检测镜面和旋转对称，residual 把目标与当前重建的差异拆成命名缺失体和多余体。

模型通过命令行界面选择工具，可随重建推进重访工具。工具输出进入 3.5 的智能体循环，供模型在 3.4 中决定构建或修正。该设计使模型主要做“选名称和选操作”的视觉决策，而精确测量由工具完成。

3.4 Construction and correction（构建与修正）

目的是每次只添加一个特征，并允许根据反馈修正。单个 sketch 命令中，模型指定平面、层位、构成轮廓的基元、操作，以及可选的结束层位。支持的操作包括拉伸（可带锥度或对称）、旋转、多个层位之间的放样（含扭转放样）、沿螺旋或检测路径的扫掠、沿检测孔栈打孔以及混合。构建器把名称解析为拟合值，生成对应 CadQuery 代码，并把新特征与当前实体做并、差、交，或保留为独立体；模型也可请求与斜面或轴对齐的工作坐标系，构建后再映射回零件坐标系。

构建器执行候选程序，检查几何有效性，并测量缺失和多余材料，即残差。体积差小时还检查局部表面偏差；小于目标体积 0.01% 的残差碎片不计入缺失和多余总量，干净残差还要求这些碎片总量不超过目标体积的 0.2%。若任一 mesh 不闭合，则用占据度量替代布尔度量。模型通过 progress 查看目标与重建在同视角下按距离着色的渲染，或把重建与目标做截面比较。特征可被丢弃、撤销、镜像或阵列化，因此下一决策既可能是构建新特征，也可能是修正已有特征。该小节使用 3.2 的名称和 3.3 的工具反馈，并把新状态交回 3.5 的循环。

3.5 Agent loop（智能体循环）

目的是把模型、工具和构建器串成受控的多轮重建过程。系统提示包含重建指南和命令/选项参考；模型最初看不到零件视图。驱动程序每回合最多执行一个命令，并把文本输出和渲染返回给模型。为控制上下文，较早的推理会被截断，旧命令输出被摘要替代，只保留有限数量的近期渲染；模型可用 recall 重新完整打印早期输出。没有命令的回合不计入调用预算；因 token 上限被截断的回复会用更大上限重试，而不是直接算失败。

当模型声明 DONE 时，若不匹配区域至少覆盖目标表面的 1%，驱动程序会要求它对每个已保存版本继续一次；满足该规则后，干净残差才算完成。若残差非零，驱动程序可在残差不再改善或至多占目标体积 1% 时以不完整重建停止。运行也会在命令预算耗尽，或缺失、失败、重复命令的重试预算耗尽时结束。构建器按请求保存程序版本；驱动程序在合格保存版本中按缺失加多余体积相对输入 mesh 最小来选择，不使用真值模型。该小节把 3.3 的检查工具和 3.4 的构建修正连接成闭环。

3.6 Implementation（实现）

目的是说明实际运行配置。系统使用 Qwen3.8-27B 的 FP8 权重，经 vLLM 以 OpenAI 兼容 API 服务，采样温度 0.2。每个零件默认一次尝试，只有 BenchCAD-2 报告最多五次完成尝试中按分数选择的最佳结果。命令预算随基准变化：DeepCAD 和 BenchCAD 为 30 条命令，Fusion 360、MCB、CADENA-Bench 和 BenchCAD-2 为 60 条。初始输出上限为 15,000 token；若在驱动程序提取命令前达到上限，则丢弃不完整回复并请求最多 30,000 token。一条命令最多附 8 张渲染，对话最多保留 12 张，来自最近 6 个产生图像的命令；命令输出完整保留 4 条命令，之后替换为摘要。报告中的运行使用四块 GPU 张量并行和 250k token 上下文，实际每次调用使用的上下文由驱动程序设置。网格修复如 3.1 所述。该小节为 3.5 的循环提供具体运行限制和上下文管理方式。

6. 局限性和展望（约300字）

论文明确说明的限制如下。第一，系统假设输入是干净的单零件 mesh；预处理只修复裂缝和重复面，不处理扫描噪声或缺失区域，所有基准都来自 CAD 模型，装配体和真实扫描留待未来。第二，工具集限制了可表达的特征：检测器没有命名、或没有操作能产生的特征只能被近似；论文在 BenchCAD-2 上观察到 0.7 mm 薄壁被漏掉，以及一个有 51 个通孔的零件最多只构建了两个。第三，输出的 CadQuery 可编辑，但尺寸是字面数值而非命名参数，圆角和倒角是显式实体而非边操作，恢复设计意图超出当前系统。第四，与前沿模型的比较依赖排行榜条目，输入模态和评测子集不同，系统区分智能体框架、具体前沿模型和输入模态各自贡献的工作留待未来。第五，系统用模型规模换交互：重建最多需要 30 或 60 次模型调用和长上下文，因此比单遍学习模型慢。图 3 的调用预算分析也显示，机械零件集的 GMS 到 60 次调用时仍在上升，说明表面细节依赖后续特征。

Figure 3：按基准，前 n 次模型调用内生成的最佳程序版本的 IoU（左）和 GMS（右）。尚无版本的零件计为 0。最佳版本按所绘指标选择，即使用参考，因此每条曲线是在 n 次调用时停止的运行所能返回结果的上界。图例给出智能体在完整预算（DeepCAD 和 BenchCAD 上 30 次调用，否则 60 次）下自身交付程序的均值；与曲线一样，它将没有程序的零件计为 0，因此可能与主论文表 1 略有不同。

可谨慎推断的限制是：对复杂自由曲面、薄壁、密集孔阵列和多体装配，当前检测器和操作库可能仍是瓶颈，需要扩展命名实体与构建操作；本地部署降低了隐私和外部服务依赖，但长上下文多轮交互对单机内存和时延有压力，需要工程优化；输出虽可编辑，但要达到工程级参数化复用，仍需恢复命名尺寸、特征关系和设计意图。
