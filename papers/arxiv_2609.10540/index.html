Programmable World Model

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 可编程世界模型，实现指令驱动的持久状态控制与视频生成

领域标签： 世界模型 / 视频生成 / 可编程交互

快速理解

背景与任务： 现有视频世界模型能生成逼真交互体验，但缺乏持久状态保持和可编程规则机制。

核心工作： 作者提出Programmable World Model框架，用程序解耦状态演化与视觉生成，并通过状态增强3D包围盒桥接到视频模型。

中文摘要

近期视频世界模型生成的视觉体验日益逼真且可交互，但缺乏可靠机制来维护持久的世界状态，并在长时间交互中执行可编程规则。我们提出可编程世界模型（Programmable World Model），一种将世界状态演化与视觉观测生成相解耦的框架。智能体将自然语言指令翻译为可执行程序，这些程序指定实体状态和状态转移规则，从而能够直接控制单个实体及其交互。一个轻量级引擎执行这些程序，以更新和维护显式、持久的全局世界状态，包括屏幕外实体和非视觉属性。为了将世界状态与视觉生成相连接，我们引入状态增强的3D有向包围盒（OBBs）作为中间表示。该表示与目标相机轨迹一起，被确定性地编译为像素对齐的时空条件信号，供作为生成式渲染器的预训练视频模型使用。这一设计允许用户创建具有预定义机制、可对单个实体进行直接控制、并在整个游戏过程中保持持久世界状态的可玩游戏。我们进一步引入CombatStateBench，一个用于评估可编程世界模型的基准。在CombatStateBench上，我们的方法实现了94%的计数准确率和98%的状态准确率，大幅超越现有交互式视频世界模型，同时支持连贯的长时程生成。这些结果证明了将显式状态演化与生成式渲染分离对于构建持久、可编程世界是有效的。

详细分析

1. 任务输入、输出、功能和边界（约100字）

任务输入：单张参考图像、自然语言世界描述，以及交互中的玩家动作/目标相机轨迹。输出：与世界状态保持一致的连续视频观察。功能：将可编程规则和显式实体状态转化为可控视觉生成，支持长期一致、可交互的游戏世界。边界：显式状态为盒式实体几何与属性；精细姿态、材质、关节运动等由生成模型补全，并非完整物理/动画仿真器。

2. 研究动机：要解决的问题与核心 insight（约300字）

现有视频世界模型能生成逼真、可交互的视频，但存在三个关键缺口：控制接口通常只是相机、动作或高层提示，无法直接寻址单个实体；没有显式、持久的全局状态，屏幕外实体和血量、库存等非视觉信息无法被独立存取；用户无法编写持续生效的世界规则，提示只是一次性希望而非可执行规则。因此，作者认为世界状态演化应与观察生成解耦：由一个轻量引擎维护“真实发生了什么”，由视频生成模型负责“看起来像什么”。

选择中间表示时，文本、2D框、掩码缺乏世界坐标下可重投影的结构；完整3D场景、G-buffer等虽控制精细，但标注和推理时构造/演化成本高，且训练时从已实现动态中提取的表示，与推理时从高层状态转移构造的表示可能存在不一致。状态增强3D OBB只需位置、尺寸、朝向和少量状态变量，紧凑且能随相机重投影；它把精细几何、关节运动、材质光照等交给生成先验完成，从而避免过度约束，也降低了训练—推理差异。图2示意了这种权衡。

图2：状态表示的权衡。候选表示范围从轻量级语义描述到详细几何结构（Huang et al., 2026b）。更大的结构细节支持更细粒度的控制，但增加了训练数据标注和推理时状态构建与演化的成本。此外，训练期间从观察中提取或从引擎记录的表示，可能与推理时以编程方式构建的表示不同，从而造成潜在的训练-推理不匹配。我们采用状态增强3D OBB作为中间抽象，支持显式世界空间控制，同时将精细几何、关节和次要视觉动态留给生成式渲染器。

3. 核心贡献（约300字）

论文的核心贡献包括四方面：

  1. Programmable World Model 框架：将世界状态演化与生成渲染解耦。编码智能体把自然语言转为可执行程序，定义实体、属性、关系和规则；引擎维护规范世界状态，支持直接实体控制、持久状态和可编程机制。
  2. 状态增强3D OBB + 确定性状态编译器：OBB支撑世界空间一致性，编译器将状态与目标相机投影为像素对齐的身份、语义和方向控制，使生成器明确知道哪个实例在哪个位置、属于什么类别、自身往哪移动。
  3. 自动数据管线：从无标注视频恢复相机、语义、实例轨迹、3D OBB和运动方向，生成训练所需的结构化控制，提供规模化数据路径。
  4. CombatStateBench 基准与验证：评估可见存活角色数和死亡状态是否被视觉实现。在50个片段上，方法取得94% Count Accuracy和98% State Accuracy，显著优于 LingBot-World-V2 与 YUME；VBench 视频质量指标也全面领先。定性结果展示了死亡事件保持、多实体共存和长时程场景支持能力。

图4：五个生成帧上实体死亡交互的定性比较。我们在(a)静态摄像机和(b)动态摄像机及移动实体条件下，将LingBot-World-v2和YUME与我们的方法进行比较。输入行可视化了提供给我们的渲染器的结构化控制信号。我们的方法遵循指定的死亡事件，同时保留剩余实体和场景演化。

图5：在五个选定时间步上展示的额外定性结果。(a) 对具有动态摄像机和实体运动的新型米诺陶洛斯场景的泛化。(b) 在大角度摄像机旋转下，模型保持场景一致性，并遵循引擎维护的持久世界状态，正确揭示初始摄像机视角后方的角色。(c) 对具有运动摄像机和车辆的赛车游戏的泛化。(d) 异构物体类别的联合渲染，包括行人和车辆。(e) 从897帧自回归序列中选出的帧，其中许多NPC逐步进入场景。输入行在(a)–(b)中可视化全局场景状态，在(c)–(e)中可视化带地面网格参考的摄像机视角3D OBB映射。生成结果始终遵循指定的摄像机运动、空间布局和实体状态。

4. 推理阶段整体流程与基模（约400字）

在实际使用中，推理链路由以下基础模型/模块协作完成：编码智能体把自然语言变成可执行世界程序；轻量级引擎维护和推进规范世界状态；确定性状态编译器把状态投影到目标视角；视频生成模型作为渲染器，根据控制信号合成观察。图1展示了这一整体流程。

图1：可编程世界模型概览。给定单个参考图像和用户描述，编码智能体生成可执行程序，以指定实体状态和交互规则。轻量级引擎执行这些程序，以维护和演化由状态增强3D OBB表示的显式世界状态。该表示被编译为生成式渲染器的条件信号，生成与世界状态一致的真实视觉观察。此设计允许用户通过预先定义游戏机制、直接控制单个实体并在整个游戏过程中维护持久世界状态来创建可玩游戏。

用户与系统的交互过程如下：

  1. 用户输入 单张参考图像 + 自然语言世界描述 → 编码智能体与3D检测器一起工作 → 输出包含实体OBB、属性、关系、规则的初始规范世界状态。
  2. 用户动作/目标相机轨迹 → 轻量级引擎依据已有规则检查动作合法性、应用状态变化、触发事件 → 输出更新后的规范世界状态。
  3. 更新后的规范世界状态 + 目标相机 → 状态编译器将实体OBB投影到目标画面中，生成身份、语义、运动方向等结构化控制信号 → 输出控制序列。
  4. 控制序列 + 目标相机轨迹 + 历史视觉信息 → 视频生成模型作为渲染器合成下一段视频 → 输出视频块。
  5. 视频块 → 系统将其写入时间记忆和空间记忆，作为下一块的视觉上下文；同时该视频反馈给用户，玩家再给出下一步动作，回到第2步。

5. 核心方法：按论文 Method 小节总结（约600字）

图3给出整体架构。下面按原论文 Method 的四个小节展开。

图3：可编程世界模型的架构。(1) 智能体编排的世界编程从自然语言规范开始，实例化可执行的规范世界状态，由轻量级引擎根据玩家行动和世界规则进行维护和推进。(2) 控制编译将目标摄像机下的状态增强3D OBB投影为像素对齐的身份、语义和运动方向控制。(3) 生成式渲染以这些结构化控制和视觉历史为条件，驱动预训练的摄像机控制视频生成模型合成下一视频块。完成的块被纳入时间对齐和几何对齐的空间记忆，以支持长时程生成。

4.1 Problem Formulation（问题定义）

该小节定义交互式生成世界中的形式化循环。世界状态 \(s_t\) 在玩家动作 \(a_t\) 下由引擎 \(F\) 推进到 \(s_{t+1}\)；状态编译器 \(P\) 在目标相机 \(C_{t+1}\) 下把 \(s_{t+1}\) 转为渲染器控制 \(M_{t+1}^{\mathrm{ctrl}}\)；生成渲染器 \(G\) 再合成观察 \(I_{t+1}\)：

\[ s_t \xrightarrow[\;a_t\;]{F} s_{t+1} \xrightarrow[\;C_{t+1}\;]{P} M_{t+1}^{\mathrm{ctrl}} \xrightarrow{\;G\;} I_{t+1}. \]

关键点是规范状态不仅包含实体几何，还包含语义/功能属性、实体间关系和可执行规则，因此世界状态可以被程序直接读写和验证。

4.2 Agent-Orchestrated Box World（智能体编排的盒式世界）

目的：让世界状态可编程、可持久。每个实体由一个3D OBB（位置、尺寸、朝向）加上身份、类别、健康、阵营等属性构成；世界还保存实体间关系和规则。形式化世界状态为：

\[ s_t=(\mathcal{E}_t,\mathcal{A}_t,\mathcal{Q}_t;\mathcal{R}_t), \]

其中 \(\mathcal{E}_t\) 是实体几何，\(\mathcal{A}_t\) 是属性，\(\mathcal{Q}_t\) 是关系，\(\mathcal{R}_t\) 是可执行规则。初始化时，3D检测器从初始帧恢复可见实体OBB和持久ID；编码智能体根据自然语言描述为这些ID编写程序，指定初始属性、动作和规则。引擎执行：

\[ s_{t+1}=F(s_t,a_t), \]

它会检查动作是否合法、应用效果并解析触发事件，同时维护屏幕外和非视觉状态。输出更新后的规范世界状态，交给控制编译。

4.3 Control Compilation（控制编译）

目的：把世界状态变成渲染器可用的像素对齐信号。编译器 \(P\) 只提取可渲染的状态变量，不改变世界状态本身：

\[ M_{t+1}^{\mathrm{ctrl}}=P(s_{t+1},C_{t+1}). \]

它把实体的3D OBB投影到目标相机下，并生成三类空间对齐控制图：

  • 身份图：每个持久实体分配一个固定身份槽位，来自身份嵌入库 \(\mathcal{E}^{\mathrm{id}}=\{q_j^{\mathrm{id}}\}_{j=1}^K\)，并栅格化到该实体可见投影区域。同一序列内身份槽位固定，从而使跨帧、跨遮挡的实例对应关系稳定。
  • 语义图：用预训练文本编码器把语义标签转成嵌入 \(q_i^{\mathrm{sem}}=E_{\mathrm{text}}(y_i)\)，填充到实体投影区域；重叠时按深度保留可见实体。
  • 方向图：把引擎维护的世界坐标速度旋转到相机坐标系，再量化为七类：前、后、左、右、静止、上、下，对应方向嵌入库 \(\mathcal{E}^{\mathrm{dir}}=\{q_\ell^{\mathrm{dir}}\}_{\ell=1}^7\)。它区分“物体自己运动”和“相机运动造成的表观位移”。

最终控制图为：

\[ M_{t+1}^{\mathrm{ctrl}}=\mathrm{Concat}(M_{t+1}^{\mathrm{id}},M_{t+1}^{\mathrm{sem}},M_{t+1}^{\mathrm{dir}}). \]

4.4 Generative Renderer（生成式渲染器）

4.4.1 Conditional Video Generation（条件视频生成）

生成渲染器以视频生成模型为基础，保留原有相机条件模块，并新增加一个结构化空间控制分支。相机轨迹 \(\mathcal{C}=\{C_t\}_{t=1}^T\) 控制全局视角变化；控制分支将 \(M_{1:T}^{\mathrm{ctrl}}\) 编码为逐层控制特征，注入主干网络：

\[ h_{\mathrm{main}}^{(\ell)} \leftarrow h_{\mathrm{main}}^{(\ell)} + r^{(\ell)}. \]

固定窗口渲染可写为：

\[ I_{1:T}=G_{\theta,\phi}(I_0,\mathcal{C},M_{1:T}^{\mathrm{ctrl}}), \]

其中 \(\theta\) 是冻结的基础模型参数，\(\phi\) 是新增空间控制分支参数。控制分支负责实体位置、身份、语义和自身运动；基础生成先验负责形状、纹理、光照、关节和次要动力学。

4.4.2 Chunk-Autoregressive Long-Horizon Rendering（分块自回归长时程渲染）

为了生成更长视频，渲染器按块自回归工作。第一个块从初始观察 \(I_0\) 初始化；后续块额外接收时间历史 \(\mathcal{H}_{\mathrm{temp}}^{(n)}\) 和几何对齐空间记忆 \(\mathcal{H}_{\mathrm{spa}}^{(n)}\)：

\[ I^{(n)}=G_{\theta,\phi,\psi}\left(\mathcal{C}^{(n)},M^{\mathrm{ctrl},(n)},\mathcal{H}_{\mathrm{temp}}^{(n)},\mathcal{H}_{\mathrm{spa}}^{(n)}\right),\quad n\ge 2. \]

时间历史保留已生成块的多尺度潜在表示，最近信息分辨率高，较远信息分辨率低；空间记忆把已完成RGB帧按估计深度和相机参数提升到世界空间，生成新块前检索并重投影到目标视角。两者都只使用当前块之前的观察，保持因果性。

4.5 Automatic Training Data Pipeline（自动训练数据管线）

目的：为上述渲染器提供大规模结构化训练数据。流程包括：

  • 相机参数估计：用 ViPE 估计相机内参、相机位姿和逐帧度量深度。
  • 语义类别发现：用 Qwen3-VL 生成视频全局描述，并发现可数的物体类别；也可替换为预定义词汇表。
  • 实例分割与跟踪：用 SAM3 结合类别提示，产生时间关联的实例掩码、2D框、语义标签和轨道ID。
  • 物体轨迹恢复：用 WildDet3D 对每个可见实例估计逐帧3D OBB：

\[ b_i^t=(\mathbf{p}_i^t,\mathbf{d}_i^t,\mathbf{R}_i^t,\ell_i,k_i). \]

利用相机位姿把这些框变换到共享世界坐标，形成轨迹；再根据世界坐标位移计算物体运动方向，并量化为七类。

  • 控制图生成：把3D OBB投影回每一帧，用 z-buffer 处理遮挡，生成与视频帧像素对齐的身份图、语义图和方向图，作为渲染器的训练监督。

6. 局限性和展望（约300字）

论文没有专设局限性章节，但从设计和实验可看出若干限制。明确而言，框架的可编程性依赖编码智能体正确生成规则和属性；如果自然语言描述含糊，或3D检测、实例跟踪出错，错误会进入规范状态并影响后续生成。实验中的训练视频来自三款游戏（《赛博朋克2077》《极限竞速：地平线6》《GTA V》），虽然定性展示了新场景泛化，但开放域覆盖仍有限。3D OBB只描述实体级几何，不表达身体姿态、关节角度或局部形变；因此需要精确动作控制时，生成器可能自由发挥。状态引擎只执行显式规则，复杂物理（碰撞、重力、流体）如果未被写成规则，就不会被一致模拟。长时程渲染依赖深度估计和相机参数提升视频到空间记忆，这些估计误差可能随自回归过程累积。评测指标 Count/State Accuracy 是全局粗粒度统计，不能完全衡量实例级身份或精确位置一致性。可合理推断：身份槽位数量、七方向运动量化粒度、以及固定窗口长度都会成为扩展时的瓶颈；这些是表示紧凑性换来的代价。未来方向可包括更丰富的状态表示、更强的规则学习，以及更细粒度的实例级评测。
