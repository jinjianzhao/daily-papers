On-Policy Codec Distillation for Efficient All-in-One Video Generation

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 多条件视频生成中的冗余条件令牌剪枝与在线自蒸馏加速。

领域标签： 计算机视觉 / 视频生成 / 扩散模型 / 令牌剪枝 / 在线自蒸馏

快速理解

背景与任务： 多条件一体化视频生成中，条件令牌数量多且冗余，导致去噪计算和缓存开销高。

核心工作： 作者先用视频编解码器思路剪枝冗余条件令牌，再用在线自蒸馏训练DiT适配器，形成CodecOPSD，在几乎不降质下显著减少令牌、加速去噪并降低缓存。

中文摘要

现代视觉生成模型以 token 为基本单元运行；它们接收的每一种视觉资产——无论是身份信息、涂鸦、深度图还是运动视频——都会被 token 化，并追加到输入 token 序列中。因此，条件信息很快在计算成本中占据主导。然而，这些 token 中大多数携带冗余的时空信息。我们的关键洞见是：识别真正新增的信息，正是经典视频编解码器（video codecs）长期以来所解决的问题。于是，我们首先引入一种基于编解码器的 token 剪枝方法，用于丢弃冗余 token。随后，我们提出一种在策略自蒸馏（on-policy self-distillation, OPSD）策略，用于训练一个 DiT 适配器，使其能够很好地学习编解码器剪枝模式，同时不造成质量下降。二者共同构成 On-Policy Codec Distillation（CodecOPSD）。我们在自有的视频扩散模型上将 CodecOPSD 扩展到 16 种条件模态，平均剪枝 66% 的条件 token，而质量几乎不下降。因此，去噪速度提升至 2 倍，并且在 KV cache 模式下，缓存内存最多缩小 73%。CodecOPSD 还可扩展到其他最先进的预训练图像和视频生成模型；在这些模型中，随着条件更多、帧更长和分辨率更高，其收益进一步提升。

详细分析

1. 任务输入、输出、功能和边界（约100字）

输入是用户文本与多种视觉条件（身份图、草图、深度、姿态、轨迹、参考视频等），输出是对应视频；扩展模型也可输出图像、音频或动作。系统功能是用视频 codec 信号剪掉冗余条件 token，再用 on-policy self-distillation（OPSD）适配器让扩散 Transformer（DiT）在少 token 下保持质量。边界：只压缩条件 token，不取代少步采样、FlashAttention、量化、稀疏注意力等；依赖可获得的 codec 信号，不同条件的保守程度不同。

2. 研究动机：要解决的问题与核心 insight（约300字）

现代 all-in-one 视觉生成模型把每个条件资产 token 化并追加到输入序列；条件越多，注意力成本随序列长度二次增长，条件很快主导计算。多数条件 token 在时空上冗余：静态背景每帧重复，运动轨迹只覆盖少量像素。现有加速多在去噪器上做少步采样、FlashAttention、量化、特征缓存或稀疏注意力，而本文从源头减少条件 token，与这些方法正交。核心 insight 是：判断“哪些像素/块是真正新信息”正是经典视频 codec 长期解决的问题。H.264 等 codec 用 I-frame/P-frame 预测每个 block，记录参考块、运动向量（motion vector）和残差（residual）；运动小且残差低的区域可视为可由已有信息推断。于是 codec 信号可把像素级运动与残差映射到 VAE token，成为跨模态的 token 选择规则，并可在 CPU 实时计算。但仅剪枝会造成质量下降；还需要让模型在自己的采样状态上学习从保留 token 复现 teacher 的输出。

3. 核心贡献（约300字）

论文的主要贡献是提出并验证一套面向可控生成的 codec token 剪枝与适配方法。第一，提出面向可控生成的 codec pruning：用视频 codec 的运动向量与残差选择条件 token，把像素块级信号映射到三维变分自编码器（3D VAE）token，形成每个 condition 的保留掩码，直接减少进入 DiT 的条件 token。第二，提出 CodecOPSD：以同一基模作 teacher 和 student，teacher 额外看到被剪掉的 token 作为特权信息，student 只看到保留 token，并在 student 自己的采样轨迹上学习匹配 teacher，从而避免只做监督微调（SFT）时保留 token 与完整条件之间的质量差。第三，在自有 16 种条件模态视频模型上验证平均剪掉 66% 条件 token 仍接近 dense teacher，去噪约 2 倍加速，键值缓存（KV cache）内存最多降 73%。

4. 推理阶段整体流程与基模（约400字）

实际推理时，已就绪的多条件视频扩散 Transformer（DiT）是去噪主干；它接收文本、保留下来的条件 token 和当前 noisy latent，逐步预测并更新 latent。VAE（变分自编码器）、codec 分析模块和可选 VLM 都是围绕它工作的黑箱工具。

  1. 用户文本与多种条件资产（参考图/视频、草图、深度、姿态、轨迹等）→ 预处理模块把它们统一成图像或视频形式并保留文本 → 输出标准化条件资产和文本，交给条件编码与筛选。
  2. 标准化条件资产 → VAE 编码器把每个条件编码成 condition tokens；同时 codec 分析模块读取可用编码信号，判断哪些 token 含新时空信息 → 输出保留 token 名单及保留下来的 condition tokens，交给拼接。
  3. 可选参考图像/视频 → VLM 模块提取 vision tokens，并用同一保留名单筛选 → 输出保留下来的 vision tokens，和保留条件 tokens 一起交给 DiT。
  4. 当前 noisy latent + 文本 + 保留条件 tokens（以及可选保留 vision tokens）→ DiT 执行一步去噪，预测当前 latent 的更新方向 → 输出更新后的 latent 和采样状态，交给采样循环。
  5. 采样循环检查是否达到预设结束条件 → 若未结束，把更新后的 latent 和同一组条件 tokens 送回 DiT 继续下一步；若结束，输出最终 latent。
  6. 最终 latent → VAE 解码器或对应输出头解码 → 输出最终视频（在扩展模型中也可为图像、音频或动作），作为系统结果返回用户。

5. 核心方法：按论文 Method 小节总结（约600字）

3.1 Video Codec Preliminaries（视频编解码器预备知识）

本节目的是说明 H.264 类 codec 如何产生后续可用的运动与残差信号。codec 把帧分为帧内编码帧（I-frame）和预测帧（P-frame）。I-frame 没有时间参考，用同一帧内已编码邻居预测每个 block，因此提供 residual 而没有 motion vector；P-frame 在先前编码帧中做 block matching 找最佳参考，记录运动向量 \(m_t(p)\)，并存储当前 block 与最佳匹配的差 \(r_t(p)\)。这些信号是像素块级的，后续 3.2 要把它们映射到更粗的 VAE token 区域，3.3 再用得到的掩码筛选条件 token。

3.2 Token Pruning from Codec Signals（从 codec 信号进行 token 剪枝）

本节目的是把像素级 codec 信号变成每个 VAE token 的标量分数，并决定保留或丢弃。一个 DiT token \(c_i\) 覆盖一组像素 \(\mathcal P_i\) 和一组帧 \(\mathcal F_i\)。对每个 token 计算运动分数 \(M_i=\max_{t\in\mathcal F_i}\max_{p\in\mathcal P_i}\|m_t(p)\|\) 与残差分数 \(R_i=\max_{t\in\mathcal F_i}\operatorname{mean}_{p\in\mathcal P_i}|r_t(p)|\)。阈值式剪枝令 \(b_i=1\) 当且仅当 \(M_i\ge\tau_m\) 或 \(R_i>\tau_r\)，用于让高相机运动与近静态视频各自找到平衡点；优先级式剪枝构造 \(E_i=\bar R_i(1+\lambda\bar M_i)\)，其中 \(\bar R_i,\bar M_i\) 是归一化分数，按 \(E_i\) 排序并先丢最低者，用于固定预算。该节输出每个 condition 的掩码 \(b^{(j)}\)，交给 3.3 应用。

图 2：从 codec 信号到保留的 tokens。(a) I-frame 根据其已编码邻居预测每个 block。(b) P-frame 在前一帧中为每个 block 找到最佳匹配，并存储其 motion vector。(c) residual 是 block 与其最佳匹配之间的差值。(d) 每个 token 从其所覆盖的 block 获得 motion score 和 residual score，然后通过基于阈值或基于优先级的 pruning 选择保留的 tokens。

3.3 Conditioning with Token Selection（使用 token 选择进行条件化）

本节目的是把多种 condition 以同一接口送入 DiT，但只保留 mask 选中的 token。每个 condition \(j\) 先渲染成图像或视频 \(I^{(j)}\)，由冻结 VAE \(\mathcal E\) 编码成条件 token \(C^{(j)}=\mathcal E(I^{(j)})\)；3.2 的 codec pruning 并行得到 \(b^{(j)}\)。应用掩码得 \(\tilde C^{(j)}=b^{(j)}\odot C^{(j)}\)。DiT 用 flow matching（流匹配）去噪 \(x_\sigma=(1-\sigma)z+\sigma\epsilon\)，输入序列为 \(\mathcal S=[x_\sigma;\tilde C^{(1)};\dots;\tilde C^{(J)}]\)，其中 \(x_\sigma\) 不被剪枝。每个保留 token 保持原三维旋转位置编码（3D RoPE）位置，DiT 架构不需要改动。对带 VLM 的模型，codec pruning 也筛 VLM 输出的 vision tokens，但 ViT 仍读取完整参考，筛选发生在 vision tokens 进入语言模型之前。该节承接 3.2 的掩码，输出去噪 DiT 的拼接输入，并为 3.4 的 student 提供只含保留 token 的输入。

3.4 On-Policy Codec Distillation（在线策略 codec 蒸馏）

本节目的是让 student 在只有保留 token 时仍复现 teacher 的预测。teacher 和 student 共享同一基模 \(v_\theta\)；student 增加可学习低秩适配器（LoRA）\(\phi\)，只作用于 condition token 的投影，不作用于 noisy latent 或 VLM tokens。teacher 冻结，接收与 student 相同类型的条件，但额外看到被剪掉的 token \(C^\star=C\setminus\tilde C\) 作为特权信息；student 只看 \(\tilde C\)。二者预测为 \(v_T(x,\sigma)=v_\theta(x,\sigma;\tilde C\cup C^\star)\) 与 \(v_S(x,\sigma)=v_{\theta,\phi}(x,\sigma;\tilde C)\)。训练时 student 先无梯度地沿推理采样器的 K 个噪声级自行采样：\(x_{k+1}=x_k+(\sigma_{k+1}-\sigma_k)v_S(x_k,\sigma_k)\)，从纯噪声 \(x_1=\epsilon\) 开始；只监督前 N 个高噪声状态 \(\mathcal N\)。每个监督状态上 teacher/student 看同一 \(x_k,\sigma_k\)，最小化 \(\ell_k=\|v_S(x_k,\sigma_k)-v_T(x_k,\sigma_k)\|_2^2\)，总损失为 \(\mathcal L_{\mathrm{OPSD}}(\phi)=\mathbb E_{\mathcal C,\epsilon}\left[\frac{1}{|\mathcal N|}\sum_{k\in\mathcal N}\ell_k\right]\)。损失不使用 ground truth，监督来自 teacher；推理时只运行 student，teacher 不再需要。该节把 3.3 的保留 token 作为 student 输入，把被丢 token 作为 teacher 特权信息，使 3.3 的剪枝输入在推理时保持质量。

图 3：CodecOPSD 的 pipeline。左侧：codec pruning 与 VAE encoder 并行运行，并按每个 condition 的动态比例丢弃 condition tokens，保留的 tokens 与 noisy latent 拼接后作为 DiT 输入。它可选地丢弃 VLM 的 vision tokens，这些 tokens 依模型不同通过 cross-attention 或 joint attention 进入 DiT。右侧：On-Policy Codec Distillation 将 codec pruning 移除的 tokens 作为 privileged information 提供给冻结的 teacher，并将 student 的预测与 teacher 的比较。

6. 局限性和展望（约300字）

论文明确写到的限制包括：在可控生成中，被剪掉 token 的内容仍可能出现在输出里，因此不能像视觉语言理解任务那样激进剪枝，需要更保守的选择；不同 condition 的鲁棒性差异很大，稠密条件可免费丢 26%–71%，稀疏条件可丢 80%–94%，实际预算要按模态调整。

图 5：各 condition 的丢弃率。我们按 Eq. 3 的顺序以不同比例丢弃单个 condition 的 tokens，并在每个目标 metric 上测量相对于 teacher 的质量，分别针对 (a) dense conditions 和 (b) sparse conditions。灰色带是 teacher 的 seed noise（±2σ）。绿色区域表示 free drop，即质量保持在该带内；橙色区域表示 lossy drop。(c) 给出每个 condition 的 free drop 值。

此外，teacher 与 student 可见 token 的信息差要合适，太小或太大都会变差（论文表3）。展望上，论文明确提出把 codec pruning 做到更细粒度，例如按每个保留 token 的 codec residual 减少其通道数。可谨慎推断：方法依赖可取得 codec 信号且能把条件渲染为图像/视频；对无法形成这种信号的抽象条件，适用性未验证；论文主要报告 token 选择时间与去噪时间，端到端系统延迟还受其他模块影响，需在部署中测量；极端剪枝会进入 lossy drop 区间（图5）。
