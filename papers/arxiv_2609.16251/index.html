CADWorld: Computer-Use Benchmark for Long-Horizon Computer-Aided Design

来源： arXiv · HF Paper · AlphaXiv

一句话主题： 面向计算机辅助设计的GUI代理长时程操作基准测试

领域标签： 人工智能 / 计算机使用代理 / 机械CAD基准

快速理解

背景与任务： 现有计算机使用基准缺乏对专业工程工作流及持久化结构产物的评估。

核心工作： 作者构建了含200个FreeCAD任务的CADWorld基准，并评测发现最强代理成功率远低于专家。

中文摘要

计算机使用智能体越来越多地在逼真的桌面环境中进行评估，但现有基准对专业工程工作流的覆盖有限，而这些工作流的输出是持久、结构化的工件。机械计算机辅助设计（CAD）是一个尤其严苛的场景：智能体必须在长交互周期内操作几何和约束，同时生成尺寸、构造结构和下游工程状态均保持有效的原生项目。我们引入了 CADWorld，一个面向 FreeCAD 中长时程计算机使用的基准。CADWorld 包含 200 个任务，涵盖 11 类机械 CAD 工作流，包括草图绘制、零件建模、装配、CAM、FEM、测量、网格处理和技术图纸。智能体通过截图和 GUI 操作进行交互，而成功与否由对保存的 FreeCAD 工件及辅助输出执行的任务特定可执行检查决定，这些检查涵盖几何属性、参数化结构、约束、制造状态和仿真结果。在完整基准上对七个当前智能体的评估中，最强智能体的成功率为 17.5%，而专家参照通过率为 87.0%。我们发现，较弱的智能体往往在生成有效工件之前就失败，而较强的智能体则越来越多地在结构、几何和构建过程要求上失败。因此，CADWorld 揭示了通用 GUI 能力与可靠执行持久、可验证的工程工作流之间的差距。项目可访问 https://cad-world.github.io。

详细分析

1. 任务输入、输出、功能和边界（约100字）

CADWorld 是一个面向 FreeCAD 的计算机使用基准。任务输入包括自然语言指令、初始应用程序状态（可选前置 .FCStd 文件）、参考图像或网格等资产，以及最大交互步数。智能体通过桌面截图观察状态，输出鼠标、键盘、热键等受限 GUI 动作；最终输出是保存的原生 FreeCAD 工件及辅助文件。评估函数对工件执行任务特定检查并返回 0/1；执行中禁止直接脚本和文件系统访问，默认上限为 100 步。

2. 研究动机：要解决的问题与核心 insight（约300字）

通用计算机使用基准大多在网页或传统桌面环境中测试点击与输入，但机械 CAD 几乎没有被深入覆盖。CAD 给智能体叠加了四类难度：从二维视图恢复三维几何意图；精确到实体、约束、参数的选择与输入；长达数十到数百步的状态依赖操作；以及必须生成可检查、可编辑且工程语义正确的持久工件。作者特别指出，CAD 的 GUI 不是可更换的脚本前端，而是工程状态的主要表达方式：特征树、约束标注、选中高亮、视图同步等都承载着操作的含义。程序化 CAD 生成虽然能在显式符号规范下工作，却跳过了“从工作区识别状态—决定如何修改—验证后果”这一核心交互环节。因此论文提出用真实 GUI 操作和工件级验证来测试计算机使用智能体。

核心 insight 来自实验结果：最强智能体成功率为 17.5%，专家参考为 87.0%；较弱模型在产出有效工件前就失败，较强模型则更多在文档结构、几何、构建过程等方面失败。这说明通用 GUI 操作能力与可靠执行持久工程流程之间存在可测的差距，并且随着能力提升，失败点会向后移动。

3. 核心贡献（约300字）

论文的主要贡献可以归纳为三点。第一，将交互式机械 CAD 形式化为计算机使用问题：智能体必须操作面向用户的环境（FreeCAD），并在交互结束后留下持久、可编辑、可测量、可验证的原生工件，而不是生成代码、文本或仅看渲染相似性。第二，构建 CADWorld 基准：包含 200 个任务、11 类工作流、183 个知识点，覆盖草图、零件建模、装配、CAM、FEM、外观、点云、宏、测量、网格和技术制图；任务由人工作者编写，提供指令、前置状态、参考资产和任务特定评估器。第三，设计了工件锚定的可执行评估器与逐项诊断，并评估了 7 个当前计算机使用智能体；结果显示最强模型只有 17.5% 成功率，而专家参考为 87.0%，在 CAM、FEM 和 TechDraw 上所有模型均为 0%，验证了该基准能暴露出不同于通用桌面任务的失败模式。

4. 推理阶段整体流程与基模（约400字）

部署后的 CADWorld 系统在推理时以多模态大语言模型（实验中包括 GPT-5.4、Opus4.8、Kimi K2.6、Qwen3.6 等，以及 OpenCUA、Holo 3.1 等 computer-use 模型）作为视觉-动作决策基模。基模不直接访问 CAD 内部对象；它只接收截图和文本/图像上下文，输出可执行的 GUI 命令。FreeCAD 虚拟机作为被操作的工具环境，runner 负责动作执行、观测采集和终止判断。

图6给出了完整流程中任务初始化、闭环执行和宿主端评估的位置。

图6：详细的 CADWorld 基准工作流。任务从结构化包初始化，智能体通过截图观察和可执行 UI 动作操作 FreeCAD，保存的 CAD 工件由主机端检查评估，而不是仅凭文本答案或最终截图评估。

推理时主数据流按以下步骤循环：

  1. 输入：任务指令、参考图像、最近 10 轮轨迹摘要和当前桌面截图。基模多模态大语言模型将当前截图与指令中的工程目标关联，决定下一步动作；输出可以是单个或有序动作（如 click、write、hotkey、dragTo），也可以是控制 token（WAIT、DONE、FAIL）。该输出交给动作适配器。
  2. 输入：模型原始输出。适配器把输出解析并映射到平台允许的 pyautogui 原语序列，过滤掉 FreeCAD 脚本、文件读写和不在白名单中的命令；保留 Shift+右键拖拽等有序按下-移动-松开语义。清洗后的动作在虚拟机内执行。
  3. 输入：执行动作后的 FreeCAD 界面。Runner 等待短暂延迟、截取新截图，并把截图、动作和日志追加到轨迹。若模型未终止且未达到 100 步，新截图与最近轨迹摘要一起作为下一轮观测返回给基模，形成闭环。
  4. 输入：DONE/FAIL 或达到步数上限。Runner 从虚拟机提取保存的 .FCStd 文件和辅助输出（如 FEM 的 CSV、网格文件）。退出状态也会被记录。
  5. 输入：提取的工件与辅助文件。任务特定评估器运行全部必需检查，输出二进制成功/失败以及逐检查诊断。该结果可回溯到动作轨迹和截图。

5. 核心方法：按论文 Method 小节总结（约600字）

论文没有独立的 “Method” 章节标题；方法主体是第 3 节 “CADWorld Benchmark Design”。正文中该节未显示显式子节编号，下面按原文顺序整理为 3.1–3.5，并保留英文主题词。

3.1 Task Taxonomy（任务分类）

目的：定义 CADWorld 覆盖的机械 CAD 知识范围。基准包含 200 个任务、11 类工作流、183 个知识点；每个任务可对应多个知识点，因此任务大小和分布由概念覆盖决定。前 190 个任务构成常规概念覆盖集，另加 10 个更短更简单的任务以区分低性能模型。指令长度中位数为 63 词、最长 178 词。任务来源包括 FreeCAD 工作台能力、教程和文档、常见机械设计流程，以及构造中发现的覆盖缺口；标注和验证约耗时 3 个月、1300 人时。图1给出一条代表性长工作流。

图1：一个具有代表性的长视界 FreeCAD 工作流，从项目创建和基础特征定义开始，经过约束草图、拉伸、阵列，直至最终验证。

3.2 Task Package and Benchmark Workflow（任务包与四阶段工作流）

目的：把每个任务变成可复现的包。任务形式为 \(x_i=(\iota_i,p_i,u_i,e_i,H_i)\)，分别对应自然语言指令、可选前置 CAD 文件、可选上传资产、任务特定评估器、最大交互视界。执行分四个阶段：打包任务；重置 FreeCAD 环境并载入前置状态；以截图为观测、以可执行 UI 动作循环运行；在宿主侧对保存工件运行评估。Runner 记录初始截图、逐帧截图、JSONL 轨迹、屏幕录像、运行日志和生成文件，用于追溯结论。图2展示任务包的组成。

图2：每个任务将指令、设置配置、参考资产、CAD 领域元数据和一个评估器打包在一起。

3.3 Observation and Action Space（观测与动作空间）

目的：规定智能体与 CAD 环境的接口，使其接近人类使用但可复现。观测以截图为主，附带任务指令、参考图像以及最近轨迹历史；前置文件由 runner 上传，模型只能通过 GUI 看到其效果。动作空间是白名单化的 pyautogui 命令，包括 moveTo、click、rightClick、dragTo、scroll、press、write、hotkey、keyDown、mouseDown 等，以及 WAIT、DONE、FAIL 控制 token。模型输出分为两类：原生 CUA 模型走提供方的 computer-control 接口；截图条件多模态 LLM 则解析文本响应。CADWorld 会清洗模型输出，禁止直接 FreeCAD 脚本和文件系统访问。特别地，状态化输入组合（如 Shift+右键拖拽旋转三维视图）被保留为有序按下-移动-松开序列。

3.4 Artifact-Grounded Evaluation（工件锚定的评估）

目的：在持久工件上判定任务是否正确，而不是看最终截图或文本答案。各工作流的检查方式不同：草图任务解析 .FCStd 中的实体、约束、尺寸、面积/周长/质心；零件、外观、宏、测量、网格、点云、TechDraw 任务检查模型元数据、对象类型、属性、包围盒、体积、面积等；装配检查 joint 对象（如 Grounded、Slider）；CAM 比较毛坯与目标的材料去除、刀路数据、过切/欠切比；FEM 要求分析对象、材料、边界条件、网格、求解器和导出 CSV 数值。每项任务只有在全部必需检查通过时才成功，不提供部分分数；诊断文件仍保留连续误差、IoU、质心距离和逐规则报告。图3展示了一个视觉相似但工程不正确的典型案例。

图3：一个具有代表性的 CADWorld 任务，包含人类和模型的输出。尽管模型结果在视觉上与三棱柱相似，但它们不符合原生结构、几何或构建过程要求。因此，CADWorld 评估保存的工程工件，而不仅仅是视觉相似性；附录表12提供了跨工作流类别的更多示例。

3.5 Metrics and Failure Diagnosis（指标与失败诊断）

目的：在二元成功之外提供可解释的性能视图。能力指标按整体、工作流类别和单任务层级报告；效率指标记录交互步数、墙钟时间、token 消耗，并区分是否计入思考 token；失败诊断把每个不成功回合归入 11 种确定性失败原因，如无输出、错误文档结构、几何不符合、构建过程错误等，并结合终止状态和轨迹获得。整个评估不依赖 LLM 裁判或人工检查，因此同一评估器可用于在线评测和回溯评测。

6. 局限性和展望（约300字）

论文明确说明的限制有四点。第一，基准任务必须提供显式目标和必要资产，因此不能覆盖真实需求中的开放设计、需求澄清、不完整源设计搜索和设计权衡。第二，被评估模型在原生接口、上下文长度、访问策略、服务基础设施和延迟上不一致，效率指标要结合附录部署细节解释。第三，人类行是单个专家参考轨迹，不是受控人类研究，不能代表总体人类表现。第四，当前只支持 FreeCAD；商业 CAD 在几何内核、界面约定、约束求解器、云集成和下游制造流程上不同，工具选择是一种权衡而非普遍结论。

在此基础上可以谨慎推断：从实验中的 CAM、FEM、TechDraw 全部为 0% 的结果看，当前模型对界面状态更不透明的专业流程缺乏可靠知识；论文也承认训练语料不可观测，因此不能说这是唯一的因果解释。图4总结了成功率与失败原因分布，能直观显示“失败随模型能力提升而移向下游”的现象。

图4：蓝色单元格表示成功率，红色单元格表示失败原因率；颜色越深表示百分比越大，精确值标注在每个单元格中。工作流分组遵循表2中的概念分类。

未来可以沿多 CAD 后端扩展、更开放任务设计、可编辑性深层检查，以及跨阶段工程交接验证等方向继续推进。
