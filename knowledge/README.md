# Knowledge 维护约定

Knowledge 是独立的静态内容栏目，不接入论文检索、Survey pipeline 或日报调度；如需写作，可以使用独立的 Knowledge writer，但它与论文处理流程分开。

日报、Survey、Knowledge 的网站目录、临时输出和发布边界见仓库根目录的 [`WORKFLOW.md`](../WORKFLOW.md)；本文件只保留 Knowledge 栏目的维护约定。

新增文章时：

1. 在 `posts/<slug>/article.md` 写 Markdown 正文；图片放在同一个文章目录或其子目录中。
2. 在 `index.json` 增加一条记录，填写 `slug`、`title`、`description`、`category`、`tags`、`date`、`sequence` 和 Markdown 路径。`category` 必须使用 `taxonomy.json` 中已有的稳定大类，它是文件夹层级的元数据，不是筛选标签；新增大类先更新 taxonomy。不要添加未经用户批准的难度等级或基础/进阶分类。`sequence` 是同一天内从 1 开始的展示序号。
3. `tags` 只能选 `tags.json` 中已批准的标签；当前已包括 `3D生成`、`3D重建`、`3D分割`、`图像分割`、`具身智能`、`扩散模型`、`AI4S`、`手撕代码`、`llm`、`llm训练框架`、`llm扫盲2610`、`视频生成`、`视频生成入门2610`。一篇文章可同时有领域标签与系列标签，但不要为了文章只提到了某个概念就给它贴该概念的标签。
4. 新增标签必须先修改 `tags.json`，并在交付时明确告知用户新增了哪些标签；未登记的标签会被检查脚本拒绝。
5. 根目录显示可点击的分类入口；点击后进入独立分类目录，例如 `?category=LLM` 只显示 LLM 文章，不再用展开式分类文件夹。分类目录内可按标签筛选。分类、标签和搜索都同步到可分享的 `?category=...`、`?tag=...` 和 `?q=...` 网址参数。每类文章把 `date` 与 `sequence` 合成一个时间值，统一从晚到早排序；卡片时间写作“日期 · 两位序号”。
6. 每篇文章末尾保留 `## QA`。读者的问题经整理后直接追加到该文章的 Markdown，按 `### 问题`、回答正文的格式逐条记录；有第一条问答时移除“暂无问答。”。

当前手撕代码文章的归类方式：

- 标签：`手撕代码`
- `Diffusion`、`Transformer`、`Flow Matching`、`ViT` 是文章标题里的题目，不是本文的标签；只有以后出现真正以这些方向为主题的文章，并经批准扩充 `tags.json` 后，才能成为筛选标签。

“面经检索入口”只是公开搜索入口，不等于本站已经审核了搜索结果。新增资料时应保留原始链接，并核对题目原文、发布时间和代码是否可运行。
