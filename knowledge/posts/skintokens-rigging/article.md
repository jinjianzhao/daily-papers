# 绑骨（Rigging）入门：从骨架、蒙皮到 SkinTokens

## 先说结论：绑骨到底在做什么

在 3D 制作里，**绑骨（rigging）**就是给一个静态模型安装一套可控制的“内部骨架”，并告诉模型表面每个位置应该跟随哪些骨骼、跟随多少。这样，动画师只需要转动手臂骨骼，角色的手臂、肩膀和衣服就会一起变形，而不是逐帧移动几万个顶点。

一个可动画的角色通常包含三层东西：

1. **几何体（mesh）**：顶点、边和面组成的外形，例如骑士的身体、盔甲和披风。
2. **骨架（skeleton/armature）**：有父子关系的关节和骨骼，例如髋部—脊柱—肩膀—上臂—前臂—手。
3. **蒙皮（skinning）**：顶点到骨骼的影响权重。权重决定顶点随哪根骨头移动以及移动多少。

绑骨不是“把一根骨头放进模型里”这么简单，而是要让骨架结构、控制方式和表面变形共同工作。最终目标是：在一组合理的动作下，模型不会塌陷、撕裂、穿帮或出现不自然的体积变化。

## 一个最小的具体例子

假设网格只有四个顶点，组成一条胳膊：肩膀点 (v_1)、肘部附近点 (v_2)、前臂点 (v_3) 和手腕点 (v_4)。我们建立两根骨骼：上臂骨 (b_1) 和前臂骨 (b_2)。

- (v_1) 的权重可能是 (w_{v_1,b_1}=1.0,;w_{v_1,b_2}=0)。
- (v_2) 在关节处需要平滑过渡，可能是 (0.6/0.4)。
- (v_3) 可能是 (0.1/0.9)。
- (v_4) 可能是 (0/1.0)。

当两根骨骼分别产生变换 (T_1,T_2) 时，最常用的**线性混合蒙皮（Linear Blend Skinning, LBS）**为：

\[
v' = \sum_j w_{v,j} T_j v,\qquad w_{v,j}\ge 0,\quad \sum_jw_{v,j}=1.
\]

因此肘部顶点会同时受到两根骨骼影响，手臂弯曲时比较平滑；但 LBS 在大角度弯曲时容易出现“糖纸卷曲”（candy-wrapper）或肩部塌陷，所以生产系统常会加 corrective blendshape、双四元数蒙皮（Dual Quaternion Skinning）或布料/肌肉模拟来修正。

## 标准绑骨流程

### 1. 清理和分析输入模型

先统一模型朝向、尺度、原点和坐标系，检查法线、非流形边、重复顶点、断开的部件和过密网格。人物身体、衣服、头发、武器通常要区分为不同对象，因为它们的变形规则不同。

还要先判断模型属于哪类资产：

- **类人角色**：可以使用人体模板或 Mixamo 等标准骨架。
- **四足或生物**：需要保留脊柱、四肢、尾巴、耳朵等结构。
- **机械体**：部件通常刚性跟随单根骨骼，不宜使用大范围平滑权重。
- **非标准生物/怪物**：通常需要模板法和自由生成法结合，之后由艺术家修正。

### 2. 生成骨架并定义层级

骨架不是一组无序的点，而是树或多棵树。父骨骼的变换会传递给子骨骼；例如前臂继承上臂的旋转，手继承前臂的旋转。除关节位置外，还要定义骨骼方向、局部坐标轴、旋转顺序、关节限制和控制器。

骨架生成有三种常见方式：

1. 人工在 Blender、Maya 等软件中放置骨骼，质量最高但耗时。
2. **模板拟合**：把预先定义的人体骨架缩放、旋转到模型上，适合常见人形。
3. **模板无关预测**：网络根据几何特征预测关节位置和连接关系，能处理更多形状，但容易漏骨、错连或生成冗余骨骼。

### 3. 绑定和蒙皮

绑定（binding）通常指把网格对象与骨架关联起来；蒙皮则是计算每个顶点的权重。权重来源可以是：

- 热扩散、距离场、骨骼包围体等几何算法；
- 图神经网络或点云网络直接预测；
- 从已有角色迁移权重；
- 生成式模型先生成骨架，再生成权重。

需要特别处理肩、髋、肘、膝、手指、盔甲接缝等区域。权重既不能“漏绑”（顶点没有骨骼影响），也不能“串权”（手臂权重跑到披风或另一条腿）。

### 4. 控制器和动作测试

生产中的 rig 往往比骨架多一层控制器：IK（逆运动学）让脚掌贴地、FK（正运动学）逐级旋转骨骼，空间切换、脚锁定、手部约束和表情控制都属于这一层。

绑骨完成后，必须用极端动作检查：手臂抬过头、膝盖弯曲、角色坐下、手指握拳、快速旋转和非对称动作。只看 T-pose 不能说明蒙皮是正确的。

## 为什么自动绑骨是一个难题

传统算法可以依据几何中心、骨骼距离和热扩散来分配权重，但它不知道“这里是手”“那边是尾巴”。一个不连通的披风和身体距离很近，却不应该共享同样的权重；盔甲的硬表面也不适合像皮肤一样平滑变形。

学习方法面临两个相互关联的预测问题：骨架决定有哪些骨骼，蒙皮又依赖这些骨骼的位置和语义。如果先独立预测骨架，再单独回归权重，前一个错误会传给后一个模型。此外，权重矩阵很大但极度稀疏：一个有 (N) 个顶点、(J) 根骨骼的模型具有 (N\times J) 个潜在权重，但实际一个顶点通常只受不超过四根骨骼影响。直接用 MSE 回归整个矩阵，会被大量零值主导，模型容易学成“到处接近零”的平均解。

## 代表性自动绑骨范式

### 几何与模板方法

Pinocchio 等经典方法利用距离场和中轴结构推断骨架，适合封闭、干净、类似生物体的网格。模板方法则直接拟合标准人形骨架，稳定、易于导出到游戏引擎，但面对翅膀、触手和多足动物时泛化有限。

### 学习式模板无关方法

RigNet 使用图网络从网格中预测关节热图，再通过连接算法组装骨架，同时估计蒙皮权重。它代表了“几何特征 → 关节/权重”的回归范式。此类方法能处理更多形状，但骨骼连接对噪声敏感，复杂模型可能产生断链或冗余关节。

### 生成式和自回归方法

较新的 UniRig、MagicArticulate、Puppeteer 等方法把骨架层级离散成 token，用 Transformer 自回归生成关节和连接关系。它们借鉴语言模型的方式：先生成根节点，再生成子节点和坐标。优点是能建模全局拓扑；缺点是如果蒙皮仍由另一个回归器完成，骨架和权重之间的信息没有完全共享。

下面的 SkinTokens/TokenRig 正是针对这一缺口的代表工作。

## SkinTokens：把蒙皮权重变成可生成的 token

论文：**Skin Tokens: A Learned Compact Representation for Unified Autoregressive Rigging**，Jia-Peng Zhang 等，arXiv:2602.04805（2026；TOG DOI: [10.1145/3859874](https://doi.org/10.1145/3859874)）。论文提出 SkinTokens 和 TokenRig，把自动绑骨从“分别回归骨架和巨大权重矩阵”改成“统一生成一条骨架 + 蒙皮 token 序列”。

### 任务输入和输出

输入是一份原始 3D 网格（论文还使用全局形状特征）；输出包括：

1. 关节坐标和父子层级组成的骨架；
2. 每个骨骼对应的顶点蒙皮权重；
3. 由骨架和权重组成的可动画 rig。

### 第一阶段：FSQ-CVAE 学习 SkinTokens

对每根骨骼 (j)，论文取出它在所有顶点上的权重向量 (w_{(:,j)})。一个网格可能有数千到十万个顶点，直接生成这些浮点数太长。论文使用条件变分自编码器（CVAE）：

- 网格编码器 (E_M) 读取无序的几何点集，得到形状条件；
- 权重编码器 (E_W) 读取该骨骼的权重分布，得到连续潜变量；
- FSQ（Finite Scalar Quantization）把连续潜变量每个维度量化到有限的整数等级；
- 解码器根据形状条件和离散 token 重建权重。

这里的 token 不是把每个顶点编号成一个词，而是对整根骨骼的“影响分布”做压缩编码。论文的配置最多为每根骨骼 32 个 SkinTokens；最终用于自回归生成时还测试了 4 或 6 个 token 的轻量设置。

FSQ 与传统 VQ 的区别是：VQ 要维护一个可学习的 codebook，可能出现 codebook collapse；FSQ 使用固定的多维离散网格，通过 Straight-Through Estimator 传递梯度，不需要额外的 codebook/commitment loss。论文选用量化等级 ([8,8,8,5,5,5])，隐式词表大小为 (8^3\times5^3=64{,}000)，并报告了约 97.3% 的离散空间使用率。

由于非零权重只占很小比例，论文使用 BCE、MSE 与 Dice loss 的组合。Dice loss 会提高非零影响区域的梯度，避免模型只把所有权重预测成零；训练解码器时还对有真实影响的表面区域做重要性采样。

### 第二阶段：TokenRig 统一自回归生成

TokenRig 使用 decoder-only Transformer。它先生成序列化的骨架：骨骼类型、关节的离散 (x/y/z) 坐标以及层级边界；骨架生成完毕后，按固定顺序继续生成每根骨骼的 SkinTokens。抽象地可以写成：

```text
<bos>  骨骼类型  关节坐标 ... <skeleton_end>
       SkinTokens(骨骼1) ... SkinTokens(骨骼J)  <eos>
```

因此，当模型生成“左前臂”的 SkinTokens 时，注意力可以访问已经生成的整套骨架和其他上下文。它不再单独预测一张无结构的 (N\times J) 矩阵，而是预测一串短的离散符号；解码器随后把每根骨骼的 token 还原成顶点权重。

这一步的关键不是把 3D 模型变成文本，而是找到一个**长度可控、可组合、能让 Transformer 学习的表示**。生成 token 后，仍然需要按 LBS、约束和动画测试把它变成实际 rig。

### 第三阶段：用 GRPO 按“能不能动好”做强化学习

监督训练只能模仿训练集。对于带翅膀、尾巴、披风或非标准身体的模型，TokenRig 可能漏掉骨骼、把骨骼放到模型外，或让一个顶点受过多骨骼影响。论文因此用 GRPO 采样同一网格的多个 rig，并依据几何和动画质量给相对奖励：

1. **体积关节覆盖**：关节是否覆盖模型的重要体积，避免遗漏末端结构；
2. **骨骼-网格包含**：骨骼采样点是否落在模型内部，避免骨头穿出身体；
3. **蒙皮覆盖与稀疏性**：每个顶点至少有一根有效骨骼，同时通常不超过四根有效影响；
4. **变形平滑度**：随机采样姿态，用 LBS 变形并惩罚边长突变、尖刺和塌陷。

对每个输入，模型从旧策略采样一组输出，在组内归一化奖励形成相对优势，再用 PPO/GRPO 风格的裁剪比率更新策略，并加入相对参考策略的 KL 惩罚。这样 RL 优化的是“生成出来的 rig 是否满足几何和动画规则”，而不是人工逐 token 标注答案。

## 论文结果与应如何理解

论文报告，SkinTokens 相对于已有蒙皮方法的 (L_1) 误差有 98%–133% 的相对改善，完整 TokenRig 在骨架 Chamfer 指标上进一步改善约 17%–22%（具体数值依数据集和指标而定）。在推理阶段，完整 rig 平均约 15 秒（单张 A800 的论文设置）。这些数字说明离散表示确实缓解了稀疏回归困难，但不意味着所有模型都能零修改直接生产：训练数据、网格清理、骨架语义和导出格式仍然会影响结果。

## 和 Blender 工作流如何对应

在 Blender 中可以把自动绑骨的输出理解为：

- TokenRig 生成的骨架 → Armature 对象及骨骼父子关系；
- 解码的权重 → 网格的顶点组（每根骨骼一个 vertex group）；
- LBS → Armature Modifier 的 Deform 过程；
- GRPO 的变形奖励 → 用一批测试动作检查肩、髋、膝、手指和衣服是否出现异常。

自动方法的输出最好视为“可编辑初稿”。对盔甲、长裙、披风等刚性或柔性部件，常需要拆分对象：盔甲可使用刚性权重，披风则可能交给布料模拟或在骨骼权重上叠加辅助骨。完成权重后应在 Blender 中检查权重可视化、镜像一致性、IK 控制器、动作库和导出到 FBX/GLB 后的骨架坐标。

## 小结

绑骨的核心链条是：**模型 → 骨架拓扑 → 顶点蒙皮权重 → 控制器/约束 → 动作下的变形质量**。传统算法主要依赖几何，学习方法把它变成骨架和权重预测，而 SkinTokens 的贡献是先把稀疏的权重矩阵压缩成紧凑离散 token，再用 TokenRig 让骨架和蒙皮在同一条自回归序列中联合生成，最后用 GRPO 直接优化“这个 rig 动起来是否合理”。

## QA

### 对于衣服，艺术家通常怎么做蒙皮？例如穿裙子的人，和穿利落抹胸的人，有什么不同？

关键不是“衣服”这个名字，而是它是否应该跟着身体连续变形、是否有独立的运动，以及是否需要碰撞和飘动。

**利落抹胸、紧身衣、贴身上衣**通常可以直接作为身体的附属网格处理：沿用身体骨架，在胸口、肩部、腰部等区域复制或投射身体权重，再手动清理领口、腋下和边缘。它和身体一起抬臂、弯腰，通常不需要单独的衣服骨骼；如果衣服有硬质胸甲或明显的装甲片，则会拆成独立部件，让每块部件刚性地跟随一根或少数几根骨骼，避免被 LBS 拉软。

**长裙、宽裙、披风、外套下摆**通常不会只靠一套身体权重解决。上半部分可以跟随髋部和骨盆，裙摆则会增加裙摆链、布料辅助骨或直接使用 Cloth/布料模拟。艺术家常先用骨骼蒙皮保证大体动作，再让布料模拟处理重力、摆动和与腿部的碰撞；如果项目需要实时运行，就会用少量裙摆骨骼、受限权重和预烘焙动画近似布料效果。

一个具体例子：角色抬腿时，紧身抹胸的腰部仍主要跟随脊柱和骨盆；长裙腰头跟随骨盆，但裙摆不能全部绑定到骨盆，否则整条裙子像硬纸板一起抬起。裙摆下方通常要保留更大的局部自由度，或者交给布料碰撞系统。自动绑骨模型只能给出初稿，裙摆、袖口和衣服与身体接触的地方仍需要艺术家按目标动作修权重和碰撞设置。

### SkinTokens 能否针对盔甲、衣物等部件自动采用不同的绑骨逻辑？

**就论文公开的 SkinTokens / TokenRig 范式而言，不能直接理解为它已经内置了“盔甲模式”“裙子模式”等部件专用规则。**它主要生成一套骨架和每根骨骼对应的蒙皮权重，权重本身可以表达不同的跟随方式：贴身衣物可以得到平滑的多骨骼权重，硬质盔甲片可以接近单骨骼的刚性权重，裙摆也可以由多根辅助骨骼组成更细的权重分布。

但“能表示”不等于“能可靠识别并自动采用正确逻辑”。要让模型自动区分盔甲、紧身衣、裙摆和披风，训练数据需要包含相应的部件语义或足够多的绑定示例；论文摘要和公开方法重点是紧凑蒙皮表示、统一自回归生成与几何/变形奖励，并没有把服装分类器、布料模拟器或专门的盔甲规则描述成通用模块。因此实际生产中更稳妥的流程是：SkinTokens 先生成初始 rig 和权重，再根据部件类型做后处理——盔甲拆件并限制为刚性权重，贴身衣物沿用身体权重，裙摆/披风增加辅助骨或交给布料模拟，最后用目标动作检查和修正。
