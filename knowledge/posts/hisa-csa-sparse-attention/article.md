# HISA 与 CSA：长上下文推理，究竟该压缩索引还是压缩记忆？

长上下文 LLM 面临两个容易混在一起的成本：**保存历史的 KV cache**，以及每生成一个 token 时**从历史中找出该读什么**。HISA 和 CSA 都利用分块让检索更便宜，但它们压缩的对象和最终读取的粒度不同。理解这个区别，比记住缩写更重要。

本文从标准注意力和 DeepSeek Sparse Attention（DSA）讲起，再分别解释 HISA、CSA，最后讨论公众号文章提到的“相位敏感性”实验。这里的 HISA 指 [HISA: Efficient Hierarchical Indexing for Fine-Grained Sparse Attention](https://arxiv.org/abs/2603.28458)；CSA 指 DeepSeek-V4 报告中的 [Compressed Sparse Attention](https://arxiv.org/html/2606.19348)。两篇论文的模型、实现和实验口径并不相同，因此不能把它们的数字直接当作同一模型上的公平对照。

## 1. 问题从哪里来

自回归 LLM 生成下一个 token 时，当前查询 `q` 要利用前文的 Key、Value（KV）。普通因果注意力会对历史所有位置打分，再加权汇总 Value。推理时把历史 KV 保存起来，就不必反复计算历史隐藏状态，这就是 **KV cache**。

但上下文越长，至少有三笔账越大：历史 KV 占用的显存；当前查询读取历史 KV 的内存流量；决定哪些历史位置重要的索引计算。**“只读少数 KV”不等于“只存少数 KV”**：稀疏注意力可以减少一次查询读取的条目，却仍保留完整历史，供后续查询重新选择。

DSA 的想法是：先用轻量 **indexer（索引器）**给整个历史的每个 token 打分，选出 top-`k` 个位置，再由后面的 Sparse MLA 只读取这些 token 的 KV。于是昂贵的核心注意力由“读全部”变成“读 `k` 个”。问题是，索引器每次仍要扫描全部历史；对长度为 `L` 的各个查询累计起来，索引成本仍可达 `O(L²)`。HISA 首先要解决的，正是这个看似轻量、实际上会随上下文增长的索引器。

## 2. HISA：先找区域，再在区域里找 token

HISA（Hierarchical Indexed Sparse Attention）不是改掉 DSA 最终的 token 级稀疏注意力，而是把原来“对全历史 token 平铺扫描”的索引器，换成两级搜索：

```text
历史 token 的索引 Key
       │ 按相邻位置分块，每块形成一个汇总 Key
       ▼
第一级：当前查询给所有块打分，选 top-m 个候选块
       │ 候选块中的 token 组成候选集 c
       ▼
第二级：用原 DSA 索引打分方法，给候选 token 重新排序
       │ 最终选 top-k 个 token
       ▼
原来的 Sparse MLA 读取这 k 个 token 的 KV
```

例如历史有 4096 个 token，示意性地每 4 个组成一块，就有 1024 个块。如果先选 100 块，第二级最多只需在约 400 个候选 token 中选出最终的 `k` 个，而不是对全部 4096 个 token 做细粒度打分。这里的 `4`、`100` 只是帮助理解的数字，不是 HISA 论文的默认配置；实际必须满足候选 token 数不少于最终 `k`，并处理因果掩码、不满块和起始/最近位置。

HISA 论文用块内索引 Key 的均值构造第一级的汇总代表。代表向量只负责**粗筛**：原来的逐 token 索引 Key 和 Sparse MLA 使用的 token 级 KV 仍在。第二级对候选 token 使用与 DSA 相同的打分机制；输出仍是一组 token 下标，所以原来的 Sparse MLA 不必改变，也不要求再训练模型。其理想化的每查询索引量由扫描 `L` 个 token，变为扫描约 `L/B` 个块和至多 `mB` 个候选 token，其中 `B` 是块大小。

代价也在这里：第一级若漏掉含有关键 token 的块，第二级再精细也找不回来。均值汇总尤其可能淹没块内极短、极稀疏的证据。HISA 原论文把这作为失败边界，并在 DeepSeek-V3.2 和 GLM-5 的长上下文实验中检验了它与原 DSA 的质量接近程度；“接近”不等于逐次选择完全一致。

## 3. CSA：压缩的内容本身进入注意力

DeepSeek-V4 的 CSA（Compressed Sparse Attention）也按序列分块，但目的不只是给索引器建一个粗目录。它生成可学习的**压缩 KV 条目**，并生成相应的压缩索引表示。当前查询先在压缩索引上选择相关块，核心注意力随后读取的是这些被选中的**压缩 KV**；另有局部窗口保留最近 token 的细节。

```text
历史 token ──可学习分块压缩──> 压缩索引表示 ──选块──┐
             └────────────> 压缩 KV ────────────┴─> 核心注意力
最近 token ───────────────────局部窗口────────────────> 合并
```

因此，CSA 的被选块不只是“进入下一轮 token 排序的候选区域”；它的压缩条目本身就是长程注意力读取的记忆单元。这可能减少长程 KV 的存储条目和读取量，但也意味着块内多个 token 的信息已融合到一个表示中，不能在同一条路径上恢复成原始的逐 token KV。局部窗口承担近处精细信息的补充。

这里也要分清两个层面：CSA 的压缩率、索引预算和端到端性能取决于 DeepSeek-V4 的训练及推理实现；HISA 的论文则主要把它作为 DSA 索引器的免训练替换。不能看到两者都“先看块”，就认为它们可以不改模型地相互替换。

| 问题 | DSA | HISA | CSA |
| --- | --- | --- | --- |
| 第一轮找什么 | 全历史 token | 历史块 | 压缩块 |
| 后续怎样细化 | 直接选 top-`k` token | 候选块内再选 top-`k` token | 选中的压缩 KV 直接参与长程注意力 |
| 最终长程读取粒度 | 原 token KV | 原 token KV | 压缩 KV 条目 |
| 原逐 token KV 是否必须保留 | 是 | 是；另加块汇总索引 | 长程路径使用压缩 KV，另有局部窗口 |
| 主要减掉的工作 | 核心注意力的全量读取 | 索引器全历史逐 token 扫描 | 长程缓存条目及核心注意力读取 |

一句话说：**HISA 压缩“搜索目录”，最后仍读原 token；CSA 压缩“可读的记忆”，最后读压缩块。** 两者都在索引侧减少逐 token 处理，但第二阶段的语义不同。

## 4. “相位敏感性”是什么意思

这里的“相位”不是信号处理中必须先学的一套新数学，而是指**关键内容相对于固定块边界的位置**。假设每四个 token 一块，同一句关键事实向前挪一两个 token，就可能从一个块中间移到两个块的交界。若一个方法主要依赖块的单个汇总或压缩表示，块内容的这种重组可能改变粗筛分数或压缩后保留的信息，进而改变检索结果。

HISA 也不是从原理上对边界位置完全不敏感：它的第一级仍用块均值粗筛。它的优势在于，**只要正确的块进入候选集**，第二级就能重新按 token 打分，而不是把整块当作最终不可拆分的答案。关键块若在第一级就被漏掉，HISA 同样会失败。因此“CSA 必然相位敏感、HISA 永不敏感”不是两篇论文证明的定理。

用户提供的公众号文章报告了一组移动证据位置的**作者复现实验**：

| 方法 | 平均准确率 | 峰谷差 |
| --- | ---: | ---: |
| DSA | 37.30% | 0.98 个百分点 |
| CSA | 45.41% | 73.83 个百分点 |
| HISA | 50.05% | 1.17 个百分点 |

这张表只能作为该文章指定模型、任务、预算和实现下的观察，**不是 HISA 或 DeepSeek-V4 原论文可直接泛化的结论**。尤其公众号原文提示过：CSA 用的是 **top-2048 个块**，其他设置按 token 预算对齐的方式可能仍需修正。块与 token 的单位不同；若预算不等价，平均准确率及峰谷差都不能被解释为纯粹由机制导致的差异。要严肃验证“相位敏感性”，需要固定模型、数据、有效读取 token 数及压缩比例，仅系统移动证据相对块边界的位置，并重复评估。原文入口：[微信公众号文章《字节最新论文意外“背刺”DeepSeek-V4？一文讲透 HISA 如何终结 CSA 的相位敏感性》](https://mp.weixin.qq.com/s/Ftkah3dY30vrGbVZ3FRw1A)，另有[知乎转载/讨论](https://zhuanlan.zhihu.com/p/2094012600119981083)。

### 一个更具体的“相位”例子

设块大小 `B=4`，token 位置对块边界的余数只有 `0、1、2、3` 四种。不要把“相位”理解成证据必须跨块才会出问题：同一条关键证据从位置 `8,9` 移到 `9,10`，其余数就从 `(0,1)` 变为 `(1,2)`，虽然仍可能落在同一个或相邻的块中，块均值和压缩权重也会随块内邻居改变；再移动到 `11,12`，余数变为 `(3,0)`，证据跨过边界，两个块的摘要会同时改变。这里的 `0/1/2/3` 是 token 位置 **modulo 4** 的示意，不是论文声称的固定块大小。实验要逐一控制这些相位位置，才能区分边界效应与内容本身的随机波动。

## 5. 该怎么选择这类方法

如果主要瓶颈是 DSA **索引器扫描全历史**，又希望保留原模型的逐 token 记忆和 Sparse MLA 接口，HISA 是一条自然路线：小代价的块级粗筛，加候选集内的原索引器细排。它省的是检索工作，不应宣传成按同样比例缩小原 KV cache。

如果目标还包括**减少长程缓存本身**，CSA 的可学习压缩 KV 更直接，但需要接受训练、实现与细节保留能力的相应取舍。评价时应分别报告缓存字节数、索引耗时、核心注意力耗时、端到端吞吐和质量；单独一个“稀疏率”无法说明整套系统是否更好。
