# 从记忆理解 Transformer

我们熟悉 Transformer 的计算流程：注意力让一个 token 读取上下文，MLP 则逐 token 处理表示。但为什么网络中恰好反复出现这两类模块？[Alex Wang 的文章《You could have invented transformers from memory》](https://alexwang.ai/posts/associative-memory/)给出一条有意思的理解路径：先问怎样存入、找回大量“线索 → 内容”，再看线性层、MLP 和自注意力各自怎样回答这个问题。

这是**理解架构的一种视角**，不是声称模型训练时真的把每个事实写进一个独立的抽屉。下面先搭一个最简单的记忆库，再一步步解决它的问题。

## 先认识关联记忆

假设我们想记住“某个线索对应什么内容”。每条记忆写作一对向量 `(kᵢ, vᵢ)`：`kᵢ` 是用来匹配的 **key**，`vᵢ` 是希望取回的 **value**。查询向量 `x` 送入记忆库 `f`，理想情况是 `x` 与 `kⱼ` 相近时，输出 `f(x)` 接近 `vⱼ`。这就是 *associative memory*（关联记忆）：凭相似的线索唤起内容。

可以把它想成“看到一段关于海王星的提问，就唤起相关信息”。真实语言模型没有把完整问题直接作为一个固定 key 存好；这个例子只帮助理解查询、匹配和取回的关系。下文都用 `M` 表示记忆条数、`dₖ` 表示 key 的维数。

## 第一种方案：把记忆叠进一个矩阵

最直接的写入方法是把每对 key 和 value 做**外积**，再相加：

\[
W=\sum_{i=1}^{M}v_i k_i^{\mathsf T},\qquad
f(x)=Wx=\sum_{i=1}^{M}v_i(k_i^{\mathsf T}x).
\]

式子右侧就是一次检索：查询 `x` 与每个 key 算内积，再按相似度混合所有 value。例如目标 key 与查询的内积是 `1`，另一个 key 的内积是 `0.1`，后者对应的 value 也会以 `0.1` 的权重混进来。这个方案写入很方便，增加一条记忆只需给 `W` 加上一个外积。

博客还指出一个值得记住的联系：对线性层 `y = Wx` 做一步梯度下降时，权重更新量也具有“输出梯度 × 输入”的外积形式。这说明训练更新**可以从记忆写入的角度解释**；它不意味着一次梯度更新恰好写入一条语义明确的事实。

### 问题：取回时有干扰

若所有 key 长度为 `1`，用第 `j` 条记忆自己的 key 查询，会得到：

\[
f(k_j)=\underbrace{v_j}_{目标信号}
+\underbrace{\sum_{i\ne j}v_i(k_i^{\mathsf T}k_j)}_{其他记忆的干扰}.
\]

其他 key 只要与 `kⱼ` 不完全正交，其 value 就会一起出现。比如要取回“海王星”的信息，许多同样带有“行星”特征的记忆都可能漏进答案。记忆越多，单条干扰虽小，合起来也会盖过目标信号。

在博客设定的**独立随机单位 key、长度相近的随机 value** 下，这种外积记忆的干扰与信号之比大约是 `√(M/dₖ)`。若把“干扰与信号一样大”作为失败界线，容量就是 `M ≈ dₖ`。这不是“维度为 64 的真实网络只能记 64 个事实”，而是这个受控实验中、这一种取回标准下的估算。

## 第二种方案：写入时先处理冲突

刚才每条记忆是直接相加的，完全没有考虑 key 之间是否相似。更仔细的做法是一次选择一个矩阵 `W`，让所有已知 `(kᵢ, vᵢ)` 的取回误差尽量小：

\[
\min_W\sum_i\lVert Wk_i-v_i\rVert_2^2.
\]

这就是最小二乘线性回归。若 `M ≤ dₖ`，且 key 线性独立，原则上可以让每个训练 key 都准确取回自己的 value；当 `M > dₖ`，有限的线性维度仍会造成混合。博客在同样随机设定下得到干扰比约 `√(M/dₖ−1)`，对应的界线约为 `M = 2dₖ`。

直觉是：外积相加相当于“把卡片随手叠放”，最小二乘则会先看卡片的相似方向，尽量抵消它们之间的冲突。不过它的读取仍是**线性的**：相似度 `0.1` 和 `1` 都按比例进入结果。要更强地压低无关项，就需要非线性选择。

## 第三种方案：MLP 让弱匹配少说话

给每个匹配分数加一个非线性函数 `σ`，得到：

\[
f(x)=\sum_i v_i\,\sigma(k_i^{\mathsf T}x)
=W_{\mathrm{out}}\,\sigma(W_{\mathrm{in}}x).
\]

这就是两层 MLP 的形状：`W_in` 的每一行可看作一个检测输入模式的 key；激活值表示这个模式触发了多少；`W_out` 的对应列把触发结果变成输出方向。比如 ReLU 会直接丢掉负匹配，而 `ReLU(s)²` 还会把 `0.1` 缩成 `0.01`，同时让 `1` 仍是 `1`。弱匹配的内容因此更少混入输出。

带门控的 MLP 延续了这个思路。例如 SwiGLU 用一个投影产生门控信号，另一个投影产生要被门控的内容，再逐元素相乘；它并不要求“一个神经元就是一条事实”。真实模型的多个模式可以叠加在同一批权重中，门控也可能依赖训练后形成的复杂特征。

这里要区分**共享位置**：标准 Transformer 中的 MLP 权重是在训练后保留下来的参数，所有 token 都使用同一组权重。把这些权重理解成长期可复用的“记忆线索”很有帮助，但不等于说所有事实都只存在 MLP 中。

## 第四种方案：注意力读取当前上下文

MLP 的 key 和 value 来自固定权重；如果希望直接从**这次输入的上下文**取内容，就让每个上下文 token 临时提供自己的 key 和 value。当前位置产生 query `q`，对所有可见位置计算：

\[
\alpha_i=\frac{\exp(q^{\mathsf T}k_i/\sqrt{d_k})}
{\sum_{r}\exp(q^{\mathsf T}k_r/\sqrt{d_k})},\qquad
o=\sum_i\alpha_i v_i.
\]

这就是自注意力的一次读取。`softmax` 用指数放大较强的匹配，再把权重归一化。读一句“莉莉把书给了小王，他随后离开”时，“他”这个位置可以对上下文位置分配权重并聚合其 value。它读取的是**当前序列中的信息**；推理时的 KV cache 只是保存这些已经算出的上下文 key/value，避免重复计算。

原博客把这种记忆称作“非参数式”：这里指**记忆条目随上下文变化**，不是说整个注意力模块没有可训练参数。产生 `q`、`k`、`v` 的投影矩阵仍需要训练。相对地，MLP 的“记忆线索”主要体现在固定参数里。这两种读取方式在 Transformer block 中互补。

## 容量数字该怎样读

沿着博客的实验设定，以 `dₖ = 64` 为例，可以得到下面的直觉对比：

| 读取方式 | 主要变化 | 博客示例中的大致界线 |
| --- | --- | ---: |
| 外积线性记忆 | 所有匹配按原始内积混合 | `64` 条 |
| 最小二乘线性记忆 | 写入时考虑 key 之间的冲突 | `128` 条 |
| ReLU MLP | 丢掉负匹配 | `128` 条 |
| 平方 ReLU MLP | 进一步压低弱匹配 | 约 `2,700` 条 |
| Softmax 注意力 | 指数放大强匹配、归一化读取 | 约 `120 万` 条 |

这些数字来自[原文的随机向量实验与推导](https://alexwang.ai/posts/associative-memory/)，其“容量”特指：**用已存入的 key 查询一层记忆库时，其他随机 value 的干扰何时达到目标信号大小**。它没有覆盖自然语言中的相似语义、查询与存储 key 不完全相同、训练数据分布、模型深度、优化过程或最终任务准确率。尤其不能把“约 120 万”读成某个 Transformer head 实际可靠记住 120 万条知识。

这个视角真正有用的是关系，而非数字：**线性叠加容易混入其他内容；更仔细的写入能缓解一部分冲突；非线性门控能压低弱匹配；注意力则对当前上下文做可变的、较集中的检索。** 这样再读 Transformer，attention 与 MLP 就不只是两个公式，而是两种不同位置、不同更新方式的关联记忆。
