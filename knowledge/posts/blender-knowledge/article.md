# Blender 全功能地图：从场景数据到粒子、渲染与制作流程

Blender 不只是建模软件，也不只是动画软件。它是一套把三维场景的创建、编辑、模拟、渲染、合成和交付放在同一工程里的内容创作工具。要快速理解它，最有效的方法不是记菜单，而是先分清三件事：**场景里有哪些数据、这些数据怎样相互关联、最后通过什么流程得到图像或动画**。

本文面向懂基本三维概念、但还没有系统使用过 Blender 的读者，按功能地图介绍从界面和数据模型到粒子系统的主要部分。Blender 更新较快，个别面板和功能在版本间会迁移；下文以当前 Blender 的通用概念为主。特别是粒子系统与 Geometry Nodes（几何节点）是两种不同的程序化工作方式，不能把它们当成同一个系统。

## 1. Blender 的工作对象：不是“一个模型文件”，而是一组相互引用的数据

### 场景、对象与数据块

可以把 Blender 工程想成一个小型场景数据库：

- **Scene（场景）**：组织一次拍摄或渲染所需的对象、世界设置、相机、时间范围等。一个 `.blend` 文件可以包含多个场景。
- **Object（对象）**：场景中的一个实例，带有位置、旋转、缩放、父子关系、可见性等变换与关系信息。对象可以引用网格、曲线、相机、灯光等数据。
- **Data-Block（数据块）**：实际可复用的数据，例如 Mesh（网格）、Material（材质）、Image（图像）、Action（动作）、Camera（相机）。多个对象可以引用同一份数据。
- **Collection（集合）**：用来组织对象的层级容器，类似可嵌套的场景文件夹。对象可以通过集合管理显示、渲染和场景结构。
- **View Layer（视图层）**：决定某个渲染视图中哪些集合可见，以及如何组织覆盖设置；常用于分层渲染与合成。

因此，“复制对象”和“复制网格数据”不是一回事：两个对象可以各自移动，却共享同一份网格；改其中一个对象的共享网格时，另一个也会变化。需要独立几何时，才把数据做成单用户副本。

### 界面、编辑器与上下文

Blender 界面由多个 **Editor（编辑器）** 拼成：3D Viewport 看和操作场景，Outliner 看对象/集合层级，Properties 编辑对象与渲染属性，Timeline/Dope Sheet/Graph Editor 处理时间与动画，Shader Editor 编辑材质节点，Geometry Node Editor 编辑几何节点，Image/UV Editor 看图像与 UV，Compositor 处理渲染结果，Video Sequencer 剪辑视频。

每个编辑器可切换类型，区域也能分割、合并和保存为工作区布局。很多命令受当前 **Mode（模式）** 和活动对象影响：Object Mode 操作对象，Edit Mode 操作几何元素，Sculpt Mode 操作表面；例如网格编辑模式下的“顶点”不是一个独立场景对象。快捷键高效，但初学时要看状态栏、模式选择器和当前活动对象，否则同一快捷键可能作用于不同对象或元素。

### 坐标与变换

Blender 使用对象局部坐标和世界坐标。对象的 Location、Rotation、Scale 是对象变换；网格顶点则存于网格数据的局部坐标中。应用变换（Apply）会把对象变换折入几何或相应数据，使对象变换归零，但外观通常不变。应用缩放会影响修改器、物理参数、倒角宽度等对尺度敏感的效果，故建模前保持合理单位与尺度很重要。

## 2. 建模与几何创建

### 网格建模

Mesh（网格）由 **顶点（Vertex）—边（Edge）—面（Face）** 构成，是硬表面、角色、道具和大多数可变形表面的基础表示。Edit Mode 可移动、挤出、切割、环切、倒角、合并、法线调整和编辑拓扑；选择模式可在顶点、边、面之间切换。常用编辑包括：

- **Extrude（挤出）**：沿方向生成新几何并连接原边界，适合从轮廓延伸体积。
- **Inset（内插面）**：在面内生成边界，常用于面板结构。
- **Loop Cut（环切）**：沿拓扑环增加边，控制细分曲面轮廓。
- **Bevel（倒角）**：给边增加宽度和圆角，改善高光与制造感。
- **Merge / Dissolve**：合并元素或移除边/面而尽量保留轮廓。
- **Normals（法线）**：决定表面朝向及平滑插值；错误法线会造成阴影断裂或内外翻转。

拓扑是几何连接方式，不等同于表面外观。规则四边面拓扑常便于细分、变形和布线；三角面适合最终实时网格与扫描数据；建模时应围绕用途选择，而不是认为一种拓扑适用于全部任务。

### 修改器：非破坏性几何处理

Modifier（修改器）以堆栈方式对对象数据进行程序化变换，通常可在不立即改写原始网格的情况下调整结果。常见类别：

- **Subdivision Surface**：细分并平滑表面；控制笼的边线布置决定最终轮廓。
- **Mirror**：沿轴复制并焊接对称几何，适合对称建模。
- **Array**：按偏移、对象或曲线重复元素。
- **Boolean**：用并集、差集、交集组合实体；结果质量受重叠、法线和拓扑影响。
- **Solidify**：给薄表面增加厚度。
- **Bevel**：按角度或权重给边倒角。
- **Shrinkwrap**：把顶点投射到另一个表面。
- **Geometry Nodes 修改器**：运行一个节点程序来生成或处理几何。
- **Armature / Deform 类**：依靠骨架、晶格或其他变形数据改变顶点位置。

堆栈顺序会改变结果。例如先镜像再倒角，与先倒角再镜像的接缝处理可能不同。需要把程序结果变成真实网格时可 Apply，但应用后可调性下降；保留修改器通常更适合迭代。

### 雕刻与重拓扑

Sculpting（雕刻）通过笔刷直接推拉表面，适合有机形体、褶皱和高频细节。动态拓扑会在笔刷操作时增删网格密度；Voxel Remesh 按体素重建连通表面；多级细分可保留不同细节层级。高密度雕刻网格不一定适合动画或实时应用，常需 **Retopology（重拓扑）** 建立更轻、边流更适合变形的网格，再通过法线烘焙把高模细节转到低模材质纹理中。

### 曲线、文本、曲面与体积

- **Curve（曲线）**：以控制点和曲线段定义路径，可有斜角、挤出、倒角与半径；适合管线、电缆、道路、轮廓和运动轨迹。
- **Text（文本）**：可编辑文字对象，能设置字体、排版、挤出和倒角；需要网格编辑时再转换。
- **Surface（曲面）**：如 NURBS 曲面，以控制点描述平滑曲面，在产品造型和连续曲面中有用。
- **Volume（体积）**：表达烟雾、云、雾等占据空间的密度场，可用于体积着色和模拟结果。
- **Metaball（融球）**：隐式融合的场表示，适合快速有机形体，转换后才成为常规网格。

不同对象类型可以互相转换，但转换通常会丢失原类型的参数化编辑能力。

### Geometry Nodes（几何节点）

Geometry Nodes 是 Blender 的节点式几何程序系统。输入几何和参数沿节点连接流动，输出可以是网格、曲线、点云、实例或体积。它既能程序化建模，也能做散布、属性计算、程序动画、场景查询和工具化资产。

理解它的关键不是把节点当成“特效按钮”，而是看成数据流：节点读取几何及其 **属性（Attribute）**，按字段（Field）在元素上计算值，再把结果交给后续节点。点、边、面、样条等域上的属性含义不同；把一个点域选择误用于面域时，结果可能与预期不同。实例（Instance）可以先以轻量引用重复对象，需要真实独立几何时才 Realize Instances，后者可能明显增加内存。

Geometry Nodes 与传统粒子系统可以相互补充：粒子系统提供成熟的发射器、速度、力场等粒子模拟工作流；几何节点提供更通用的程序几何和属性流程。具体功能随 Blender 版本变化，不应假设所有旧粒子功能都已一一迁移为节点。

## 3. 材质、着色器、纹理与 UV

### 材质节点与表面外观

Material（材质）定义表面如何与光交互。Shader Editor 用节点把图像、程序纹理、数值和着色器组合起来，通常由 **Principled BSDF** 提供金属度、粗糙度、基色、法线、透射等常见参数；透明、发光、次表面散射等特性取决于着色器设置与渲染器支持。

着色器不是几何：粗糙度改变反射高光的扩散程度，不会把表面变粗糙；凹凸贴图近似改变着色法线，不会改变轮廓；位移可真实改变表面位置，但需要合适的几何细分和渲染设置。节点输出最终进入材质表面着色器，再由渲染器求出像素颜色。

### 纹理与 UV

纹理可以是 Image Texture，也可以是 Noise、Voronoi、Gradient 等程序纹理。**UV 坐标**把三维表面展开到二维图像上，便于指定每个表面位置对应纹理的哪个像素。UV Unwrap 会产生 UV 岛；接缝位置、拉伸、重叠和纹理分辨率都影响结果。程序纹理也可使用对象坐标、生成坐标或几何位置，不必总有 UV。

常见贴图通道包括 Base Color、Roughness、Metallic、Normal、Height/Displacement、Opacity 等。法线贴图存的是方向变化，不是颜色图；在导入外部贴图时需确认颜色空间：颜色纹理通常按 sRGB 解释，粗糙度、金属度和法线等数据贴图通常按 Non-Color 处理。

## 4. 灯光、相机与渲染

### 相机与构图

Camera（相机）决定投影、焦距/视场、传感器与景深等成像参数。透视相机会让远处物体显小；正交相机不产生这种透视缩放，常用于工程视图、图标和等距风格。相机动画可通过关键帧或约束制作。景深以焦点距离和光圈等参数控制清晰范围，但不能替代真实几何或构图。

### 灯光与世界环境

常见灯光有 Point、Spot、Area、Sun。Area Light 可模拟较大面光源，通常产生更柔和的阴影；Sun 近似远距离平行光；World 环境可提供背景颜色或 HDRI 照明。灯光能量、尺寸、颜色、衰减、阴影和曝光共同决定观感。颜色管理将线性渲染值映射到屏幕显示范围；曝光与 View Transform 会显著改变最终图像，不是几何或材质本身变了。

### Eevee 与 Cycles

- **Eevee** 是实时/光栅化取向的渲染器，交互速度快，适合预览、动画和需要实时反馈的场景。其阴影、反射、全局照明等效果依赖实时渲染实现与设置，不能简单等同于完整路径追踪。
- **Cycles** 是路径追踪渲染器，通过采样光线路径估计光照传输，适合更真实的间接光、反射、折射和复杂照明；代价是采样导致噪声，需要足够样本、降噪和显存/时间预算。

二者共享很多材质和场景概念，但渲染特性、节点支持与设置并非处处相同。应按目标画质、时间、交互需求和硬件选择，而不是认为一个永远优于另一个。

### 渲染输出

渲染前需要设置分辨率、帧率、帧范围、采样、输出格式、色彩管理和渲染层。Still Render 输出单张图；Animation Render 输出帧序列或视频。长动画通常优先保存逐帧图像序列，因为中途失败后可从缺失帧续跑；视频编码适合最终交付，不利于局部重渲染。Render Layers 与 View Layers 可把对象、光照或效果分开输出，再进入合成器组合。

## 5. 动画、骨架、约束与驱动

### 关键帧与曲线

Keyframe（关键帧）记录某一时刻某属性的值，例如位置、旋转、材质参数。Blender 在关键帧之间插值；Dope Sheet 管理关键帧的时间位置，Graph Editor 查看和编辑 F-Curve（函数曲线）的数值与切线。插值类型决定匀速、缓入缓出或阶跃变化。关键帧可以作用于对象、形状键、骨骼、材质等属性。

### 骨架、蒙皮与形状键

Armature（骨架）包含骨骼层级；Pose Mode 调整姿势，动画通常驱动骨骼变换。网格通过顶点组权重绑定到骨骼，权重表示每个骨骼对顶点变形的影响。权重涂抹、骨骼命名、骨骼轴向和约束共同决定变形质量。Shape Keys（形状键）以不同顶点位置表示表情或形变，可用关键帧、驱动器或骨骼控制。

### 约束与驱动器

Constraint（约束）用关系规则控制对象或骨骼，如跟随目标、复制变换、追踪朝向、限制位置/旋转、沿路径运动等。约束一般不直接重写网格，而是改变求值后的变换。Driver（驱动器）用表达式或属性关系控制另一个属性，例如用一个旋钮控制多个对象的开合。约束适合关系，驱动器适合可计算的参数映射；复杂依赖要避免循环引用。

### 动画剪辑与角色流程

Action 是一组可复用动画数据；NLA Editor 可把动作片段排列、混合和循环。角色流程通常包括骨架搭建、蒙皮权重、控制器/约束、动作制作与清理。Blender 能完成这些环节，但大型影视团队也常与专门的绑定、动捕、资产管理和协作系统搭配使用。

## 6. 物理模拟与粒子系统

Blender 的物理模块让几何随时间受力、碰撞或场约束。模拟结果依赖时间步长、尺度、碰撞几何、质量/阻尼和缓存设置；它不是“按一帧自动算出正确物理”的黑盒。复杂场景要先用低分辨率、短帧范围验证，再提高质量。

### 常见模拟类型

- **Rigid Body（刚体）**：处理硬物体的平移、旋转和碰撞。主动刚体参与动力学，被动刚体通常作为静态碰撞体。适合掉落、堆叠、破碎后的块体运动。
- **Soft Body（软体）**：以点/边弹性和约束近似柔软网格的形变，适合弹性物体、果冻等；大幅折叠或复杂布料往往更适合专门布料设置。
- **Cloth（布料）**：模拟网格在拉伸、弯曲、剪切、阻尼、空气阻力和碰撞作用下的运动。网格拓扑、碰撞厚度、质量与自碰撞成本影响稳定性。
- **Fluid（流体）**：Mantaflow 工作流可做液体、气体/烟雾等网格化模拟。液体通常要区分 Flow（流入/流出/几何初始液体）与 Domain（模拟域），还涉及分辨率、黏度、表面网格和缓存；烟雾还需密度、温度、燃料等属性与体积材质。
- **Smoke/Fire（烟火）**：作为气体流体域中的密度、温度、燃料等场随时间演化，网格分辨率越高，细节与内存、计算成本通常越高。
- **Dynamic Paint**：让对象接触或移动影响画布上的颜色、湿度或位移等结果，可用于脚印、积水和表面痕迹。
- **Force Fields（力场）**：风、涡旋、吸引/排斥等影响粒子及部分模拟系统；具体可影响哪些系统取决于模拟类型与版本。

模拟器会写入缓存（Cache），以避免每次重算并保持播放一致。修改参数后通常要清理或重烘焙相应缓存。缓存的存储位置和是否随 `.blend` 一起打包需要明确管理。

### 粒子系统：粒子是什么

粒子不是一种固定形状的物体，而是大量轻量的 **运动样本/实例位置**。每个粒子通常带有出生时间、寿命、位置、速度、大小、旋转等状态；渲染时可以显示为小点，也可以在每个粒子位置放置一个对象、集合或毛发几何。因此“发射了 10,000 个粒子”不等于创建了 10,000 个可编辑网格对象。

经典 Particle System 常通过对象的 Particle Properties 设置发射器和渲染方式。它尤其适合理解点状发射、对象散布、毛发和受力运动。不同 Blender 版本中经典粒子功能的界面和未来维护状态可能变化；若目标是新的程序化散布或自定义属性处理，也可考虑 Geometry Nodes，但两者的语义、模拟能力和参数组织不相同。

#### 发射器与粒子生命周期

粒子一般由某个网格表面或体积发射。关键参数包括：

- **Emission Number**：发射数量。数量多会增加模拟与渲染负担。
- **Frame Start / End**：粒子在哪段帧区间出生。窄区间是瞬时爆发，长区间是持续喷射。
- **Lifetime**：粒子存活帧数；寿命结束后粒子消失。
- **Emit From**：从顶点、面等位置发射；面发射还能按面面积或分布方式影响密度。
- **Distribution**：决定发射位置的空间分布。随机分布容易自然但可能聚簇；规则分布更均匀但显得人工。
- **Seed**：随机种子；改种子可获得不同随机布局，便于复现和调整。

粒子从发射点获得初速度。初速度可包含法线方向、对象速度或随机扰动；随后重力、风、涡旋等力场改变速度，再由速度积分得到位置。可以把一帧更新粗略看作：`新速度 = 旧速度 + 加速度 × 时间步长`，`新位置 = 旧位置 + 新速度 × 时间步长`。真实模拟还会加入碰撞、阻尼和求解器细节。

#### 粒子类型和渲染/实例化

粒子可作为 Emitter（发射后运动的粒子）或 Hair（附着于表面的毛发/曲线状粒子）使用。粒子的呈现方式可能是 Halo/点状表现、对象实例、集合实例或毛发几何等，具体选项取决于版本及渲染器。对象/集合实例的局部原点、朝向、尺度和粒子旋转设置会影响排布。若实例对象轴向不对，即使粒子位置正确，草叶、碎片或道具也会侧躺。

常见用途：

- 用实例化草叶、石子、树叶做场景散布；
- 用粒子速度和随机旋转生成碎屑、火花、尘埃；
- 用 Hair 粒子生成毛发、草和短绒，再配合梳理与材质；
- 用粒子路径或粒子状态驱动其他效果。

需要大量相同物体时，实例比复制成独立网格节省内存；但碰撞、阴影、透明材质和过高实例数仍会增加计算与渲染成本。

#### 力场、碰撞与粒子之间的相互作用

粒子运动可被重力、风、涡旋、吸引/排斥等力场影响。场强、衰减、作用范围与粒子质量等决定响应。碰撞对象需要启用相应物理碰撞设置，粒子才能与其发生反弹、滑动、减速或粘附等交互；反弹系数和摩擦会影响结果。场景尺度与碰撞厚度不匹配时，粒子可能穿透薄面或抖动。

粒子可以和其他系统耦合，例如粒子推动或触发刚体、用粒子速度驱动运动效果。但“能够连接”不等于每种求解器都严格双向耦合；应根据具体功能验证数据传递方向和更新顺序。工程上通常先单独验证发射、再加力场、再加碰撞，逐层排查。

#### 粒子属性、权重与控制

粒子系统不仅有位置，还能使用速度、年龄、大小、旋转等状态；不同系统可提供不同属性。发射权重/顶点组可控制哪些表面位置更容易发射、粒子速度或长度如何变化。顶点组权重可视为从 0 到 1 的空间遮罩：0 处不发射或作用弱，1 处作用强，中间值做渐变。

在程序化流程中，可进一步按位置、速度、年龄或随机值筛选实例、改变尺度/材质、驱动颜色和其他几何。传统粒子属性与 Geometry Nodes 字段/属性不是同一套数据接口；要跨系统传递时，需明确是在对象、网格、实例还是缓存层级上读取，并核对该版本支持的接口。

### 从你的 Houdini 思路看 Blender 的对应概念

你描述的流程是：流体驱动粒子并产生碰撞 → 用 Vellum 气球约束做软体 → 给部分几何建组并增加 temperature → 通过属性传递更新温度 → 温度超过阈值后删除几何，并用组或约束抑制一次删得过多。这个思路可以拆成几类通用操作：**模拟数据驱动几何、属性随时间传播、阈值选择、局部删除/约束**。

在 Blender 中可以找到相近的构件，但不能假设有与 Houdini 一一对应的同名节点或完全相同的数据流：

1. 用 Mantaflow 做流体/烟火，用粒子系统或 Geometry Nodes 生成/处理点与实例；粒子和流体间是否按预期互相驱动，要具体验证版本能力与求解顺序。
2. 用 Cloth 或 Soft Body 处理弹性变形；几何节点也能做参数化构造，但不是自动等同于 Vellum 的约束求解器。
3. 温度可作为自定义属性/模拟状态的一部分。若需逐帧累积或传递，必须使用支持时间状态的模拟方案或将结果烘焙缓存；单纯普通几何节点字段通常是对当前输入的求值，不会天然记住上一帧温度。
4. 阈值筛选可由属性比较产生选择，再控制删除、隐藏、缩放或材质变化。删除过多时，可额外加入空间组、邻域条件、速率限制或缓冲区，但这些规则要根据具体几何语义设计。

最重要的差异是：Houdini 的 SOP/DOP/Vellum 流程强调整套节点网络与显式属性流；Blender 把几何节点、粒子、物理模拟、对象属性和缓存分散在不同系统里。可以实现相似的视觉或几何效果，但复杂耦合流程未必能用同样简洁的方式搭建，适合先做小规模原型验证。

## 7. 合成、视频剪辑与 2D 工具

### Compositor（合成器）

合成器把渲染层、图像、遮罩和效果节点组合起来，可做颜色调整、模糊、畸变、雾效、遮罩合成等。使用 Cryptomatte 或对象/材质索引等通道，可在渲染后按对象或材质选择区域。合成适合图像后处理，不适合修补本应由几何、灯光或材质解决的结构问题。

### Video Sequencer（视频序列编辑器）

VSE 可将视频、图像序列、音频和场景渲染结果排在时间线上，进行剪切、转场、变速、混合、字幕/效果和音画组织。它能满足基础剪辑和预览，不是专业非线性剪辑软件的全部替代品；高分辨率素材、复杂音频和交付规范仍可能需要专用工具。

### Grease Pencil 与 2D/3D 混合

Grease Pencil 可在三维场景中绘制和组织笔画，用于二维动画、分镜、标注或 2D/3D 混合制作。它与普通网格不同，有自己的笔画/图层/材质语义；版本更新可能改变其对象与绘制工作流。

## 8. 资产、脚本、插件与工程管理

### Asset Browser 与复用

Asset Browser 可浏览标记为资产的材质、对象、集合、动作、节点组等。资产可通过 Asset Library 组织复用；分类、预览图和清晰命名能让团队快速找到内容。资产仍然依赖外部贴图、字体、缓存等资源时，需要正确打包或维护路径。

### Python 与扩展

Blender 内置 Python API，可通过脚本批量创建对象、修改属性、渲染、导入导出和搭建自动化流程。脚本能够访问场景数据，但也受当前上下文、模式和版本 API 影响；大批量自动化应显式设置活动对象、选择集、帧、渲染器和输出路径，并记录 Blender 版本。

插件/扩展可增加建模工具、导入器、渲染集成等能力。安装前要看其维护状态、兼容版本和许可；外部扩展不是 Blender 核心能力的一部分，版本升级后可能失效。

### 导入、导出与互操作

常用交换格式包括 FBX、glTF/GLB、USD、OBJ、Alembic、STL、PLY 等，具体可用格式取决于内置支持和扩展。不同格式保存的内容不同：几何、法线、UV、材质、骨骼、动画、实例和单位未必全部保留。导出前要明确目标应用所需的坐标轴、单位、三角化、贴图打包、骨骼命名、动画范围和材质模型，并用目标软件重新导入检查。

### 工程组织与可复现

`.blend` 可包含对象、材质和节点等数据；外部图片、缓存、字体、视频通常仍可能是外部路径。相对路径和 Pack Resources 可减少丢失资源，但大缓存也会显著增大工程。建议按场景、集合、资产和输出版本建立命名规则，保存增量版本，标注 Blender 版本、渲染器、插件、随机种子和关键模拟缓存信息。多人协作可通过链接/追加（Link/Append）复用资产，但要理解链接数据与本地副本的差别。

## 功能分类流程图与学习路径

先用下面的功能树定位“该问题属于 Blender 的哪一层”。同一个项目通常会经过多个分支，但每个分支处理的对象不同：几何节点处理几何和属性，材质节点处理光照响应，模拟系统处理随时间变化的状态。

```text
Blender
├── 场景数据：Scene / Collection / Object / Data-Block / View Layer
├── 几何创建
│   ├── 网格编辑、修改器、雕刻、重拓扑
│   ├── 曲线、文本、曲面、体积
│   └── Geometry Nodes：字段、属性、点云、实例、程序化工具
├── 外观
│   ├── 材质与 Shader Nodes
│   ├── UV 与图像纹理
│   └── 法线、位移、体积着色
├── 时序
│   ├── 关键帧、F-Curve、Action、NLA
│   ├── 骨架、蒙皮、形状键、约束、驱动器
│   └── Grease Pencil 与 2D/3D 动画
├── 模拟
│   ├── 粒子、毛发、力场、碰撞
│   ├── 刚体、软体、布料
│   ├── 流体、烟火、Dynamic Paint
│   └── 缓存、烘焙、逐帧求解
├── 成像
│   ├── 相机、灯光、World、色彩管理
│   ├── Eevee（实时取向）/ Cycles（路径追踪）
│   └── Render Layers、分层输出、合成器
├── 后期
│   ├── Compositor：遮罩、颜色、效果、通道合成
│   └── VSE：图像序列、视频、音频、剪辑
└── 复用与交付
    ├── Asset Browser、Link / Append
    ├── Python API、脚本、扩展
    └── glTF/GLB、FBX、USD、OBJ、Alembic、STL/PLY 等
```

从需求到交付的主流程可以压缩成一条检查链。模拟和动画不是所有项目都必需的分支，但一旦加入，就应在渲染前完成缓存验证：

```text
需求/参考图/输出平台
          ↓
场景初始化：单位、坐标、Collection、相机、帧率
          ↓
几何：网格/曲线/雕刻/修改器/Geometry Nodes
          ↓
材质：UV、纹理、Shader、法线与位移
          ↓
动画分支 ──→ 关键帧/骨架/约束/驱动器
          │
模拟分支 ──→ 粒子/布料/刚体/流体 → 缓存与烘焙
          ↓
灯光、World、相机、色彩管理、Eevee 或 Cycles 预览
          ↓
Render Layers / 帧序列
          ↓
Compositor 与 VSE 后期
          ↓
复核资源路径、单位、材质、动画和格式
          ↓
导出图像/视频/GLB/FBX/USD/其他目标格式
```

推荐的学习顺序不是把所有按钮逐个背下来，而是每层完成一个小闭环：先做“一个物体能被看见”，再做“一个物体能被修改”，然后做“一个物体能动/能模拟”，最后做“结果能稳定输出”。对应路径是：

```text
界面与数据模型
      ↓
网格 + 对象变换 + Collection
      ↓
修改器 + 材质节点 + UV + 相机灯光
      ↓
关键帧 + 骨架/约束（需要动画时）
      ↓
粒子/布料/刚体/流体（一次只学一种模拟）
      ↓
Geometry Nodes 与属性流（程序化和批量资产）
      ↓
渲染分层 + 合成/VSE
      ↓
Python 自动化 + 资产管理 + 目标格式交付
```

## 9. 一个从想法到交付的典型工作流

1. 明确输出目标：单张图、动画、实时资产、仿真缓存还是可编辑场景；确定分辨率、帧率、格式和目标软件。
2. 用 Collection 整理场景，先搭相机、尺度、主体与构图；避免过早雕刻细节。
3. 选择合适表示：网格编辑适合明确拓扑，曲线适合路径，雕刻适合有机细节，几何节点适合重复和参数化结构。
4. 建立材质与 UV；先验证颜色空间、法线方向和渲染器兼容。
5. 设置灯光与渲染预览；先低采样、低分辨率检查构图和噪声，再提高质量。
6. 若有动画，先验证关键帧、骨架、约束和动作，再加入昂贵模拟；模拟从简化几何和短帧段开始。
7. 烘焙所需模拟缓存，检查时间范围、帧率和资源路径。
8. 输出分层图像或帧序列，进入合成器/VSE；最终交付前在干净环境或目标软件中复核文件。

## 10. Blender 的强项与边界

Blender 的优势是覆盖面广、场景数据可脚本化、程序化几何和渲染能力丰富，且可在同一工程中完成建模、动画、模拟、合成和基础剪辑。它适合个人创作、研究原型、自动化合成数据生成、可视化和很多中小型制作流程。

边界也值得提前知道：大型协作制作中的资产版本、权限、审阅和渲染农场管理通常需要额外流程；高度耦合的工程模拟未必等同于专门 DCC/CAE 求解器；不同交换格式对节点材质、模拟、骨架和实例的支持不一致；版本升级、插件和缓存会影响可复现性。选工具时应按任务约束，而不是只按功能列表判断。

## 小结

理解 Blender 的关键是把它看成一个场景数据系统和一套制作工具链：对象引用数据块，修改器与节点生成几何，材质描述光照响应，动画和模拟让属性随时间变化，渲染器把场景转成图像，合成与序列编辑器完成后期，资产、脚本和格式互操作负责复用与交付。

粒子系统则是在发射器上生成随时间更新的轻量粒子状态，再由力场和碰撞影响运动，并可把点呈现为对象实例、毛发或其他效果。粒子的发射分布、寿命、速度、属性遮罩、求解缓存和渲染表示都需要分别理解；它既不是“很多个独立物体”，也不只是动画特效。

## QA

### Blender 的粒子系统和 Geometry Nodes 是一回事吗？

不是。粒子系统围绕粒子生命周期、发射、运动、力场和碰撞组织；Geometry Nodes 是通用几何数据流与属性计算系统。两者可在工作流中协作，但不能假设接口和求解语义完全相同。

### 为什么修改模拟参数后结果没有变化？

模拟可能仍在使用旧缓存。清除或重新烘焙对应缓存，并检查帧范围、缓存位置、求解分辨率和依赖对象是否正确。

### 先学哪个渲染器？

先用 Eevee 熟悉材质、灯光和构图的快速反馈，再用 Cycles 理解路径追踪、间接光与采样噪声。若项目有明确实时或高保真需求，则以目标渲染器为主，并尽早验证材质兼容。
