# LLM 入门：从会续写到会解决问题

如果你已经懂 token、attention 和 Transformer，但还没把预训练、SFT、奖励、GRPO 和推理模型串起来，可以把 LLM 入门看成一张六阶段地图。它回答六个连续的问题：模型怎样生成文字？基础能力从哪里来？怎样学会按指令回答？什么叫“好答案”？怎样利用这个评价继续训练？最后怎样判断训练真的有效？

这六个阶段是**学习顺序，不是所有模型都必须执行的固定流水线**。真实项目可能跳过某一步、把几步合并，或使用不同的训练方法。

## 一、Transformer：模型怎样生成下一个 token

文本先被切成 token，再转换成向量。decoder-only Transformer 用因果注意力读取当前位置之前的内容，最后输出词表中每个候选 token 的分数（logits）。把分数变成概率后，模型选出一个 token，接回输入末尾，再重复同样的过程。

例如输入“北京是中国的”，模型可能给“首都”较高概率。完整回答不是一次性从模型里取出的，而是许多次“根据已有前缀预测下一 token”的结果。采样温度、top-k 等设置会改变选择方式，但不会改变模型参数。

![自回归生成：上一步生成的 token 接回输入，继续预测下一步](https://jalammar.github.io/images/xlnet/gpt-2-autoregression-2.gif)

学完这一阶段，你应该能把 token、attention、logits、概率和采样放到同一条链上。下一步的问题是：模型凭什么知道哪些 token 更可能出现？

## 二、预训练：从大量文本获得基础能力

预训练就是让模型在大量文本上反复练习下一 token 预测：给它前文，让它预测真实后文；预测错了，就调整参数。经过足够多的数据和更新，模型会学到语言规律、常见事实、代码模式以及一些解决问题的结构。

这里的关键不只是“数据越多越好”。数据去重、质量、语言和代码比例、训练数据与测试集是否重叠，都会影响结果。读预训练工作时，可以先问三件事：数据从哪里来？怎样清理和混合？模型在没有见过的数据上是否仍然有效？

预训练得到的是一个会续写的基础模型，不等于一个总能听懂指令的助手。它可能知道很多内容，却不稳定地执行“只输出 JSON”或“用三步解释”。这就需要下一阶段。

## 三、SFT：让模型学会按要求回答

SFT（supervised fine-tuning，监督微调）仍然训练 token 预测，但训练样本变成了“指令—示范回答”。模型看到问题和一份人工准备的答案，学习提高这份答案中各个 token 的概率。

例如基础模型面对“用三步解释梯度下降”，可能写出一段相关文字；SFT 样本会示范怎样分成三步、面向什么读者、使用什么格式。模型因此更像一个会遵循任务说明的助手。

SFT 的局限是：同一道题往往有多份都不错的回答，而训练数据通常只给其中一份示范。它能教“应该怎样答”，却不容易表达“这两份都正确，但第二份更清楚”。下一步需要显式的评价信号。

## 四、奖励与强化学习：怎样表达“这个答案更好”

这一阶段先建立三个直觉：**策略**是负责生成答案的当前模型；**采样**是让它实际写出一个或多个答案；**奖励**是对答案质量的评价。奖励可以来自人类偏好训练出的奖励模型，也可以来自可验证的结果，例如代码测试是否通过、数学最终答案是否正确。

以“写一个排序函数”为例，同一问题可以采样几份代码。通过测试的代码获得较高奖励，未通过的获得较低奖励。训练算法再利用这些差异，让高奖励答案以后更容易出现。

奖励不是天然客观的。如果测试不完整，模型可能学会钻测试漏洞；如果人工偏好有偏差，奖励模型也会继承这种偏差。因此要区分两件事：**奖励定义了什么叫好，优化算法决定怎样利用这个信号**。PPO、GRPO 解决的是后者。

## 五、PPO 与 GRPO：根据评价更新模型

PPO 和 GRPO 都属于后训练优化方法。它们的前提是：模型已经能生成回答，并且我们已经有办法给回答打分。

GRPO（Group Relative Policy Optimization）的直觉是：针对同一道题生成一组回答，在组内比较它们的奖励，再让相对较好的回答更可能被生成。例如四份回答的奖励是“高、低、高、低”，GRPO 可以用这一组的相对差异形成基线，而不必单独训练 PPO 中常见的价值模型。它仍然需要奖励函数，也不是凭空产生“推理能力”。

![PPO 与 GRPO 的训练结构对比](https://arxiv.org/html/2402.03300v3/GRPO.svg)

*图 3：取自 [DeepSeekMath](https://arxiv.org/abs/2402.03300) 的 GRPO 对比图。先看两种方法共有的“生成—打分—更新”链条，再看 GRPO 如何利用同一问题的一组回答形成相对比较。图为论文原图；本文不展开目标函数推导。*

学习到这里，重要的不是背下缩写，而是能回答：奖励从哪里来？一组回答为什么有用？策略更新怎样避免一步走得太远？这些问题比“GRPO 是否等于推理模型”更接近方法本身。

## 六、推理模型训练与评估：怎样知道它真的变强

真实训练还需要把数据、奖励、更新和评估连成闭环。数学和代码任务有时能用最终答案或测试结果自动验证；开放式任务则更难，需要人工评价、多个评测器或其他交叉检查。

评估不能只看一个总分。至少还要问：模型是否能解决没见过的题？换一种表述或提高难度后是否仍然有效？它多花了多少 token 和时间？训练集与测试集是否有重复？如果奖励变高但独立测试不变，可能只是学会了刷奖励的捷径。

因此第六阶段不是再记一个新算法，而是学会做可复现的对照：固定训练前基线、独立测试集、清楚的验证器和失败案例。 [DeepSeek-R1](https://arxiv.org/abs/2501.12948) 是使用可验证奖励研究推理训练的一个具体案例，但不代表所有推理模型都采用同一方案。

## 把六阶段放回一张图

可以用一句话记住它们的关系：

> **Transformer 负责生成；预训练提供基础能力；SFT 教会模型遵循指令；奖励定义“好”；PPO/GRPO 利用奖励更新策略；评估检验改进是否迁移。**

如果你的目标是学习 GRPO，建议先掌握第一至第四阶段的直觉，再读 GRPO 的采样、组内相对奖励、策略约束和评估实验。这样你看到的是一条完整链路，而不只是一个算法缩写。
