# LLM 入门：从预测下一个词到训练推理模型

如果你已经听过 Transformer、预训练、SFT 和 GRPO，却总觉得它们像一堆不相干的名词，可以先把 LLM 的学习路线想成六个问题：**模型怎样写字？基础能力从哪里来？它怎么学会按要求回答？好回答由谁判断？怎样利用判断结果继续训练？最后如何确认它真的变强？**

本文按这六个问题建立大脑里的地图，不推公式。这里的“六阶段”是**建议的学习顺序**：许多真实模型的训练流程并不完全相同，也可能省略或替换某些步骤。

## 第一阶段：Transformer 与下一个 token

先从模型最基本的动作开始。输入句子会被切成 token（一个字、词或词的一部分），转换成向量；decoder-only Transformer 利用因果注意力读取此前的 token，最后给词表里的每个候选 token 一个分数。分数经过 softmax 变成概率，模型选出下一个 token，接到输入末尾，再重复一次。

例如输入“北京是中国的”，下一步可能给“首都”较高概率。模型完成一段回答，就是把这种**下一 token 预测**重复许多次；它不是一次性把整篇文字从网络里取出来。注意力决定当前位置能参考哪些前文，但“参考过”不等于“事实一定正确”。

![GPT-2 把上一步生成的 token 接回输入，继续预测下一步](https://jalammar.github.io/images/xlnet/gpt-2-autoregression-2.gif)

*图 1：Jay Alammar 在 [The Illustrated GPT-2](https://jalammar.github.io/illustrated-gpt2/) 中绘制的自回归生成示意（原图，页面标注 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/)）。看图时只抓一件事：**输出 token 会成为下一步输入的一部分**。这是 GPT-2 的教学示例，不表示今天所有 LLM 的结构细节都相同。*

学完这一阶段，你应该能解释“token、注意力、logits、采样”各在什么位置，以及为什么改采样方法会改变回答，却不等于重新训练模型。[原始 Transformer 论文](https://arxiv.org/abs/1706.03762) 和 [The Illustrated GPT-2](https://jalammar.github.io/illustrated-gpt2/) 可作为进一步阅读。

## 第二阶段：预训练，基础能力从哪里来

有了能预测下一个 token 的网络，还要让它在大量文本上反复练习：给出前文，预测真实的后文；预测错了就调整参数。这是语言模型**预训练**的核心。模型因此学到词语搭配、写作方式、很多事实和一些解决问题的模式，最终得到能广泛续写的基础模型。

训练材料不只是“越多越好”。重复、错误或泄漏测试题的数据会让评估变得虚高；代码、数学、不同语言的比例也会改变模型擅长的任务。所以读一篇预训练论文时，可以先问：**数据从哪来，怎样清理？训练目标是什么？模型在未见过的数据上表现怎样？**

预训练模型的能力与“聊天时愿意照着你的指令回答”是两回事。它见过问答文本，可能会答题；但对于“请只输出 JSON”这样的要求，不一定稳定遵守。这就引出下一阶段。[GPT-3 论文](https://arxiv.org/abs/2005.14165) 展示了大规模语言模型的广泛任务能力；具体模型的数据与训练设置仍须看各自论文。

## 第三阶段：SFT，让模型学会按要求回答

SFT 是 *supervised fine-tuning*，即**监督微调**。数据通常是一组“输入指令—示范回答”。训练时，模型看到输入和正确示范，学习提高示范回答各 token 的概率。它仍在做 token 预测，只是练习材料从一般文本变成了更明确的任务示范。

例如，基础模型可能看到“用三步解释梯度下降”后写出与梯度下降有关的任意文字；SFT 数据会示范“三步、面向读者、直接回答”的格式。它帮助模型学会回答方式、角色和输出格式，也可以加强某些具体任务能力。

但一条指令可能有许多都不错的回答。SFT 通常给模型一个或少数几个示范，不容易明确表达“这两个回答都能用，但第二个更好”。这时就需要下一阶段的比较与奖励。

## 第四阶段：奖励与强化学习的基本角色

先不急着学 GRPO 公式，分清三个角色更重要：**策略**是当前负责生成回答的模型；**采样**是让它对一道题实际写出一个或多个回答；**奖励**是对回答质量给出的评价。奖励可以来自人工偏好训练出的奖励模型，也可以来自可验证的结果，例如代码测试是否通过、数学最终答案是否正确。

以“写一个排序函数”为例：同一问题可生成几份代码。测试通过的回答得到较高奖励，未通过的较低。训练算法会利用这些结果调整模型，让高奖励回答以后更容易出现。这比只模仿一份标准答案灵活，但也带来新风险：如果测试不完整，模型可能学会**通过测试的捷径**，而不是写出真正稳健的程序。

图 2 中的奖励模型就是一种做法。要特别区分**奖励是什么**和**怎样用奖励更新模型**：前者是评价标准，后者才涉及 PPO、GRPO 等算法。评价标准有偏差时，换一个优化算法也不会自动修好目标。

## 第五阶段：PPO、GRPO 等后训练算法

现在 GRPO 的位置就清楚了：它是“已经有模型、能生成回答、也能评价回答”之后，**怎样利用奖励更新模型**的一种方法。GRPO 全称 *Group Relative Policy Optimization*，核心直觉是针对**同一问题生成一组回答**，比较组内奖励，再让相对较好的回答更可能被生成。

例如一道题采样四份解答，奖励分别较高、较低、较高、较低。GRPO 使用同组表现作为相对基线，而不是单看某份答案得了多少绝对分。DeepSeekMath 论文将它与 PPO 对照：该实现不另训练 PPO 中常见的价值模型，而从组内分数估计基线；训练目标还包含限制更新幅度的机制。[DeepSeekMath §4.1](https://arxiv.org/html/2402.03300#S4.SS1)

![DeepSeekMath 论文中 PPO 与 GRPO 的训练结构对比](https://arxiv.org/html/2402.03300v3/GRPO.svg)

*图 3：取自 [DeepSeekMath 论文 Figure 4](https://arxiv.org/html/2402.03300#S4.F4)。先找两边共同的“采样回答—打分—更新策略”，再看 GRPO 如何利用**同组回答的奖励**形成比较基线。这是论文原图；初学时不需要逐个读懂图中的数学符号。*

PPO 和 GRPO 不负责告诉模型“什么叫好”，它们使用已经定义的奖励。两者也都不是“推理能力”的同义词：如果题目过于单一、奖励有漏洞，模型仍可能只学会针对训练题的技巧。到这一步，建议你能回答“策略、参考模型、奖励、组内比较各做什么”，再深入目标函数。[DeepSeekMath 论文](https://arxiv.org/abs/2402.03300) 是 GRPO 的主要原始资料。

## 第六阶段：推理模型训练与评估实践

把前面几阶段放到真实项目里，还差一个关键问题：**模型是真的更会解决新问题，还是只把训练奖励刷高了？** 推理模型通常要认真设计题目来源、答案验证器、训练与测试的隔离，以及失败案例分析。数学和代码任务有时能检查最终答案；开放式任务则更难得到可靠的自动奖励。

评估也不能只报一个正确率。可以同时看：未见过的题目是否答对；换个题目措辞或难度后是否还行；生成更长的回答多花了多少时间和 token；错误答案是否伴随看似合理的推导。若训练集和测试集出现相同或近似题目，漂亮的数字可能只是记忆或数据泄漏。

这一阶段不是再记一个新算法名，而是把**数据—训练—验证—成本**连成闭环。用一份可检查的训练前基线，再与训练后模型在同一独立测试集上比较，才比较容易判断改进是否成立。关于可验证奖励如何用于推理训练，可进一步读 [DeepSeek-R1 论文](https://arxiv.org/abs/2501.12948)；它是具体实例，不代表所有推理模型都采用同一配方。

## 一张学习地图，接下来怎么读

回看六阶段：**1 是网络怎样生成；2 是从大量数据获得基础能力；3 是学会按指令回答；4 是定义并取得评价信号；5 是用 PPO、GRPO 等方法根据评价更新模型；6 是检验改进能否迁移到新问题。**

如果你已经懂 Transformer，想学习 GRPO，可以先补上 SFT、采样、奖励和策略更新的直觉。这样读 GRPO 时，你关注的会是“它如何比较一组回答、如何控制更新”，而不只是记住一个缩写。
