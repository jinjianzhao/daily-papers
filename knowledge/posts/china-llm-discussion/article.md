# 中国 LLM 讨论纪要：反蒸馏、算力竞争与 AI for Science

> 本文解读来源于 Startup Research 的微信文章《中国 LLM 讨论纪要》（2026 年 11 月 3 日发布，整理 10 月初的讨论）。文章包含访谈观点、行业判断和部分未公开验证的数据；本文会明确区分事实、观点与推测，不构成投资建议。

## 先说这篇文章讨论的是什么

这不是一篇介绍某个模型网络结构的论文，而是一份关于中国大语言模型（LLM）产业竞争的讨论纪要。它试图回答几个问题：

1. 国产模型为什么越来越难以通过“蒸馏”追赶前沿闭源模型？
2. 训练规模扩大后，真正的瓶颈是模型结构、数据，还是算力和验证环境？
3. 中国模型公司的竞争优势来自哪里，独立模型公司能否长期生存？
4. 在 coding 之后，AI for Science、机器人和空间理解是否会成为下一批重要场景？

这里的“LLM 竞争”不只是比较一次 benchmark 分数，而是比较一整套系统：预训练数据、后训练方法、GPU 集群、工具调用环境、可验证反馈、产品收入，以及继续购买算力的能力。

## 一、先理解几个关键词

### 蒸馏是什么

知识蒸馏（distillation）是让一个较小或较新的学生模型学习教师模型的输出。最简单的形式是：给教师和学生同一个问题，让学生拟合教师给出的答案或 token 概率。推理模型中还可能尝试学习教师的长链推理、工具调用轨迹或最终结果。

它的价值在于，学生不必从零探索所有能力，可以把教师已经找到的解法压缩到自己的参数中。但蒸馏依赖一个前提：你能稳定地获得足够高质量的教师反馈。

### 反蒸馏是什么

反蒸馏不是一种训练算法，而是教师模型提供方采取的一组防护措施，例如拒绝回答特定探测问题、降低推理细节、改变采样分布、检测批量调用，或对高风险 API 请求限流和封禁。文章认为，前沿模型开始更积极地采取这些措施，导致完整推理轨迹和高质量反馈更难获得。

### RSI 是什么

文中的 RSI 指 Recursive Self-Improvement（递归式自我改进）：模型或模型驱动的 agent 参与提出实验、生成数据、运行验证和改进下一版模型，形成自动化反馈闭环。它不等于“模型自己凭空变聪明”，关键是每一轮是否有可靠的验证器或真实结果告诉系统哪里做对了、哪里做错了。

### Verification 为什么重要

强化学习需要奖励，蒸馏需要教师反馈，自动改进需要判断改进是否有效。这个判断就是 verification（验证）。代码有编译、单元测试和 CI/CD；数学有形式化证明或答案检查；但药物发现、营销创意、真实机器人动作等任务往往没有即时、廉价且客观的验证器，因此更难自动迭代。

## 二、反蒸馏让“追赶前沿模型”变贵了

文章的第一条主线是：国产模型过去可以通过调用前沿模型、收集答案和推理轨迹来快速获得训练数据；现在这种方式的成本和不确定性都在上升。

### 为什么成本会上升

一个简单问答的蒸馏成本并不只包含一次 API 调用。为了得到稳定训练集，通常还需要：

- 对同一问题多次采样，过滤低质量答案；
- 设计探测问题，避免学生只记住表面模板；
- 对长推理、工具调用和代码轨迹做结构化存储；
- 用其他模型或人工检查答案；
- 处理服务限流、封禁和输出策略变化。

教师输出越少、越短或越不稳定，就越需要更多调用和筛选。文章给出的“成本上升 5—10 倍，甚至 20 倍”是讨论中的估计，并非公开审计数据，应该作为行业判断而不是精确事实。

### 为什么“把问题拆成很多小问题”不能完全替代

一种替代方案是把一个复杂问题拆成十个简单问题，分别询问前沿模型，再由另一个模型拼接答案；也可以只拿到摘要，再让模型反向补出可能的推理过程。这些办法可以获得部分监督信号，但它们可能丢失原始推理中的关键依赖，生成的“解释”也不一定是教师真正使用过的过程。因此它们通常比直接获取完整、高质量轨迹更弱。

### coding 和 agent 为什么仍然容易蒸馏

代码任务有相对明确的验证方式：编译、测试、静态检查、运行结果。Agent 任务也可以保存 trajectory（行动轨迹），并通过环境状态判断某一步是否成功。这使得学生模型即使看不到教师的内部思考，也能根据最终结果筛选有用样本。

相反，空间理解、视频生成、科学发现和真实世界机器人任务，很多质量标准难以从公开接口中完整提取。文章因此判断，下一阶段竞争会从“谁更会生成文字”转向“谁拥有更好的环境、数据和验证闭环”。

## 三、模型规模扩大后，瓶颈从研究员转向算力和实验闭环

### 训练规模带来的变化

文章讨论了从十亿级、百亿级模型逐步扩展到万亿级甚至更大规模模型时的组织变化。模型越大，一次实验所需的 GPU 时间越长；研究团队同时能尝试的实验路线数量，越来越受总算力限制。

可以把它想成实验室：

- 研究员决定要试哪些方案；
- GPU 集群决定这些方案能否并行；
- 数据和验证环境决定每个方案能否被可靠比较。

因此，增加研究员数量并不会自动带来同比例进步。如果每个人都没有足够算力跑完实验，许多想法只能停留在设计文档里。

### 数据瓶颈和算力瓶颈的关系

文章提到公开高质量文本数据的规模大约在数十万亿 token 量级，但具体数字受清洗规则、语言分布和重复去重方式影响很大，不能简单当作统一统计口径。更重要的是，数据并非越多越好：重复、低质或错误数据会限制继续训练的收益。

当可靠人工数据不足时，模型可能通过合成数据扩充训练集。但合成数据能否带来新信息，取决于它是否有外部验证；否则系统只是重复自己的错误。文章的判断是，数据经过一定阶段后会逐渐收敛到算力和验证能力这个瓶颈。

## 四、中国模型公司的竞争逻辑

### 算力、融资和收入构成一个循环

训练和推理都需要 GPU。GPU 带来模型能力，模型能力带来 API、云服务或应用收入，收入和融资又能购买更多 GPU。这是文章描述的“算力 → 收入 / P&L → balance sheet → 更多算力”的飞轮。

但这个飞轮也可能反过来：如果模型能力没有形成足够收入，持续扩张的算力投入就会变成现金流压力。独立公司通常需要租用或购买外部算力，而大型云厂商可以把模型、云和应用业务放在同一个集团内协调，因此两者的成本结构不同。

### 国产模型大致分为三类

文章将国内参与者粗略归为：

1. **有主业的云厂商**：模型可以服务云、办公、电商或其他业务，收入来源更分散。
2. **获得国家层面支持的模型团队**：可能更容易获得长期算力和资源，但商业化节奏不一定与独立公司相同。
3. **纯商业化独立模型公司**：需要同时面对算力、研发、销售和融资压力。

这是文章的分析框架，不是严格的行业分类。不同公司可能跨越多个类别，也会随时间变化。

### 蒸馏优势会不会商品化

如果多家公司都能以相似方式蒸馏同一批前沿模型，蒸馏能力本身就难以形成长期差异化，服务可能进入价格竞争。要避免这种结果，公司需要在架构效率、专有数据、验证环境、产品渠道或垂直场景上形成新的壁垒。

文章还指出，开源模型的传统优势包括便宜、可微调和可私有部署，但闭源模型也可以通过新一代硬件和软件效率降低价格。因此，“开源一定便宜、闭源一定昂贵”不再是稳定的竞争划分。

## 五、为什么 AI for Science 被反复提到

文章把 AI for Science（AI4S）和机器人视为 coding 之后可能更重要的方向，原因不是它们一定更容易，而是它们拥有更高的数据和环境壁垒。

### AI4S 的两层问题

第一层是语言模型作为科研助手：检索文献、总结知识、提出实验计划、调用工具。这些工作在形式上接近 agent 和 coding。

第二层是科学模型本身：预测分子结构、蛋白质结合、材料性质、实验结果或反应条件。这些任务需要专业数据和真实实验验证，不能只靠语言模型生成一段看起来合理的文字。

即使模型提出了有希望的候选分子，仍然要经过合成、体外实验、动物实验和临床等物理流程。AI 只能缩短搜索和设计环节，不能直接跳过现实世界验证。

### 为什么“验证”在 AI4S 更难

代码的反馈可能几秒钟就回来，而一个药物候选物的实验周期可能是数周、数月甚至更久。模型生成得越快，实验环节越可能成为新的瓶颈。文章因此对“AI 制药会立刻完全替代科学家”持谨慎态度，认为真正有价值的系统需要把模型、实验工具和数据闭环连接起来。

## 六、从 coding 到空间理解和机器人

文章认为，coding benchmark 已经达到很高水平后，继续刷公开题目的边际收益会下降。下一个方向可能包括：

- 计算机使用和复杂软件操作；
- 视频理解与生成；
- CAD、雕刻等 DCC 软件；
- 物理仿真和游戏环境；
- 具身机器人在真实环境中的规划与控制。

这些任务的共同点是：模型输出不是一段孤立文本，而是会改变环境状态。例如机器人抓取物体后，物体是否真的被抓住；3D 软件生成模型后，几何是否闭合、是否可编辑；视频生成后，动作和物理关系是否持续一致。这些结果可以提供比语言偏好更接近真实任务的反馈，但采集成本也更高。

文章举“老游戏中的碰撞系统”作为直观例子：完整的物理规则可以为模型提供大量空间关系和动作结果。不过，游戏世界与现实世界仍有差异，能否迁移需要额外研究。

## 七、阅读这份纪要时需要保持的边界

这篇文章混合了三种内容，不能用同一种标准阅读：

### 可以作为技术背景的内容

- 蒸馏需要教师输出和质量筛选；
- coding 更容易获得自动验证；
- 规模化训练受算力、数据和实验并行度约束；
- AI4S 和机器人需要连接真实环境反馈。

这些是比较通用的技术判断。

### 需要核验的行业数字

文章提到的模型 token 规模、GPU 数量、蒸馏成本、GPU 价格和公司投入等数字，部分注明“有数据称”或“未验证”。它们可能来自闭门交流或二手信息，不能直接当作审计数据，也不适合用来精确比较公司。

### 属于作者或参与者的判断

例如“最终可能只剩一家独立模型公司”“某家公司技术优势不明显”“某个方向更有投资价值”等，属于分析者的观点，不是模型论文中的可复现实验结论。读者可以把它们当作待检验的假设，再寻找财报、公开技术报告、模型评测和产品数据来验证。

## 八、把文章压缩成一条因果链

可以用下面这条链理解全文：

```text
反蒸馏措施增加
        ↓
高质量教师反馈更贵、更难获得
        ↓
单靠蒸馏的追赶路线边际收益下降
        ↓
竞争转向专有数据、算力、环境和验证器
        ↓
coding 之外，机器人、空间理解和 AI4S 的价值上升
        ↓
真正的壁垒变成“模型 + 工具 + 真实结果”的闭环
```

这条链并不意味着蒸馏会消失，也不意味着更大的模型必然更好。它强调的是：当模型能力接近时，决定下一步差距的可能不再是一次 benchmark，而是系统是否能持续产生可靠反馈。

## 对人工智能博士生的几个启发

1. **不要把模型能力等同于模型参数。** 数据管线、训练基础设施、工具环境和评测器同样是模型系统的一部分。
2. **研究一个新方向时，先问“反馈从哪里来”。** 没有可靠验证器的任务，即使能生成漂亮结果，也很难形成稳定的强化学习闭环。
3. **区分可复现结论和行业传闻。** 论文实验、公开代码、财报数字和闭门访谈的证据强度不同。
4. **看真实任务的失败模式。** 在 coding、3D、机器人或 AI4S 中，研究价值常常来自发现模型为什么失败，以及怎样设计更好的环境和反馈。
5. **关注跨模块闭环。** 未来的系统可能不是“一个更大的 LLM”，而是 LLM、专用模型、工具调用、模拟器和实验设备的组合。
