# LLM 入门（三）：PPO 与 GRPO，语言模型如何用奖励学会更好的回答

如果把语言模型的预训练看成“从大量文本中学会续写”，把监督微调（SFT）看成“照着示范答案学会按要求回答”，那么 PPO 和 GRPO 位于更后面的阶段：**让模型自己生成回答，再根据奖励把概率往更好的回答方向推**。

这里的“更好”不是模型凭空知道的。它必须来自一个奖励定义，例如数学答案是否正确、代码测试是否通过，或者一个奖励模型对回答的评价。PPO 和 GRPO 解决的是“如何稳定地利用这些奖励更新语言模型”，而不是“如何自动发明推理能力”。

本文面向已经读过最简单强化学习介绍、懂基本 Transformer，但还没形成后训练算法整体图景的读者。我们沿着同一条主线理解两种方法：**模型生成什么，谁来打分，如何把分数变成更新信号，以及怎样避免一次更新把模型推得太远**。

## 先把问题摆清楚：模型要学什么

设输入问题是 `q`，语言模型生成回答 `o`。回答其实是一串 token：

```text
q → o₁ → o₂ → … → oₜ
```

模型在每一步都给下一个 token 一个概率。训练的目标不是直接把某个完整答案写进参数，而是调整这些 token 概率，让高奖励回答以后更容易出现，低奖励回答以后更不容易出现。

一个典型的 LLM 强化学习回路是：

1. 从问题集合中取出一个问题；
2. 当前策略模型生成一条或多条回答；
3. 奖励函数或奖励模型为回答打分；
4. 把分数整理成“这条回答相对好不好”的学习信号；
5. 更新策略模型，同时限制它不要偏离得过于剧烈；
6. 用更新后的模型继续生成下一批回答。

“策略”只是强化学习对模型的称呼：给定当前上下文，它决定下一个 token 的概率分布。所谓策略优化，就是直接调整这个分布。

## 从奖励到优势：为什么不能只看一个分数

假设一个问题的回答拿到奖励 0.8。这个数字单独看并不能说明太多：对简单题来说可能很差，对难题来说可能已经很好。因此算法通常需要一个基线，回答的训练信号看的是：

```text
优势 ≈ 这次回答的奖励 − 在类似状态下通常能得到的奖励
```

优势为正，表示这次回答比预期好，应该提高它产生过的 token 的概率；优势为负，则相反。

在 LLM 中，优势可以分配到回答的每个 token，也可以把最终答案的结果奖励广播给整条回答。前者更像“哪一步推理有帮助”，后者更像“最终答案是否正确”。这也是 outcome supervision 和 process supervision 的区别之一。

## PPO：带 critic 的稳定策略更新

PPO（Proximal Policy Optimization）是 LLM 后训练中常见的 actor–critic 方法。它通常维护几个角色：

- **策略模型（actor / policy）**：真正生成回答、需要被更新的语言模型；
- **旧策略**：采样这批回答时的策略快照，用来记录更新前的概率；
- **价值模型（critic / value model）**：估计当前状态大概能得到多少回报，帮助计算优势；
- **参考模型（reference model）**：通常是 SFT 模型的冻结副本，用来计算 KL 惩罚，防止策略为了奖励而忘掉原本的语言能力。

### 重要性比率：这次把概率改了多少

回答是在旧策略下采样出来的，但参数更新后要评估新策略。对某个 token，可以比较：

```text
重要性比率 = 新策略给这个 token 的概率 / 旧策略给这个 token 的概率
```

比率大于 1，说明新策略更偏爱这个 token；小于 1，说明更不偏爱。这样就能在“回答已经采样出来”的情况下，估计新策略会怎样评价它。

### clip：给更新踩刹车

如果一个回答获得了正优势，最直接的做法是把它的概率大幅提高；如果优势为负，就大幅降低。但这种更新很容易让策略突然改变，下一批样本的分布也随之失控。

PPO 的核心直觉是：当重要性比率超出一个小区间时，把它截回区间边缘。也就是说，**好回答可以变得更可能，坏回答可以变得更不可能，但单次更新不要改变得太猛**。clip 不是在判断答案是否正确，而是在限制优化步幅。

### critic 和 KL 各自管什么

critic 解决的是“这个状态的正常回报大概是多少”，从而提供优势的基线；KL 约束解决的是“更新后的策略离参考模型有多远”。二者不要混为一谈：一个主要降低优势估计的噪声，一个主要约束策略漂移。

PPO 的代价也很明显：除了策略模型，通常还要训练或运行一个价值模型，显存和计算开销都比较大；而价值模型的估计质量也会影响训练稳定性。

## GRPO：用同组回答代替价值模型

GRPO（Group Relative Policy Optimization）由 DeepSeekMath 提出，是 PPO 的一个变体。它的关键想法很直接：**对同一个问题一次采样一组回答，用这组回答之间的奖励差异构造相对优势**。

例如，同一个数学题生成四个答案，奖励是：

```text
[1.0, 0.0, 1.0, 0.5]
```

可以用这组分数的均值和标准差把它们标准化。得到的相对信号大致表示：

```text
高于组平均 → 提高这条回答的概率
低于组平均 → 降低这条回答的概率
```

因此 GRPO 不需要一个单独的 critic 来预测“这道题通常能得多少分”。同一个问题提供了一个天然的比较基线。它仍然保留 PPO 风格的重要性比率、截断更新和参考模型 KL 约束，只是把优势估计方式换成了组内相对比较。

### “没有 value model”不等于“没有奖励模型”

这是最容易混淆的一点。GRPO 省掉的是用于估计状态价值的 critic/value model，不是奖励本身。它仍需要一个可计算的奖励来源：

- 数学题可以检查最终答案是否匹配；
- 代码题可以运行测试；
- 开放式回答可以使用奖励模型；
- 过程奖励可以对中间步骤逐步打分。

如果奖励定义错了，GRPO 只会更有效地优化错误目标。它不会自动知道“什么是好推理”。

## PPO 和 GRPO 放在一起看

| 问题 | PPO | GRPO |
| --- | --- | --- |
| 如何估计基线 | critic/value model | 同一问题的一组回答的奖励统计量 |
| 是否需要多条回答 | 不一定 | 需要，对每个问题采样一组 |
| 是否使用旧策略 | 是 | 是 |
| 是否可使用参考模型 KL | 是 | 是 |
| 主要资源代价 | 价值模型带来额外显存和训练开销 | 多次采样带来生成开销 |
| 相对优势来自哪里 | 价值估计与回报之差 | 组内奖励相对均值/标准差 |

二者并不是“一个正确、一个过时”的关系。PPO 的 critic 在某些任务上可以提供更细致的状态价值估计；GRPO 则适合奖励可比较、同题多采样有意义的场景，尤其是有明确可验证结果的数学和代码任务。最终效果取决于任务、采样策略、奖励设计和训练稳定性。

## 一条贯穿两种算法的最小例子

假设问题是：`12 × 13 等于多少？`

当前模型生成两条回答：

```text
A: 12 × 13 = 156       奖励 1
B: 12 × 13 = 146       奖励 0
```

在 PPO 中，critic 会估计“面对这个问题时通常能得到的价值”，再把 A、B 的结果与这个估计比较，形成优势；策略更新时还要结合旧策略概率、clip 和 KL 约束。

在 GRPO 中，可以对同一问题生成更多答案，直接比较这组奖励。A 高于组内平均，就得到正的相对优势；B 低于平均，就得到负的相对优势。接下来的概率更新仍然需要 PPO 式的稳定机制。

这个例子刻意省略了许多工程细节，但保留了本质：**奖励负责告诉模型结果好不好，优势负责告诉模型相对好多少，策略目标负责把这个信号变成 token 概率的改变，clip/KL 负责防止改变过头**。

## DeepSeekMath 中的 GRPO 实例

DeepSeekMath 论文将 GRPO 用于数学推理强化学习。它采用可验证的数学奖励，并比较 outcome supervision、process supervision 以及迭代强化学习等设置。论文摘要报告，DeepSeekMath-Instruct 经过 GRPO 后，在 GSM8K 上从 82.9% 提升到 88.2%，在 MATH 上从 46.8% 提升到 51.7%。这些结果说明 GRPO 可以成为一种有效的后训练工具，但不能由此推出 GRPO 在所有任务上都会带来同样收益。

## 读论文或实现时的顺序

面对一篇 PPO/GRPO 论文，可以按下面顺序提问：

1. 问题和回答分别是什么？模型一次生成一条还是一组？
2. 奖励来自答案检查、过程检查，还是另一个奖励模型？
3. 优势或相对优势是如何得到的？有没有 critic？
4. 新旧策略的概率比率在哪里出现？clip 或其他信赖域约束在哪里出现？
5. 参考模型 KL 惩罚如何加入？它约束的是哪一个分布？
6. 训练使用的是在线新样本，还是固定的离线数据？
7. 评估提升是否可能来自奖励泄漏、测试污染或采样数量变化？

这组问题比死记“PPO 有 critic、GRPO 没有 critic”更有用，因为不同论文可能改变奖励、采样、优势归一化和 KL 的具体实现。

## 最后留下一个正确的直觉

PPO 和 GRPO 都是“用奖励更新语言模型”的策略优化算法。PPO 借助价值模型估计基线；GRPO 用同一个问题的一组回答做相对比较，从而减少对 value model 的依赖。两者都要处理探索、奖励噪声、策略漂移和训练稳定性，也都可能因为奖励设计不当而学到投机模式。

因此，看到“某模型使用 GRPO”时，应该先问：它优化的奖励是什么、每题采样多少回答、相对优势怎么计算、KL 如何控制，以及评估是否真正测量了目标能力。算法名字只是训练回路的一部分，不是能力本身的保证。
