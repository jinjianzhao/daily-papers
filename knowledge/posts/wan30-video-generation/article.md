# Wan 3.0：从视频生成范式到公开能力边界

> 本文面向刚入学、已经理解基本 Transformer、但还不熟悉视频生成进阶内容的博士生。先建立视频生成的基本地图，再说明公开资料能够确认的 Wan 3.0 定位。重要边界：截至本文写作时，Wan 3.0 官方公开仓库主要给出产品能力与入口，并没有像 Wan 技术报告那样公开完整网络结构、训练数据规模、损失细节或统一评测表。因此，不把 Wan 2.1 的论文细节冒充成 Wan 3.0 的实现。

## 1. 先建立视频生成的基本范式

### 1.1 输入、输出与 latent

视频生成的输入可以是文本、首帧图像、参考图像/视频、编辑指令或声音；输出通常是一段按时间排列的图像帧，也可能同时有音频。令视频为

$$
x=(x_1,x_2,\ldots,x_T),\qquad x_t\in\mathbb{R}^{H\times W\times 3},
$$

其中 T 是帧数。直接在像素空间处理全部帧代价很高，所以主流系统先用视频变分自编码器（VAE）把视频压缩成时空 latent：

$$
z=E_{\mathrm{VAE}}(x),\qquad \hat{x}=D_{\mathrm{VAE}}(z).
$$

压缩后的 z 仍保留时间和空间轴，但 token 数少很多。生成器在 latent 空间中从噪声得到视频 latent，VAE 再把它解码回像素。

### 1.2 Diffusion / Flow Matching

给定目标 latent $z_1$，训练时采样噪声 $z_0$，构造中间状态。例如线性路径为

$$
z_t=(1-t)z_0+t z_1,\qquad t\in[0,1].
$$

网络 $v_\theta(z_t,t,c)$ 接收状态、时间和条件 c（如文本或图像），学习目标速度：

$$
\mathcal{L}=\mathbb{E}\left[\lVert v_\theta(z_t,t,c)-(z_1-z_0)\rVert_2^2\right].
$$

推理时从高斯噪声开始，用数值积分器逐步更新：

~~~text
z = random_noise()
for t in sampling_schedule:
    v = video_transformer(z, t, condition)
    z = solver_step(z, v, t)
video = VAE_decode(z)
~~~

这里的扩散是生成范式，不代表所有模型网络完全相同。实现可以预测噪声、速度或其他等价参数化；采样步数、调度器和 guidance 会影响速度与质量。

### 1.3 为什么视频比图片难

逐帧独立生成会导致主体身份、背景、文字或运动方向跳变。因此模型要同时处理：

1. 空间关系：同一帧内物体、文字和布局；
2. 时间关系：相邻帧运动是否连续；
3. 条件关系：输出是否一直遵循文本、首帧或参考资产。

视频 Diffusion Transformer（DiT）通常把时空 latent 切成 patch/token，再用 Transformer 做全局或局部注意力。序列越长，注意力成本越高，所以 VAE 压缩、时空 patch、分块注意力、上下文并行和缓存都是重要工程问题。

## 2. Wan 家族放在这张地图上

Wan 的公开技术报告《Wan: Open and Advanced Large-Scale Video Generative Models》介绍了 Wan 2.1 时代的开放视频基础模型：采用视频 DiT 与 Flow Matching，并讨论时空 VAE、数据构建和训练/推理加速；报告列出 1.3B 与 14B 模型，以及文本到视频、图像到视频、视频编辑等任务。[Wan 技术报告（2025）](https://arxiv.org/abs/2503.20314)

这篇报告能帮助理解 Wan 家族的技术路线，但它不是 Wan 3.0 的技术报告。Wan 3.0 官方仓库没有承诺沿用其中每个组件。因此，本文把 Wan 2.1 只当作背景，不把其参数量、VAE 结构或训练流程写成 Wan 3.0 的已证实事实。

## 3. 公开资料能确认的 Wan 3.0

官方仓库将 Wan 3.0 描述为 Alibaba Cloud 的视频生成模型，并列出以下产品级能力：[AlibabaCloud-Official/Wan3.0](https://github.com/AlibabaCloud-Official/Wan3.0)

- 支持最长约 30 秒的原生视频生成；
- 可使用最多 20 个参考资产进行多模态创作，并提到文档和网页解析；
- 支持文本到视频、图像到视频、参考图到视频、视频编辑，以及文本到图像和图像编辑；
- 强调角色/参考细节在时间上的保持、电影感视觉和声音设计；
- 支持指令式和参考式视频编辑，并提到多人/人-物交互与自动场景切分；
- 支持连续故事图像、局部框选编辑和多语言长文本、图表、公式渲染。

这些是官方的能力描述。它们说明 Wan 3.0 的产品边界很宽，不只是单一 text-to-video 模型；但不足以推出特定 DiT 层数、参数量、MoE 或 VAE 压缩率等架构结论。

### 3.1 输入输出关系

| 模式 | 用户侧输入 | 输出的公开描述 |
| --- | --- | --- |
| Text-to-Video | 文本提示词 | 一段视频 |
| Image-to-Video | 图像和文本/编辑描述（具体参数依入口而定） | 由图像延展出的动态视频 |
| Reference-to-Video | 多个参考资产和场景描述 | 保持参考对象/人物特征的新视频 |
| Video Editing | 原视频、编辑指令或参考资产 | 按指令重构视觉内容的视频 |
| Text/Image Editing | 文本或图像编辑输入 | 图像结果，不等同于视频输出 |

“最多 20 个资产”和“30 秒”是 README 的产品描述，不应解释为所有模式、分辨率和账号都能同时达到的固定配置。官方公开页面没有给出统一输入分辨率、帧率、采样步数或 API schema，使用时应以具体入口说明为准。[Wan 官方产品页](https://wan.video/)

## 4. 用一个不越界的流程理解 Wan 3.0

下面是依据视频生成通用范式和 Wan 3.0 官方能力描述整理的概念流程，不是官方公布的内部网络图：

~~~text
文本 / 首帧 / 参考资产 / 原视频 / 编辑指令
                 │
                 ▼
        条件理解与时空对齐（公开细节不足）
                 │
                 ▼
      视频 latent 的生成或编辑（扩散/流式采样范式）
                 │
                 ▼
        时间一致性、主体细节与场景关系
                 │
                 ▼
         解码、音视频合成与结果输出
~~~

把每层的已知和未知分开：

- **已知**：官方把它定位为视频生成/编辑平台，公开多种文本、图像、视频和参考资产模式；
- **家族背景**：Wan 技术报告公开过视频 DiT、时空 VAE、Flow Matching 路线；
- **未知**：Wan 3.0 是否沿用报告中的具体 VAE、DiT 结构、条件注入、训练阶段、采样器和规模，官方仓库没有完整说明。

因此，不能仅凭“Wan”这个名字把 Wan 2.1 的公开实现当作 Wan 3.0 的实现。

## 5. 条件控制为什么重要

视频生成不是只采样看起来像视频的随机序列，而要让输出满足条件。一般可写成

$$
c=\{c_{\text{text}},c_{\text{image}},c_{\text{reference}},c_{\text{video}},c_{\text{edit}}\}.
$$

条件编码器把不同输入变成 token 或特征，在生成器的注意力层中影响时空 latent。图像到视频中，首帧提供外观和构图锚点；参考到视频中，多张参考图提供人物、物体或风格线索；视频编辑中，原视频提供应尽量保留的运动和场景结构。

Wan 3.0 README 强调“最多 20 个参考资产”“参考细节保持”和“指令式视频编辑”，说明产品目标包含多条件控制。但官方没有公开每种资产如何编码、如何分配权重、冲突条件如何处理。因此不能把能力描述写成已证实的 cross-attention 或拼接实现。

## 6. 视频一致性：要观察什么

一致性至少包含三种问题：

1. **身份一致性**：人物脸、服饰、物体外形不在帧间突然改变；
2. **几何和运动一致性**：物体移动有连续轨迹，遮挡和重新出现时形状合理；
3. **条件一致性**：视频一直执行文字、参考图或编辑指令，而不是只在开头符合。

产品页所说的 “pixel-perfect consistency” 是官方宣传措辞，不能替代给定数据集、指标和基线的实验结论。严谨比较时，应分别报告视频质量、运动平滑度、主体保持和提示词遵循，并说明分辨率、时长、采样设置与人工评测协议。Wan 3.0 当前公开仓库没有提供可复核这些维度的完整统一评测表。

## 7. 训练和推理：目前知道到哪一步

对 Wan 3.0，公开资料支持的最稳妥说法是：它是面向视频创作的生成模型/平台，官方仓库发布了能力入口和展示材料；具体训练数据、训练阶段、模型规模、损失、并行策略和推理加速细节尚未在仓库完整披露。

作为家族背景，Wan 2.1 报告展示过典型路线：先进行低分辨率图像预训练，再逐步加入图像和视频、提升空间分辨率与时间长度，最后用高质量视频后训练；模型在 latent 中进行 Flow Matching 训练。这是理解课程式训练的好例子，但不是 Wan 3.0 已确认的训练配方。

一个通用而非 Wan 3.0 专属的推理伪代码如下：

~~~python
condition = encode_user_inputs(text, image, references, source_video)
latent = sample_gaussian_noise(video_shape)

for t in schedule:
    velocity = video_generator(latent, t, condition)
    latent = integrator_step(latent, velocity, t)

frames = vae_decode(latent)
result = optional_audio_and_editing_postprocess(frames)
~~~

其中 video_generator、condition 的具体结构和 schedule 的具体形式，对 Wan 3.0 仍属于未公开实现细节。

## 8. Wan 3.0 的局限和资料边界

### 已公开、可以直接引用

- 官方仓库的模式、参考资产数量、原生 30 秒、视频编辑、多语言文字渲染等产品能力描述；
- Wan 官方网站的创作入口；
- Wan 技术报告对 Wan 2.1 时代视频 DiT、VAE、Flow Matching 和训练路线的说明。

### 目前不应写成事实

- Wan 3.0 的参数量、层数、隐藏维度、训练 token/视频数量；
- Wan 3.0 是否采用 Wan 2.1 报告中的同一套 3D causal VAE；
- Wan 3.0 是否采用 MoE、哪一种时空注意力或哪种缓存机制；
- 固定的分辨率、帧率、采样步数和显存需求；
- 没有公开评测表支持的“全面领先”或“像素级一致性”定量结论。

把官方产品承诺、家族论文背景和尚未公开的实现分开，对刚开始读视频生成尤其重要：模型名称相同或相近，不代表每一代网络和训练配方可以无条件继承。

## 9. 一句话总结

Wan 3.0 的公开定位是覆盖文本、图像、参考资产和视频编辑的多模态视频创作系统；从视频生成范式看，它应放在“条件控制的时空 latent 生成”这张地图里。现在能够可靠讲清的是任务边界与产品能力，不能可靠补写的是 Wan 3.0 的内部网络和训练数字。若后续官方发布完整技术报告，应优先用原文更新本文的架构、训练和评测部分。
