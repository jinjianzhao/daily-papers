# 视频生成入门：从文本或图像到连续画面

如果已经理解 Transformer，但还没有把“一个提示词”如何变成一段视频串起来，可以先把视频生成看成一个受条件控制的时空预测问题：模型接收文本、图像或视频片段等条件，输出一串随时间变化的图像。难点不只是每一帧好看，还要让相邻帧中的物体、相机和运动保持合理关系。

本文的重点是**视频生成的共同范式**。Wan 和 MiniMax H3 只在最后作为例子，用来说明一个具体模型可能落在这张地图的什么位置；它们的独立创新不构成本文的主线。

## 1. 任务到底是什么

设视频有 `T` 帧，每帧大小为 `H × W`，可以写成

```text
视频 x = [x₁, x₂, …, x_T]，其中 x_t ∈ R^(H×W×3)
```

模型根据条件 `c` 生成视频：

```text
文本到视频：   c = 文本提示词
图像到视频：   c = 首帧、参考图或多张参考图
视频到视频：   c = 原视频、遮罩、姿态或深度等
```

输出可以是像素视频，也可以是压缩后的 latent（潜变量）再经视频解码器还原为像素。对用户来说，交付物通常是带有帧率、分辨率和时长的短视频；对模型来说，核心对象是一个带有时间轴的三维张量，而不是独立生成的图片列表。

**边界要点：**“每帧单独生成再拼接”不等于真正的视频生成。视频模型需要在训练或采样中处理时间维度，或者使用显式的跨帧条件，使生成结果具备一定的时间一致性。

## 2. 为什么视频比图片难

图片模型只需要处理空间结构；视频模型还要处理时间结构。一个物体在连续帧中应当保持身份、形状、纹理和运动轨迹。常见失败可以按原因分为三类：

1. **空间错误**：单帧中的手、文字、物体边界不合理。
2. **时间错误**：闪烁、纹理跳变、物体突然变形或身份漂移。
3. **条件错误**：没有按照文字动作、镜头或参考图生成。

因此视频生成的目标不是简单最大化每帧的清晰度，而是在空间质量、跨帧一致性、运动自然度和条件遵循之间取得平衡。更长的时长也会加重记忆和计算开销：生成第 100 帧时，模型既要考虑局部运动，又可能需要保留第 1 帧建立的身份信息。

## 3. 统一范式：视频扩散模型

### 3.1 为什么通常先压缩到 latent

直接在像素空间生成 `T × H × W` 个值很昂贵。视频模型通常先用一个视频 VAE（变分自编码器）把像素视频压缩成 latent：

```text
像素视频 x ──视频编码器──> latent z ──扩散模型──> 预测的 ẑ ──视频解码器──> 视频 x̂
```

latent 在空间和时间上都可以下采样。例如，连续多帧可能被编码成较少的时间 token 和空间 token。这样做降低了扩散网络每一步的计算量，但也意味着细节已经经过压缩；最终清晰度还依赖解码器和后处理。不同模型的压缩比例、是否使用 3D VAE、是否在 latent 中保留时间轴，必须以各自公开资料为准，不能从“latent video”四个字推断具体结构。

### 3.2 加噪和去噪

扩散模型训练时，从干净 latent `z₀` 出发，按随机时间步 `t` 加入噪声得到 `z_t`：

```text
z_t = α(t) z₀ + σ(t) ε，  ε ~ N(0, I)
```

网络输入带噪 latent、噪声时间步和条件 `c`，学习预测噪声、速度（v）或干净 latent。训练损失通常是预测量与目标之间的均方误差；具体参数化因模型而异。

采样时从随机噪声开始，反复调用网络，把 `z_t` 变成较干净的 `z_{t-1}`，最后通过视频解码器得到帧序列。采样步数、噪声调度和 guidance 强度影响速度、细节和条件遵循程度。采样不是一次前向直接“写出整段视频”，而是一个多步的反向过程。

## 4. DiT：把时空 latent 交给 Transformer

DiT（Diffusion Transformer）把图像或视频 latent 切成 token，再用 Transformer 处理这些 token。视频 token 至少带有空间位置和时间位置：同一个物体在不同帧的 token 可以通过时空注意力交换信息。

一种概念流程如下：

```text
文本 / 参考图 / 控制信号
            │
            ▼
     条件编码器（文本、图像、姿态等）
            │
随机噪声 z_T ──> 时空 DiT ──> z_{T-1} ──> … ──> z_0
            │                              │
            └──── cross-attention / 条件注入 ┘
                                           ▼
                                      视频 VAE 解码
                                           ▼
                                         输出视频
```

这里“时空注意力”不一定意味着所有 token 永远做全局注意力。为了控制显存，工程实现可能使用局部窗口、分解的空间/时间注意力、稀疏连接或分块计算。它们都在近似同一个目标：让相关位置交流，同时把计算量控制在可接受范围。

## 5. 条件是怎样进入模型的

### 文本条件

文本编码器把提示词转为一串语义向量，DiT 的 cross-attention 或其他条件注入层读取这些向量。模型由此学习“一个词对应什么外观或动作”，但文本本身没有精确的像素轨迹，所以复杂动作仍需要大量数据和更强的时空建模。

### 图像条件

图像到视频（image-to-video）通常把参考图编码成图像特征，或者把它与噪声视频在通道、token 或注意力层中融合。首帧条件尤其适合控制主体身份和初始构图；运动仍由模型根据数据分布和文字条件补全。只给一张静态图，并不能唯一确定真实世界中物体应怎样运动，因此输出是合理的可能运动之一，不是对未来的唯一恢复。

### 结构条件

姿态、深度、光流、边缘、轨迹和遮罩可以提供更明确的空间或时间约束。它们通常先经过专门编码器，再注入主 DiT。条件越精确，控制通常越强，但也需要相匹配的训练数据和预处理器。

## 6. 一致性：视频生成真正要解决的核心问题

一致性可以拆成三个层级：

- **身份一致性**：同一个人、物体或角色在不同帧保持可识别。
- **几何一致性**：物体的形状、遮挡关系和相机运动不会无故跳变。
- **运动一致性**：速度、方向和动作阶段连续，避免抖动或瞬移。

常见工程手段包括：在训练样本中联合读取连续帧；使用跨帧注意力或时间卷积；对首帧、参考图或轨迹施加条件；在采样中采用重叠窗口生成较长视频，再把窗口边界融合起来。窗口拼接可以降低显存，但若不同窗口对主体的理解不一致，边界仍可能出现闪烁，因此它不是一致性的充分保证。

## 7. 长视频与高分辨率的工程流程

一个可复用的推理流程通常是：

1. **准备条件**：文本清洗、参考图编码、姿态或深度预处理。
2. **规划时空尺寸**：确定帧数、帧率、分辨率和 latent 的压缩尺寸。
3. **低分辨率或短时长生成**：先用较小 latent 完成主要构图和运动。
4. **时空扩展**：使用时间窗口、重叠上下文或分阶段采样延长时长。
5. **空间超分与细化**：提高分辨率、补充纹理和边缘细节。
6. **解码与后处理**：视频 VAE 解码，进行插帧、去闪烁、颜色和编码处理。

这些步骤不表示每个模型都必须照做。它们是分析工程实现的检查表：要问清楚每一步在什么表示上工作、使用了什么条件、会丢掉什么信息，以及时间和显存成本在哪里产生。

## 8. 怎么评价一个视频生成系统

评价至少应同时看四个维度：

| 维度 | 要问的问题 | 常见证据形式 |
| --- | --- | --- |
| 视觉质量 | 单帧是否清晰、结构是否合理？ | 人评、图像质量指标、样例 |
| 运动质量 | 动作和相机运动是否自然？ | 人评、运动相关指标、视频样例 |
| 时间一致性 | 身份、纹理和几何是否跨帧稳定？ | 一致性指标、跟踪结果、长片段样例 |
| 条件遵循 | 是否满足文字、首帧或结构控制？ | 提示词基准、参考图相似度、控制误差 |

单一分数不能替代这些维度。一个模型可能画面很清晰但运动僵硬，也可能动作自然但文字遵循不足。比较论文结果时还要核对分辨率、时长、采样步数、硬件和是否使用额外后处理；这些设置不同，分数不应直接横向比较。

## 9. Wan 和 MiniMax H3：把具体模型放回范式

### Wan

公开的 Wan 2.1 技术报告将 Wan 描述为面向视频生成的一套大规模模型，覆盖文本到视频、图像到视频等任务，并公开了模型与推理代码。按照本文的范式，它可以被理解为：以视频 latent 为主要生成表示，使用时空生成网络在文本或图像条件下进行多步生成，再解码为视频。这里的概括用于帮助定位它在“latent video + 时空生成 + 条件控制”地图中的位置，不等同于复述某个单独组件的完整创新。

### MiniMax H3

“MiniMax H3”这一名称在本文写作时缺少我能够核验的完整公开技术论文或官方模型报告。MiniMax 公开材料中存在多种模型和产品名称，名称相近并不意味着它们都是同一种视频生成模型。因此本文只把 H3 作为用户指定的待核验例子：如果其正式资料确认它是条件视频生成模型，就可以按照“输入条件—视频 latent—时空生成网络—视频解码—后处理”的链条定位；具体是扩散、流匹配、混合架构还是其他方案，不能仅凭名称判断。

## 10. 一张可复用的阅读检查表

读任何视频生成论文时，可以按以下顺序问：

1. 用户给了什么条件：文字、首帧、参考视频，还是结构控制？
2. 模型生成的是像素、latent，还是另一种时空表示？
3. 训练目标是噪声、速度、干净 latent，还是自回归的下一 token？
4. 时间信息在哪里交互：时间注意力、3D 卷积、窗口，还是显式轨迹？
5. 长视频如何处理：一次生成、滑动窗口、分阶段扩展，还是后处理拼接？
6. 实验是否同时报告画质、运动、跨帧一致性和条件遵循？

这套问题比记住某个模型名称更有用。模型名字会变化，但“条件进入哪里、时空信息如何交互、生成表示是什么、计算成本怎样控制”始终是理解视频生成的主线。
