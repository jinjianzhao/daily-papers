# 后训练的四条主线：大规模强化学习、过程奖励模型、推理时扩展与合成数据

预训练给模型的是"下一个 token 的分布"，它不会自动让模型更愿意写解题步骤、更少编造、更擅长在一道难题上多花时间。把这些行为装进去的环节叫**后训练（post-training）**。近两年这个环节演化出四条互相咬合的主线：

1. **大规模强化学习**：RLHF / RLAIF / GRPO，用奖励信号直接改策略；
2. **过程奖励模型（PRM）**：不只看最终答案对不对，还给每一步打分；
3. **推理时扩展（test-time compute scaling）**：训练完之后，在推理阶段多花算力换准确率；
4. **高质量合成数据**：用模型（和验证器）生产训练数据，突破人工标注的规模上限。

这四件事经常被分开讲，但它们其实在回答同一个问题的四个侧面：**在预训练算力之外，还能从哪里获得可靠的学习信号，以及怎么把这个信号转化成模型能力。** 本文按这条主线把它们串起来，并说清每条线各自解决什么、代价是什么、在哪里失效。

本文面向懂 Transformer 基本结构、读过一点 PPO/GRPO 介绍，但还没把后训练整体图景拼起来的读者。

## 一、先建立一个统一视角：学习信号从哪来

把语言模型看成策略 $\pi_\theta(o \mid q)$：给定问题 $q$，它生成回答 $o$（一串 token）。后训练的所有方法，本质上都在做同一件事——**定义一个标量信号 $r$，然后想办法让高 $r$ 的回答更容易被生成**。

差别只在三处：

- **$r$ 由谁给**：人类标注、奖励模型、规则验证器、另一个模型、还是模型自己；
- **$r$ 有多稠密**：只给整条回答一个分数（outcome），还是给每个推理步骤一个分数（process）；
- **信号作用在什么时候**：作用在参数上（训练），还是作用在采样过程上（推理）。

```text
                    ┌── 参数更新（训练时）──┐
问题 q ──► 策略 π ──┤                      ├──► 更好的回答分布
                    └── 采样聚合（推理时）──┘
                              ▲
                     奖励 / 验证器 / PRM
```

左边这条"参数更新"支路，就是强化学习和合成数据在做的事；右边这条"采样聚合"支路，就是推理时扩展。而中间的"奖励 / 验证器"，是 PRM 和各类 reward model 的战场。四者共享同一套基础设施：**能对回答打分的判别器**。

理解了这一点，就能看懂为什么这些方向会互相借用：RL 需要 PRM 提供稠密奖励，合成数据需要 PRM 或验证器做筛选，推理时扩展需要 verifier 做重排，而 PRM 自己又是用合成数据训出来的。

## 二、主线一：大规模强化学习

### 2.1 RLHF 的三段式

经典 RLHF（以 InstructGPT 为代表）是三步：

1. **SFT**：人工示范数据做监督微调，得到一个"会按指令回答"的起点；
2. **奖励模型（RM）**：让人对同一个问题的多个回答排序，训一个回归模型去预测人类偏好分数；
3. **RL 微调**：用 PPO 优化策略，让奖励模型打分更高，同时用 KL 惩罚拴住策略不要偏离 SFT 模型太远。

InstructGPT 论文里有一个常被引用的结论：1.3B 参数的 RLHF 模型在人类偏好上被认为优于 175B 的原始 GPT-3。这说明**对齐带来的收益，在当时的规模差下可以压过参数量的差距**。

KL 项的存在有个容易忽略的原因：奖励模型只是人类偏好的**有偏代理**，策略一旦发现它的漏洞（reward hacking），就会生成人类看了会摇头、但 RM 打高分的文本。KL 惩罚让策略留在"RM 训练数据覆盖得到的区域"附近，是一种粗糙但有效的分布约束。

### 2.2 RLAIF：把标注者换成模型

RLHF 的瓶颈在人类标注：贵、慢、标注者之间不一致、难以规模化。RLAIF 用模型代替人类做偏好判断——给一个强模型看两个回答，让它选更好的那个，或者按 rubric 打分，然后用这些 AI 偏好训奖励模型或直接做 RL。

Constitutional AI 是这条线的代表：先让模型按一组书面原则自我批评并改写回答（监督阶段），再用 AI 偏好做 RL 阶段。好处是原则可审计、可修改；代价是**AI 标注的偏差会原样进入模型**，包括它对某些风格的偏好和对某些话题的回避倾向。

一个实践上的关键点：AI 标注者的能力和被训练模型的能力不能差太少，否则偏好信号会退化；同时要用人工抽检校准 AI 标注的偏移，否则错误会被放大而不是被平均掉。

### 2.3 从 PPO 到 GRPO：去掉 critic

PPO 需要一个和策略同样大的价值网络（critic）来估计基线。在 LLM 场景下这意味着显存翻倍、训练更不稳定。GRPO（DeepSeekMath 提出）的做法很干脆：**同一个问题采样一组回答，用组内统计量当基线**。

对问题 $q$ 采样 $G$ 条回答 $o_1,\dots,o_G$，奖励为 $r_1,\dots,r_G$，第 $i$ 条的优势近似为

$$
A_i = \frac{r_i - \operatorname{mean}(r_1,\dots,r_G)}{\operatorname{std}(r_1,\dots,r_G)}
$$

然后用 PPO 的 clip 目标更新：

$$
\mathcal{L} = -\mathbb{E}\left[\min\left(\rho_i A_i,\ \operatorname{clip}(\rho_i, 1-\epsilon, 1+\epsilon)A_i\right)\right], \quad \rho_i = \frac{\pi_\theta(o_i\mid q)}{\pi_{\theta_{old}}(o_i\mid q)}
$$

不用 critic，只多花采样算力。这个替换带来两个后果，都很重要：

- **好处**：省一个模型、省显存、实现简单，且天然适配"同一道题采样很多次"的推理型任务；
- **代价**：组内奖励如果全都一样（全对或全错），优势全为 0，这条数据完全浪费。所以 GRPO 的实际吞吐高度依赖**题目难度分布**——太简单和太难的题都不产生梯度。

这也是为什么后来的大规模 RL 系统都在做**难度课程**：动态过滤掉全对和全错的组，把算力集中在"有区分度"的样本上。

### 2.4 RLVR：当奖励可以不靠人给

真正让大规模 RL 跑起来的关键变化，是**可验证奖励**（RLVR, RL with Verifiable Rewards）。数学题有标准答案，代码有单元测试，格式有解析器，逻辑题有唯一解——这些任务的奖励可以由程序判定，不需要奖励模型，也就没有 reward model 被 hack 的空间。

于是训练信号变成二值的：

$$
r(o) = \begin{cases} 1 & \text{验证器判定正确} \\ 0 & \text{否则} \end{cases}
$$

配合 GRPO 的组内归一化，这就是 DeepSeek-R1 系列使用的核心循环。它跑得通的前提是任务本身有**廉价、可靠、不可作弊的验证器**。这个前提一旦不成立（开放式写作、主观建议、长文档摘要），就得退回奖励模型或 PRM。

### 2.5 大规模 RL 真正的难点在工程

算法本身几行公式就写完了，落到几千张卡上是另一回事：

| 问题 | 表现 | 常见处理 |
| --- | --- | --- |
| 采样吞吐 | rollout 占 70% 以上时间，GPU 空转等生成 | 异步 rollout、推理引擎与训练分离、off-policy 校正 |
| 长度偏置 | 模型学会"写更长换更高分" | 长度惩罚、按 token 归一化优势 |
| 奖励作弊 | 输出格式怪异但能骗过验证器 | 验证器加固、多验证器投票、抽样人工检查 |
| KL 塌缩 | 策略退化到重复短语 | KL 系数自适应、熵正则 |
| 训练不稳定 | 少数 step loss 爆炸 | 梯度裁剪、clip 收紧、回滚检查点 |

一个经验判断：**当 RL 效果不及预期时，先怀疑奖励和验证器，而不是算法。** 大多数"RL 训不上去"的案例，根因是奖励定义里的漏洞被策略找到了。

关于 PPO/GRPO 的公式推导和最小实现，本站另外两篇讲得更细：[LLM 入门（三）：PPO 与 GRPO](../../article.html?slug=ppo-grpo) 和 [从 REINFORCE 到 GRPO](../../article.html?slug=reinforce-to-grpo)；想直接上手跑，可以看 [用 TRL 跑通 GRPO](../../article.html?slug=trl-grpo-framework)。

## 三、主线二：过程奖励模型（PRM）

### 3.1 ORM 和 PRM 的区别

结果奖励模型（ORM）给整条回答打一个分；过程奖励模型（PRM）给推理链的**每一步**打分。

```
ORM:  q ──► [步骤1 步骤2 步骤3 答案] ──► 0.7

PRM:  q ──► [步骤1] ──► 0.9
            [步骤2] ──► 0.8
            [步骤3] ──► 0.2   ← 这里错了
            [答案 ] ──► 0.1
```

动机很直接：最终答案错，可能是因为中间某一步算错，也可能只是最后抄错。ORM 只能告诉你"这条链不行"，PRM 能告诉你"从哪一步开始不行"。对搜索和 RL 来说，后者信息量大得多——它能在错误发生的位置就掐断，而不是等整条链跑完。

OpenAI 的 *Let's Verify Step by Step* 给出了这条线最常被引用的结论：在 MATH 数据集上做 best-of-N 重排，PRM 的排序效果明显优于同等条件下的 ORM，而且随着 N 增大差距拉大。这也解释了为什么"过程监督"在数学推理上被反复提起。

### 3.2 PRM 是怎么训出来的

难点在于**步骤级标签极其昂贵**。主流做法有三类：

1. **人工逐步标注**：标注者给每一步标对/错。PRM800K 就是这种做法，8 万条步骤级标签，成本极高但质量最好。
2. **蒙特卡洛自动标注**：对某一步之后的续写采样多次，用最终正确率估计这一步的价值。Math-Shepherd 是代表。做法上，一个步骤的分数 ≈ 从该步骤出发、让模型继续写 $K$ 次、最终答对的比例。这样完全自动，但**标签质量被策略本身的能力上限绑住**——如果模型从这一步出发永远写不对，这一步会被错标成"坏"，即使它其实是对的。
3. **用强模型蒸馏**：让更强的模型（或带搜索的模型）标注/生成步骤评分。省人工，但引入了教师模型的偏差，且容易在教师也弱的领域失真。

### 3.3 PRM 的三种用法

- **Best-of-N 重排**：采样 N 条完整回答，用 PRM 给每条链打分（取最差步骤分、平均分或乘积），选最高的。简单、无需改训练，是工业界最常见的用法。
- **搜索引导**：在树搜索（beam search、MCTS）中把 PRM 当价值函数，用于剪枝和扩展。收益更大，但实现复杂，且对 PRM 的校准要求更高。
- **稠密奖励进 RL**：把每步的 PRM 分数作为中间奖励，解决 GRPO 里"整条链只有一个 0/1"的稀疏性问题。

### 3.4 PRM 的失效模式

PRM 不是免费的午餐，四个坑要认清：

1. **步骤边界不明确**：自然语言推理没有天然的分步边界。切得太细，单步没意义；切得太粗，等于退回 ORM。
2. **分布漂移**：PRM 在策略的旧输出上训练，策略更新后输出分布变了，PRM 的评分就失准——这是 RL 里 PRM 当奖励最危险的地方。
3. **可被优化**：只要 PRM 参与优化，策略就会找它的漏洞。PRM 当奖励比 ORM 更危险，因为**每一步只要看起来合理就能得分**，模型可以学会写"看起来很像推理"的废话。
4. **误判的代价不对称**：PRM 倾向给"表述规范"的步骤高分，这会系统性惩罚那些写法潦草但正确的推导路径。

一个务实的做法是：PRM 主要用于**推理时的重排和剪枝**（不改变策略分布，不会引发 reward hacking），而不是长时间 RL 的稠密奖励。真要用进 RL，要配合 ORM 或验证器做终局校验。

## 四、主线三：推理时扩展（Test-time Compute Scaling）

### 4.1 两条完全不同的路子

训练完之后想提高准确率，有两条路：

**路子 A：让单条回答更长。** 用 CoT、反思、自我检查，把更多计算花在一条序列里。这条路的极端是"思考模型"——模型在给出答案前先写很长的推理过程。

**路子 B：采样多条，再聚合。** 同一道题采样 N 条回答，用某种方式选一个：

- **多数投票（self-consistency）**：取出现次数最多的最终答案；
- **best-of-N + verifier**：用 PRM 或验证器打分，取最高；
- **加权投票**：按 verifier 给出的置信度加权。

两条路的成本结构不同。路子 A 是串行、延迟高、单条贵；路子 B 是并行、吞吐友好、但需要可靠的选择器。

### 4.2 一个反直觉的结论

Snell 等人在 2024 年的工作给出了一个被广泛引用的判断：**在固定的推理算力预算下，用较小模型配合最优的 test-time 策略，可能优于用大得多的模型只采样一次**。也就是说，推理算力和预训练算力之间存在某种可替换性。

但这个结论有严格前提，漏掉前提就会误读：

- "最优策略"指的是在"短链多采样"和"长链少采样"之间**按题目难度动态分配**——简单题多采样，难题长链；
- 收益上限取决于**选择器的质量**。没有 verifier，多数投票只在答案可枚举时有效（数学填空、选择题）；开放式生成里多数投票几乎无意义；
- 收益**边际递减**：采样数从 1 增到 16 提升明显，从 64 增到 256 往往不值那个成本。

### 4.3 覆盖与验证的分离

把这件事想清楚，可以用两个量：

- **覆盖（coverage）**：采样 N 条里**至少有一条正确**的概率，记为 $\text{pass@}N$。它衡量模型的"潜在能力"。
- **验证（verification）**：给定一堆候选，**选对**的概率。它衡量选择器的能力。

$$
P(\text{答对}) \le \min\big(\text{coverage}(N),\ \text{verification}(N)\big)
$$

真实收益被两者中较差的那个卡住。这解释了大量实验现象：

- 模型很强但 verifier 很弱（开放式任务）→ 多采样没用，因为你选不出来；
- 模型很弱但 verifier 很强（有标准答案的数学题）→ 多采样非常有效，因为只要有一条对，就能选出来；
- 两者都强 → 收益最大，这也是"推理模型 + 可验证任务"组合最亮眼的原因。

工程上的启示：**推理时扩展的投入应该先花在 verifier 上，再花在采样数上。** 一个差的选择器会把多采样的收益全部吃掉，而且会给你虚假的进步感。

### 4.4 训练和推理的耦合

一个容易被忽略的事实：**RL 训练会改变模型使用 test-time compute 的方式**。经过 RLVR 训练的模型，在同样的采样预算下往往表现更好，不只是因为能力更强，还因为：

- 它更愿意展开长推理，而不是急着给答案；
- 它的错误更"局部"——错在具体一步，而不是整条链跑偏，这让 PRM 和搜索更容易纠回来；
- 它的输出分布更集中，多数投票的有效性提高。

反过来说，test-time 的表现也在指导训练：如果一个模型在 test-time 扩展下收益很小，通常说明它的 pass@N 已经饱和，或者它的错误高度相关（N 条错得一模一样），这时候加采样不如加训练。

## 五、主线四：高质量合成数据

### 5.1 为什么必须要合成数据

三条压力同时存在：

- **人类数据墙**：高质量人工标注的增速远低于模型对数据的需求；
- **覆盖长尾**：人类标注很难系统性覆盖"难题的中间推理步骤"这类数据；
- **可规模化**：合成数据的边际成本随算力下降，人工标注的成本是线性的。

### 5.2 四种主要做法

| 做法 | 机制 | 典型代表 | 主要风险 |
| --- | --- | --- | --- |
| 蒸馏 | 强模型生成，弱模型学 | 大模型蒸馏到小模型 | 天花板锁死在教师 |
| 拒绝采样 / STaR | 自己采样，只留验证通过的 | STaR、ReST、R1 的 SFT 数据 | 只覆盖模型已会的区域 |
| 自我奖励 | 模型自己打分再训练 | Self-Rewarding LMs | 评分漂移、自我强化偏见 |
| 程序化生成 | 用规则/模拟器造题和答案 | 数学题合成、代码题合成、环境交互 | 分布与真实任务脱节 |

**拒绝采样**是当前最主流也最可靠的一种：让当前策略对一批 prompt 采样多条，用验证器筛出正确答案的轨迹，再用这些轨迹做 SFT。它同时具备两个好处——数据一定"在模型能力范围内"（否则采不出来），且标签一定正确（有验证器）。代价是它只能强化已有能力，不能凭空创造新能力；这也是为什么 R1 的流程里要先用少量人工冷启动数据把模型带到能采出正确轨迹的水平。

### 5.3 合成数据的质量控制

"合成数据能训出好模型"和"合成数据会把模型训坏"都是真的，分野在质量控制。四个维度必须同时管：

1. **正确性**：有验证器就用验证器；没有就用强模型多轮交叉检查，并接受一定残余噪声。
2. **多样性**：同一个 prompt 反复采样会得到高度相似的答案，直接训练会导致 mode collapse。要做去重（语义级，不是字符串级）和 prompt 层面的分布覆盖。
3. **难度**：全对的样本没有学习信号（对 GRPO 是优势为 0，对 SFT 是梯度很小）。要有难度分层和课程。
4. **分布匹配**：合成数据的风格如果和真实用户输入差异太大，模型会学到"只会回答考试题"。要用真实分布做校准集。

### 5.4 模型崩塌不是都市传说

Shumailov 等人在 Nature 上的工作展示了递归训练在什么条件下会退化：当每一代都用上一代的输出训练，分布尾部会逐代丢失，最终收敛到低多样性、高方差的分布。

但要注意条件——**退化发生在"只用模型输出、不做筛选、不做真实数据混合"的情况下**。实践中的缓解手段都是围绕这三点：

- 保留一部分真实数据混训（锚定分布）；
- 用验证器筛选而不是全盘接收；
- 保留多样性机制（温度、prompt 多样性、拒绝采样时的多样性约束）。

所以正确的表述不是"合成数据会导致模型崩塌"，而是"**无筛选、无锚定的递归自训练会退化**"。

## 六、四条线怎么咬合：一个完整的飞轮

把四条线放在一张图上，就是一个自我强化的循环：

```text
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
   ① 大规模 RL（RLVR / GRPO）                          │
        │  用验证器给奖励，提升策略能力                  │
        ▼                                              │
   ② 策略变强 → 能采出更多正确轨迹                     │
        │                                              │
        ▼                                              │
   ③ 拒绝采样 → 高质量合成数据（SFT 数据）              │
        │                                              │
        ▼                                              │
   ④ 训练 PRM / verifier（用步骤级标签或 MC 估计）      │
        │                                              │
        ▼                                              │
   ⑤ 推理时扩展：更多采样 + 更好重排                    │
        │  产出更可靠的答案，也产出更高质量的轨迹         │
        └──────────────────────────────────────────────┘
```

DeepSeek-R1 的流程基本就是这个环的一次完整实例：少量冷启动 SFT → RLVR（GRPO + 规则验证器）→ 用 RL 后的模型做拒绝采样，造 80 万条 SFT 数据 → 再训一轮 → 把能力蒸馏到小模型。四条线在里面各司其职：RL 提供能力，合成数据提供规模，验证器提供正确性保证，推理时扩展提供上限。

反过来看，这个环里任何一环断了，整体收益都会打折：

- **没有好验证器** → RL 只能退回奖励模型，reward hacking 风险陡增；
- **没有 PRM** → 推理时扩展只能在可枚举答案的任务上工作；
- **没有合成数据** → 每轮迭代都要重新人工标注，迭代速度降一个数量级；
- **没有 RL** → 合成数据的质量上限被初始模型锁死，做几轮就饱和。

## 七、读论文和做实验的顺序建议

如果你要从零进入这个方向，我建议这个顺序：

1. **先建直觉**：把"奖励从哪来、有多稠密、作用在训练还是推理"这三个问题当成阅读框架，任何一篇后训练论文都先回答这三问。
2. **跑通一条最小链路**：用 TRL 在一个小模型上跑通 GRPO + 规则验证器（比如 GSM8K 或简单的格式任务）。这一步的目的是理解"奖励定义 → 采样 → 优势 → 更新"的实际数据流，而不是追求分数。
3. **加一个 PRM**：在同一个任务上加 best-of-N 重排，观察 PRM 和多数投票的差异。你会亲眼看到"verifier 质量决定 test-time 收益"。
4. **做数据**：用拒绝采样产出数据，比较"同量真实数据"和"同量合成数据"的效果差，重点看分布外测试集。
5. **最后再碰大规模**：异步 rollout、难度课程、多验证器投票这些工程问题，在没有跑通小链路之前不要碰。

## 八、几个常见误解

- **"GRPO 一定比 PPO 好"**：错。GRPO 省掉 critic，但依赖组内方差。奖励近乎二值且难度合适时它很好用；需要精细信用分配时，critic 仍有价值。
- **"PRM 比 ORM 高级，所以一定更好"**：错。PRM 的优势在搜索和重排；当稠密奖励进 RL 时，它的 reward hacking 面更大。很多团队最后发现"ORM + 强验证器"性价比更高。
- **"test-time compute 可以无限换参数"**：错。收益被 coverage 和 verification 双重截断，且边际递减。它和预训练是互补关系，不是替代关系。
- **"合成数据越多越好"**：错。无筛选、无多样性控制、无真实数据锚定的合成数据会退化。质量控制的成本经常超过生成成本。
- **"RL 训不上去是算法问题"**：大概率不是。先查奖励和验证器的漏洞。
