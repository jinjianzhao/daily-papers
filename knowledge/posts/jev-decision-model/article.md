# Jev 是什么？如何训练一个类似的决策模型

截至 2026 年 10 月，**Jev** 指 TypeSafe AI 发布的 **System One 决策模型**。它读取一段文本状态和一个有明确答案空间的问题，直接返回各个答案的概率，供软件选择、排序或决定是否复核。它的核心任务是：在给定上下文中，做一个可量化不确定性的判断。[TypeSafe 官方介绍](https://docs.typesafe.ai/introduction)

官方没有公开 Jev 的权重、内部结构和完整训练配方。因此，下面的“自己训练”指训练一个 **Jev 风格模型**；其中具体可复现的算法来自独立论文 [LLM-as-Jev](https://arxiv.org/abs/2610.02076)，不能当作 Jev 官方内部实现。

## 先用一个例子理解

客户邮件写着“我被扣了两次钱”。输入状态是邮件和交易记录；问题是“交给哪个团队？”；候选项是账单、技术支持、账户管理、其他。

模型输出可以是：`账单 0.84 · 技术支持 0.05 · 账户管理 0.02 · 其他 0.09`。系统据此把邮件交给账单团队；如果概率分散，则交给人复核。模型直接给出一个 **候选答案上的概率分布**，应用程序无需从一段自由文本中提取结论。

TypeSafe 官方提供三种问题形式：[Choice](https://docs.typesafe.ai/primitives/choice) 在若干选项中选择；[Noul](https://docs.typesafe.ai/primitives/noul) 返回一个判断为“是”的概率；[Score](https://docs.typesafe.ai/primitives/score) 在有序等级上评分。Choice 和 Score 附带的 `confidence` 是由概率分布的形状计算出来的摘要，不是另一个单独训练的“答案正确概率”。当前官方 Jev 接收文本、文本数组及 JSON 形式的文本状态；官方文档说明它暂不直接支持图像、音频或视频。[System One 文档](https://docs.typesafe.ai/concepts/system-one) · [Confidence 文档](https://docs.typesafe.ai/confidence)

## 它与聊天模型的算法目标有何不同

普通语言模型训练下一 token 概率，并通过反复生成 token 写出文字。Jev 风格任务的输出是有限答案空间中的概率。它要求同时做好两件事：**选得对**，以及**报告可信的概率**。

“概率可信”指群体上的校准：如果模型对许多可比较事件都给出 0.8 的概率，这些事件应大约有 80% 发生。它不保证某一次预测一定正确。[官方 AI primer](https://docs.typesafe.ai/introduction/machine-learning-primer)

TypeSafe 把自己的后训练方向称为 **RLCD**，即 *reinforcement learning for calibrated decisions*。公开资料给出了“训练出校准决策”的目标，但没有披露具体奖励函数、策略更新算法或网络结构；仅凭 RLCD 这个名字，无法推断它用了 PPO、GRPO 或其他特定方法。

## 自己训练：先定义问题，再选择路径

一个训练样本应包含四部分：**状态、问题、候选答案、正确结果**。二元核验可视为两个候选；有序评分可把各档写成带描述的候选。若候选列表可能不完整，需要有“其他／均不符合”以及证据不足时的复核路径。

标注也要与问题性质匹配。客观且可核验的任务可用单一正确答案；主观判断如果标注者常有分歧，就应收集多名标注者的判断或保留不确定状态，避免把分歧伪装成确定标签。

### 路径 A：先用现成 LLM，暂不训练

这是最有价值的基线。[LLM-as-Jev §3.2–3.3](https://arxiv.org/html/2610.02076#S3.SS2) 提出：把状态、问题和**全部**候选同时放入提示词，候选编号为 `[1]` 到 `[K]`；在模型回答前填入 `Best answer: [`。随后分别计算每个合法编号后缀（例如 `1]`、`2]`）的条件 token 概率，把该后缀中各 token 的对数概率相加，最后在所有候选之间做 softmax 归一化。

用一句公式表示：**选项分数 = 该编号后缀各 token 的 log 概率之和；选项概率 = 这些分数的 softmax。** 编号右侧的闭括号很关键，它让完整答案互不成为彼此的前缀；例如 `1]` 不是 `12]` 的前缀。模型读的是整组选项，计算又可以复用同一段输入的前缀并并行评估短后缀。

该论文在 **231 道公开 JevBench 题**上，用冻结的 Qwen3.5-4B 得到 **81.4% 准确率**和 **0.057 ECE**。这是该论文所用公开题集的结果，不是 TypeSafe 官方 Jev 的成绩，也不保证换到你的数据仍能达到同样水平。[LLM-as-Jev §4.2](https://arxiv.org/html/2610.02076#S4.SS2)

### 路径 B：基线有明确短板时再微调

有可靠标注后，可以让模型对正确选项分配更高概率，最简单的目标是**正确选项的负对数概率**，即分类交叉熵。训练时随机调换候选顺序、变化问题措辞，能减少模型记住固定编号或模板的倾向。

[LLM-as-Jev §3.4](https://arxiv.org/html/2610.02076#S3.SS4) 给出了更具体的目标：把合法编号组织成一棵短的前缀树，在正确答案经过的每个分叉处，只在合法的下一 token 之间归一化，累加正确路径的负对数概率。这叫 **tree-factorized listwise loss**。例如 `[1]` 与 `[12]` 共存时，读到数字 `1` 后，合法的下一步可以是 `]` 或 `2`。候选很多时，训练主要沿正确路径计算。

只优化“合法编号内部谁排第一”有一个漏洞：模型即使把绝大部分概率给了无关文本，合法编号之间仍可能排对。论文因此把微调模型与冻结的原模型比较，加入三类 **KL 约束**：维持合法编号的总概率质量、维持非法 token 的相对分布，以及维持其他生成位置的 token 分布。这样做的目的是提高决策能力，同时保留原模型的一般生成行为。

在该论文的 Qwen3.5-4B 实验中，LoRA 微调加这组约束在公开 JevBench 上达到 **84.0% 准确率**和 **0.050 ECE**。这是公开复现路线的实验结果，不能证明官方 Jev 采用同样训练法。[LLM-as-Jev §4.4](https://arxiv.org/html/2610.02076#S4.SS4)

## 数据与评估：怎样知道模型真的可用

1. **覆盖实际使用场景。** 训练数据要有不同选项数、二元判断、有序评分、未知项、短输入和长输入。若大量样本仅凭一个关键词就能判断，模型可能学会捷径，却不能处理真正需要综合证据的案例。[LLM-as-Jev §4.3](https://arxiv.org/html/2610.02076#S4.SS3)
2. **留下独立测试集。** 按时间、来源、用户或实体切分，避免同一事件的近似复述进入训练集和测试集。不要用公开 benchmark 一边调参一边宣称泛化成绩。[LLM-as-Jev §3.5](https://arxiv.org/html/2610.02076#S3.SS5)
3. **同时测选择和概率。** 准确率衡量“选没选对”；负对数似然、Brier 分数和可靠性图衡量“概率是否可信”。ECE 可辅助概括，但它会受分箱和样本量影响。有限训练数据上的低交叉熵并不自动证明部署时校准良好。
4. **专门测失效情况。** 调换候选顺序、改写问题、加入无关文本、测试长状态和“均不符合”。若还保留聊天用途，也检查普通生成是否退化。官方列出的 Jev 1.13 弱点包括计数、无关长状态及对抗性输入。[官方已知弱点](https://docs.typesafe.ai/model-jaggedness/jev-1.13)
5. **用验证集决定自动处理阈值。** 根据不同阈值下的错误率与人工复核量设定业务规则。最大选项概率、分布形状算出的 `confidence` 和“保证正确”是不同的概念。[官方 Confidence 文档](https://docs.typesafe.ai/confidence)

交叉熵是学习概率的合理目标：在标签可靠、训练样本代表目标人群等理想条件下，它的最优解对应数据的条件事件概率。但类重采样、类别加权、领域变化都会影响实际概率解释。若验证集显示系统性过度自信，可以在**独立校准集**上考虑温度缩放；这只是可选工程方法，不是 Jev 官方披露的训练步骤。

## 如果今天开始做，我会这样排实验

先选一个具体决策域，定义答案空间与“其他”选项，准备独立标注和测试集；接着用较强的开放权重 LLM 做**免训练决策基线**。如果它已经满足准确率、校准和延迟要求，就无需微调。若缺陷集中在特定领域或大量选项，再做小规模 LoRA 决策微调，并与简单交叉熵训练对照。最后仅根据独立测试结果决定是否采用新模型，报告准确率、校准、选项顺序敏感性、未知项检出率以及需要人工复核的比例。

**结论：** 公开资料足以指导你训练一个 Jev 风格的决策模型；目前还不足以完全复刻 TypeSafe Jev 的内部算法。
