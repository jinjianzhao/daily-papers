# 如何训练一个 Jev：从语言模型到概率决策

如果你已经懂 Transformer，可以先抓住一个变化：普通 LLM 的任务是**继续写 token**，Jev 这类决策模型的任务是**在给定的答案中分配概率**。两者可以共用同一套语言模型主干；关键在于怎样把问题交给模型、怎样从 token 概率得到选项概率，以及何时需要额外训练。

本文以 [LLM-as-Jev](https://arxiv.org/abs/2610.02076) 的公开方法为主线。TypeSafe AI 的 Jev 是一个实际产品，提供结构化决策接口；它的内部网络与完整训练配方未公开。下文讲的具体算法是论文给出的可复现路线。

## 先看标准 LLM：它原本在做什么

一个常见的 decoder-only LLM 把输入文本切成 token，经 embedding 和位置信息送进多层 Transformer。每层用因果注意力读取已有上下文，再经过 MLP；最后的 LM head 对整个词表给出下一 token 的 logits。对 logits 做 softmax，就得到下一 token 的概率。生成时再把选出的 token 接回输入，重复这一过程。

> 输入 token → 因果 Transformer → 词表 logits → 下一个 token → 继续生成

例如读到客户邮件“我被扣了两次钱”，聊天模型可能续写“这看起来是账单问题”。软件若要据此分单，还得从自由文本中提取类别，也很难直接知道其他类别有多大可能。**决策任务需要的是固定答案空间上的概率分布**，例如账单 0.84、技术支持 0.05、账户管理 0.02、其他 0.09。

论文的公开路线保留上述 Transformer 主干和 LM head，不另加分类头：通过设计输入与答案格式，从原有的下一 token 概率算出这些选项概率。训练是可选的下一步，而非使用这一接口的前提。[论文 §3](https://arxiv.org/html/2610.02076#S3)

## Jev 要解决什么问题

可以把一次决策写成四项：**状态**（邮件与交易记录）、**问题**（交给哪个团队）、**候选答案**（账单、技术支持、账户管理、其他）和**正确结果**。推理时没有正确结果，模型返回候选答案的概率；程序据此选择动作，或者在不确定时交给人复核。

TypeSafe 提供 [Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)、[Score](https://docs.typesafe.ai/primitives/score) 等问题形式，分别用于多选一、是／否判断和有序评分。官方当前接口处理文本状态，相关文档没有提供可据以复刻内部网络的细节。[System One 文档](https://docs.typesafe.ai/concepts/system-one)

概率还有一个要求：**校准**。若系统在许多相似任务上给“账单”约 80% 的概率，理想情况下其中约 80% 真是账单问题。这说的是一组预测的统计性质，不保证某次预测一定正确。

## 路径 A：不训练，先让 LLM 给出选项概率

论文首先把**全部候选同时交给模型**，让模型在看完整组选项后判断。下面是格式示意；候选标签、编号和最后一行的方括号都是输入的一部分。

```text
状态：客户说“我被扣了两次钱”，并附有两笔交易记录。
问题：应交给哪个团队？
[1] 账单
[2] 技术支持
[3] 账户管理
[4] 其他
Best answer: [
```

模型此时还没有输出答案。程序分别计算合法后缀 `1]`、`2]`、`3]`、`4]` 出现的概率。如果选择第一项，**完整的一行是 `Best answer: [1]`**；`1]` 只是接在已给定前缀后的续写，所以单独看才像少了左括号。每个后缀可能被 tokenizer 切成多个 token，程序把这些 token 的条件 log 概率相加，得到该候选的分数，再对所有候选分数做 softmax。[论文 §3.2–3.3](https://arxiv.org/html/2610.02076#S3.SS2)

右括号也有作用：如果有第 1 项和第 12 项，完整后缀 `1]` 和 `12]` 互不构成前缀。这样程序比较的是明确终止的答案。各候选共享长输入前缀，因此计算时可复用其 KV cache；候选顺序仍可能影响概率，评估时需要换序测试。

![论文图 1：同一语言模型主干的免训练评分与可选微调路线](https://arxiv.org/html/2610.02076v2/framework.svg)

*图 1（[LLM-as-Jev 原图](https://arxiv.org/html/2610.02076#S3.F1)）：读图时先看共同的输入和 LLM；一条路径直接比较合法编号的续写概率，另一条路径在同一结构上增加训练目标。它不是“另造一个分类网络”。*

## 路径 B：什么时候训练，训练改了什么

免训练基线如果已经满足准确率、概率质量和速度要求，就可以直接使用。若在特定领域或选项很多时仍有稳定缺陷，再准备标注样本做微调。训练样本至少需要状态、问题、全部候选与正确答案；实际数据还应覆盖候选换序、“均不符合”、短长上下文及容易误判的例子。

### 前缀树损失：让正确答案赢过其他合法答案

论文把合法编号的 token 序列组织成前缀树。想象候选编号 1 到 12：读到 `1` 后，合法的下一步可能是 `]`（第 1 项结束），也可能是 `2`（走向第 12 项）。训练时在每个分叉点**只比较合法的下一 token**，并沿正确答案的路径累计负 log 概率。这就是 *tree-factorized listwise loss*。[论文 §3.4](https://arxiv.org/html/2610.02076#S3.SS4)

它直接优化“合法候选中谁更可能正确”，不要求模型在所有词表 token 中每一步都先输出编号。训练时的局部分叉归一化，与推理时“完整后缀分数再 softmax”的概率通常**不严格相等**；论文指出，在根之后的内部节点把全部概率都给合法后继等条件下才一致。把两者当作同一个精确公式会误解方法。

### KL 锚定：保住原来的语言能力

只练候选排名会留下漏洞：模型可以在合法选项内部排对顺序，却把大量概率放在无关词上；也可能学会做选择后，普通文本生成退化。论文用一个冻结的原模型作为参照，在训练损失外加入三类 KL 约束，分别关注：合法 token 的**总概率质量**、非法 token 之间的**相对分布**、以及决策位置之外的**普通生成分布**。[论文 §3.4](https://arxiv.org/html/2610.02076#S3.SS4)

![论文图 2：决策训练时的三类 KL 锚定](https://arxiv.org/html/2610.02076v2/anchors.svg)

*图 2（[LLM-as-Jev 原图](https://arxiv.org/html/2610.02076#S3.F2)）：把注意力放在“正确编号以外的概率去哪儿了”。三类锚定分别守住合法答案的总质量、非法词的相对概率，以及其他位置的生成行为。*

KL 约束不能替代好数据：如果训练集总让“是”当正确答案，模型仍可能学到“是”的偏置。论文在狭窄意图数据上观察到训练损失下降而 JevBench 准确率从 81.4% 降至 74.9%；短上下文数据也可能伤害长上下文能力。[论文 §4.3](https://arxiv.org/html/2610.02076#S4.SS3)

## 论文实验告诉我们什么

在论文使用的 **231 道公开 JevBench 题**上，冻结的 Qwen3.5-4B 免训练达到 **81.4% 准确率、0.057 ECE**。同一 4B 模型用 LoRA 加 KL 约束微调后，达到 **84.0%、0.050 ECE**。较小的 Qwen3-0.6B 从免训练 **56.7%、0.278 ECE** 到 LoRA 微调 **61.0%、0.121 ECE**。ECE 越低通常表示分箱统计下的概率与实际频率更接近，但它会受样本量和分箱方式影响。[论文 §4.2–4.4](https://arxiv.org/html/2610.02076#S4.SS2)

这些数字支持“先试免训练、再针对缺陷微调”的路线，不代表微调总会提高每个任务的成绩。论文还发现，去掉 KL 约束时，4B 模型在 231 题中有 **69 题会在编号后继续输出文本**；只看选择准确率会漏掉这种输出格式退化。[论文 §4.4](https://arxiv.org/html/2610.02076#S4.SS4)

## 如果今天动手，我会怎样做

1. **定义一个真实决策问题。** 明确状态、答案空间、正确标签来源，以及何时应回答“其他”或转人工。主观问题若标注者常有分歧，保留多位标注者判断。
2. **先建免训练基线。** 用完整候选和括号编号评分，记录准确率、每个候选概率、运行成本与候选换序后的变化。
3. **准备代表性训练数据。** 覆盖二元、多选、有序问题和短长上下文；打乱候选顺序，防止编号捷径。把独立测试集按时间、来源或实体切开。
4. **只针对已观察到的缺陷微调。** 比较免训练、简单选项交叉熵、论文的前缀树损失，以及 LoRA 加 KL 锚定；同时检查普通生成有没有退化。
5. **同时测选择与概率。** 报告准确率、负对数似然或 Brier 分数、可靠性图与 ECE；另外统计“均不符合”、长上下文、选项换序和输出越界的失败率，再用独立验证集确定人工复核阈值。

这条路线的关键不是给 LLM 换一个神秘的网络，而是把自由续写变成**可枚举、可比较、可校准的选择**。TypeSafe 的产品说明有助于界定目标；具体可运行的方法与证据，以 LLM-as-Jev 论文为准。
