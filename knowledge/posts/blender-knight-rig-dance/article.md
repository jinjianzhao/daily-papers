# Blender 里让盔甲骑士跳舞：从已有 Mesh 到绑骨与舞蹈动作

你已经有一个穿盔甲的骑士模型，希望它跳一段舞。最短的答案是：**通常需要一套能驱动身体关节的骨架，并让模型正确跟随骨架；然后给骨架套上舞蹈动作。**“绑骨”只是这条链中的一部分。一个模型即使看起来像人，也不一定已经有骨架、蒙皮权重或动画。

这篇文章以这个骑士为例，走完一条可在 Blender 中操作的路径：检查模型 → 准备网格 → 骨架与蒙皮 → 找到舞蹈动作 → 重定向与修正 → 导出。

## 1. 先判断手里的“模型”究竟是什么

你提到的 SDF，通常指 **signed distance field（有符号距离场）**：空间中每个位置记录它到表面的距离，并用正负号区分内外。它适合表示或生成三维形状，却不是 Blender 里可直接绘制顶点权重的角色网格。如果手里只有 SDF/体素，先提取出表面 Mesh，再清理和分件；如果你说的“SDF”其实是生成模型的内部表示，而交付文件已经是 GLB/OBJ/FBX，就以导出的 Mesh 为起点。

在 Blender 里导入文件后，先看右上角 **Outliner**：

| 看到什么 | 意味着什么 | 下一步 |
| --- | --- | --- |
| 只有 Mesh 对象 | 有外形，未必能动 | 检查拓扑、分件，再创建或获取骨架 |
| 有 Armature 对象，Mesh 上也有 Armature Modifier | 通常已有骨架驱动关系 | 进入 Pose Mode 转动骨骼，检查变形 |
| Dope Sheet 的 Action Editor 里有动作，或 NLA 里有动作条 | 可能已经有动画 | 播放时间轴，确认动画确实驱动这个骑士 |

这些只是检查线索：例如有 Armature 但网格没绑定，转骨骼仍不会让盔甲跟着动。GLB、FBX 可以携带骨架和动画，**文件格式本身不保证内容已包含它们**；OBJ 通常用于静态几何交换，不要预期其中有可直接使用的角色动画。

如果是生成式 3D 提取出的网格，还要特别看腋下、胯部、膝肘关节：这些地方常有粘连、破洞或没有合理分件。骨架能移动顶点，不能自动把粘在一起的硬甲分成可活动的肩甲和胸甲。此时应先修网格或把硬件拆为对象，之后再绑定。

## 2. “绑骨”实际包含哪几件事

把骑士想成一套戏服，骨架是演员，网格是衣服：

1. **建骨架（rigging）**：安排骨骼层级，例如髋部 → 大腿 → 小腿 → 脚。父骨移动会影响子骨。
2. **蒙皮（skinning）**：决定网格各顶点跟随哪些骨骼、跟随多少。这些系数叫**权重**。肘部周围的布料顶点可能同时跟随上臂和前臂；胸甲则适合几乎完全跟随胸部骨骼。
3. **做动作（animation）**：在不同时间记录骨骼姿态。舞蹈动作通常已经是某套骨架上的骨骼关键帧，而不是一段能无条件贴到任何 Mesh 上的“视频”。

因此，真正的流程是“Mesh ← 权重/刚性父子关系 ← 骑士骨架 ← 舞蹈动作”。模型本来已有可用骨架时，你可以跳过重新绑骨，直接处理动作匹配。

## 3. 先准备骑士模型：硬甲、链甲和披风不要混为一谈

穿盔甲的角色难点不是“人形能否弯曲”，而是不同部件的运动规律不同：

- **胸甲、头盔、护腿板等硬质金属**：应保持形状。若是独立对象，可以选对象、再选对应骨骼，把它父级到骨骼；或者让顶点几乎 100% 归属一根骨骼。把整块胸甲做平滑权重，跳舞时可能像橡胶一样扭曲。
- **肩甲、护肘、裙甲片**：分别跟随合适骨骼，检查旋转时的铰接空间；肩甲尤其容易撞到胸甲。必要时调整枢轴、分件或增加辅助骨，而非只刷权重。
- **关节链甲、内衬和软布**：需要跨关节平滑变形，可以用多骨权重。关节处至少要有足够的网格边环，否则即使权重正确也会折出尖角。
- **披风**：先让领口/肩部固定在角色上，再决定是简单骨骼摆动还是 Cloth 模拟。若选 Cloth，可参考站内 [Blender 布料模拟文章](article.html?slug=blender-cloth-simulation)；高速舞蹈时还要处理角色与披风碰撞。

一个实用起步法是先隐藏披风和复杂装饰，只让“身体代理网格 + 主要硬甲”完成一段舞。身体不穿插后再加其他层。

## 4. 在 Blender 中给没有骨架的骑士绑骨

### 4.1 摆好标准姿态和骨架

模型最好站直，双臂展开成清晰的 T-pose 或 A-pose，左右对称、脚踩地。这个**静止姿态（rest pose）**是后续权重和动作重定向的参照。若模型已经在做复杂动作，先整理回自然站姿，否则自动绑骨和动作对齐都更困难。

在 Blender 中可以通过 **Add > Armature > Single Bone** 创建骨架，然后在 Armature 的 Edit Mode 中挤出骨骼，依次搭建脊柱、颈、头、双臂、双腿。为了看到盔甲内部的骨骼，可在 Armature 的 Object Properties 中开启 **In Front**。初学者也可以用 Blender 附带的 **Rigify** 插件建立人形控制骨架，但生成的控制骨架与动作文件骨架并不一定同名或同层级，后面仍可能需要动作重定向。

骨骼应放在**关节转轴附近**：膝骨骼接点靠近膝盖，肘接点靠近肘部。建完后先在 Pose Mode 转动一条腿，确认膝盖朝正确方向弯，不要一上来导入舞蹈动作。

### 4.2 建立蒙皮和修正权重

对需要柔性变形的身体/链甲网格，先选 Mesh，最后 `Shift` 选 Armature，使骨架成为活动对象；在 Object Mode 使用 **Ctrl+P > Armature Deform > With Automatic Weights**。Blender 会建立顶点组和 Armature Modifier，并尝试估计每个顶点受哪些骨骼影响。

接着在 Pose Mode 把手臂抬高、膝盖弯曲，观察腋下、胯部、肘膝。某个点被错误拉走时，在 Mesh 的 **Weight Paint** 中选择相应骨骼的顶点组，增减权重。自动权重是起点，不是质量保证；分离的盔甲片、几何体互相穿过或关节拓扑很差时尤其需要手工处理。

对独立硬甲，可以用 **骨骼父级**或指定单骨权重。要检查 Mesh 的 **Armature Modifier** 是否指向正确骨架、是否重复绑定；重复的 Armature Modifier 容易造成二次变形。

## 5. 舞蹈动作一般去哪里找？

动作可以来自现成动作库、动捕数据，或自己录制/制作。对第一个骑士跳舞实验，先挑**人形舞蹈动作**，比从零逐帧打关键帧快得多。

| 来源 | 适合拿来做什么 | 使用前要确认 |
| --- | --- | --- |
| [Adobe Mixamo](https://www.mixamo.com/) | 搜索舞蹈动作，也可给符合条件的人形角色自动绑骨；常见下载工作流为 FBX | 登录、自动绑骨对模型的要求；下载的是带角色动画，还是针对你已有角色的动画；许可见 [Adobe Mixamo FAQ](https://helpx.adobe.com/creative-cloud/faq/mixamo-faq.html) |
| [Rokoko Motion Library](https://www.rokoko.com/products/motion-library) | 寻找现成的人体动捕动作 | 具体动作是否免费、可下载格式、许可和账户条件，以当时页面为准 |
| [Blender Studio Characters](https://studio.blender.org/characters/) | 学习带骨架的角色资产及其动画组织方式 | 这里主要是角色资源，不等同于“随便下载一个动作就适配骑士”；资产访问和许可逐项确认 |
| [CMU Motion Capture Database](https://mocap.cs.cmu.edu/) | 学习和尝试研究用途的人体动作数据 | 其网站当前可能出现证书/访问问题；先确认动作内容、转换格式和使用条款，再纳入项目 |

**别混淆两类下载**：“带动画的角色”通常有它自己的 Mesh + Armature + Action；“仅动作文件”可能只是一套骨架姿态序列。前者可以先在 Blender 里看到动作，但仍需把动作迁移到你的骑士；后者还要先建立与骑士骨架的对应关系。选择动作时也要看是否有原地舞蹈（in-place）版本：它更容易测试脚步和镜头；需要角色在场景中移动时，再处理 root motion。

## 6. 动作如何真正套到骑士身上

### 情况 A：骑士与动作使用同一套骨架

导入动作文件（例如 **File > Import > FBX**，或启用/使用相应 BVH 导入工具）。选骑士的 Armature，在 **Dope Sheet > Action Editor** 选择对应 Action；播放时间轴查看结果。要连接多段动作，可在 **NLA Editor** 中把 Action 推入动作条，排列起止帧、过渡和循环。

如果同一骨架的动作看起来完全不对，先检查动作作用在哪个 Armature、骨骼命名是否匹配，以及导入时的轴向和比例。只把 Action 名称选上但没有对应骨骼通道，不会凭空产生有效舞蹈。

### 情况 B：动作骨架与骑士骨架不同——需要 retarget

**动作重定向（retargeting）**是在源骨架与目标骨架之间建立映射，再把源骨骼旋转/位移转换过去。它不是复制关键帧那么简单：源动作叫 `LeftArm`，骑士可能叫 `upper_arm.L`；骨骼长短、父子层级、静止姿态也可能不同。通常要完成四件事：

1. 对齐源/目标的标准姿态，至少让身体朝向和手臂姿态相近。
2. 映射髋、脊柱、头、上/下臂、上/下腿、脚等主要骨骼。
3. 处理比例与根骨骼位移：源角色迈一步的距离不能机械套给身高不同的骑士。
4. 预览并修正肩、手、脚，再把转换后的动作烘焙为骑士骨架自己的 Action。

Blender 原生可用约束和烘焙动作搭建重定向流程，也可选用与当前 Blender 版本兼容的 retarget 插件。无论用哪种工具，仍要人工检查结果。尤其要分清 **root motion**（角色整体位移）和脚部相对身体的摆动：根位移缺失会原地滑步，位移重复叠加则可能让角色冲出场景。

## 7. 盔甲骑士跳舞常见的四种失败

1. **脚滑或脚穿地**：调整角色整体比例、地面位置、根运动，再用脚部 IK/脚底约束修正落脚帧。仅把脚的视觉位置“拉回来”可能破坏下一步动作，要看整段时间线。
2. **肩甲穿进胸甲**：先检查分件和旋转枢轴；硬甲改为单骨跟随或辅助骨控制，必要时修改动作幅度。Weight Paint 不会解决所有硬物碰撞。
3. **关节像橡胶、胸甲被拧弯**：把硬甲从软蒙皮里分离，检查是否被多个骨骼平滑影响；软甲区域才保留渐变权重。
4. **披风穿过腿或抖动**：先让主体动作正确，再处理披风。检查固定点、碰撞体和模拟缓存；高频舞蹈动作可能需要提高模拟精度并简化披风碰撞几何。

最终在需要交付的格式中导出（例如 FBX 或 glTF/GLB），并把导出的文件**重新导入一个空场景**检查：骨架、动作、材质、披风和硬甲是否都在。Blender 内播放正常，并不能保证目标软件里完全相同。

## 8. 两条实际可走的路线

**最快做出一段舞蹈**：选一个接近标准人形、分件合理的骑士 → 用 Mixamo 等工具自动绑骨并选择舞蹈动作 → 下载带动画的角色/动作 → 在 Blender 里修胸甲、肩甲和脚滑 → 导出测试。若你的骑士本来就有兼容骨架，直接导入动作和预览会更快。

**自己控制品质**：清理 Mesh 和硬甲分件 → 设计人体骨架与额外肩甲/披风控制 → 自动权重后手工刷关节 → 获取动捕动作 → 对齐姿态并 retarget → 用 IK 和关键帧逐段修正脚、手、盔甲穿插 → 做披风模拟或辅助骨动画 → 烘焙、导出和复核。这条路线费时，但能让“厚重盔甲还跳得可信”成为可控目标。

## QA

### Q1：已有的人物 Mesh 想跳舞，是不是要绑骨？

**大多数情况是。**先查模型是否已带 Armature、权重和动作；如果已有，重点是找到可用动作及匹配骨架。如果只有静态 Mesh，通常需要骨架，并通过蒙皮权重或把硬甲直接绑定到骨骼，让各部分跟随它运动。若只有 SDF/体素表示，先提取并整理 Mesh。盔甲的硬件不必全部做平滑蒙皮。

### Q2：舞蹈动作通常去哪里找？

想最快看到结果，可以从 [Mixamo](https://www.mixamo.com/) 找人形舞蹈动作；想试动捕素材，可看 [Rokoko Motion Library](https://www.rokoko.com/products/motion-library) 或 [CMU MoCap](https://mocap.cs.cmu.edu/)。下载前确认动作格式、是否包含角色和骨架、是否与骑士骨架兼容，以及该素材当时的许可与商业使用条件。不同骨架之间通常还需 retarget，并修脚滑和盔甲穿插。

### Q3：如果骑士是“一个完整 GLB”，能直接把舞蹈动作拖上去吗？

先在 Outliner 找 Armature，并在 Pose Mode 转一根骨骼测试。若只有外形，不能直接套骨骼动作；若有骨架，也要看动作与该骨架是否一致。不一致时，需要对齐标准姿态、映射骨骼并重定向动作。
