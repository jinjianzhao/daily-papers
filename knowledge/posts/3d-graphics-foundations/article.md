# 3D 图形学知识体系：从几何、渲染到物理模拟

## 先回答：3D 图形学到底在解决什么问题

3D 图形学可以看成一条信息加工链：我们用数学对象描述一个场景，规定相机如何观察它，规定光如何与材料交互，最后把结果变成屏幕上的像素。动画和物理模拟则负责让场景随时间变化。

```text
几何与场景数据
    ↓
坐标变换与相机
    ↓
可见性判断、光栅化或光线追踪
    ↓
材质、光照、纹理、体积
    ↓
像素、合成、显示

同时：动画 / 粒子 / 流体 / 布料 / 软体
        持续修改几何和属性
```

例如，画一个会被风吹动的旗帜，至少要回答六个问题：旗帜由哪些三角形组成？它们位于哪个坐标系？相机从哪里看？哪些三角形挡住了别的三角形？布料的质量、拉伸和碰撞如何计算？最终每个像素的颜色如何得到？

本文面向熟悉基本编程、但不假定有图形学背景的读者。每个概念先给直观解释，再给必要的数学形式和工程注意事项。

## 1. 场景、对象与几何表示

### 1.1 场景图和对象

场景（scene）是对象的集合。对象通常包含几何体、材质、变换、可见性和动画数据。场景图（scene graph）用父子关系组织对象：把一个手臂挂在身体下面，身体移动时手臂跟着移动。

一个对象的局部数据与它在世界中的位置分离：同一个网格可以被多个对象实例化，只需给每个实例一个不同的变换矩阵。这是实例化渲染节省内存和绘制调用的基础。

### 1.2 网格、曲线和曲面

- **网格（mesh）**：顶点、边、面以及它们的属性。实时渲染通常把面三角化，因为 GPU 的基本光栅化单元是三角形。
- **曲线（curve）**：由控制点和插值规则定义，适合文字、路径、毛发和管线。
- **参数曲面**：用参数 `(u,v)` 生成连续表面，例如 Bézier/NURBS。建模时保持连续性，渲染时通常再细分为三角形。
- **体素和隐式场**：用网格采样标量场，或用 `f(x,y,z)=0` 表示表面。它们适合布尔运算、流体和体积，但需要考虑分辨率和内存。

### 1.3 网格属性

常见属性包括位置 `P`、法线 `N`、切线 `T`、UV、颜色、权重、材质编号、速度 `v`、质量 `mass`、温度 `temperature` 和自定义组（group）。

属性必须带有明确的**归属元素**：point（点）、vertex（面角）、primitive（面）或 detail（整个几何体）。例如同一个空间顶点在两个面上可能需要不同 UV，因此 UV 常存为 vertex 属性，而不是 point 属性。很多“属性传错了”的问题，本质是归属层级不一致。

## 2. 坐标系和变换

图形学至少会遇到四个坐标空间：

1. **对象/局部空间**：建模软件保存的原始坐标。
2. **世界空间**：场景中统一的坐标，物理模拟通常在这里或在模拟空间进行。
3. **观察空间（view/camera space）**：以相机为原点，便于做投影。
4. **裁剪、归一化设备和屏幕空间**：投影后的坐标，最终映射到像素。

点的齐次坐标写成 `(x,y,z,1)`，方向向量写成 `(x,y,z,0)`。平移、旋转、缩放可以统一为 4×4 矩阵。一个常见的变换链是：

```text
p_clip = P_projection · V_view · M_model · p_object
```

透视投影后要做齐次除法 `(x/w, y/w, z/w)`。工程中要明确矩阵是行向量还是列向量、乘法顺序、右手系还是左手系，否则模型会翻转、相机方向会反过来。

法线不能简单使用位置的变换矩阵，非均匀缩放时应使用模型矩阵逆转置的 3×3 部分，并在插值后重新归一化。

## 3. 相机和投影

### 3.1 透视相机

现实相机中远处物体看起来更小。透视投影可直观写成：

```text
x_screen ∝ f · x / z
y_screen ∝ f · y / z
```

`f` 是焦距相关参数，`z` 越大，投影越小。视场角、宽高比、近裁剪面和远裁剪面共同决定视锥体。

### 3.2 正交相机

正交投影不随深度缩放，工程图和部分 2D/3D 编辑器常使用它。相机类型会直接影响重建、深度估计和训练数据的解释，不能把两者混用。

深度缓冲使用非线性深度，近裁剪面过小会降低远处深度精度；常见工程改进是合理设置裁剪面、使用反向 Z 或更高精度深度格式。

## 4. 可见性、光栅化和光线追踪

### 4.1 光栅化

光栅化把三角形覆盖的像素找出来，再对顶点属性做插值。典型流水线是：顶点着色器变换顶点，裁剪和透视除法，三角形装配，光栅化，片元着色，深度/模板测试，混合和写入目标。

深度测试解决“前面的三角形挡住后面的三角形”，但透明物体需要排序、深度预通过或特殊的加权混合策略。

### 4.2 光线追踪

光线追踪从相机像素发出射线，与加速结构中的三角形求交，再根据材质产生反射、折射或阴影射线。它更接近光学过程，适合复杂反射、软阴影和全局光照，但每像素需要大量随机样本，必须降噪或时空复用。

### 4.3 加速结构

BVH（包围体层次结构）把三角形包在盒子里，射线先与盒子求交，再递归进入可能命中的子节点。AABB、层次更新、TLAS/BLAS、空间划分和实例化决定了动态场景的性能。

## 5. 光照、材质与颜色

### 5.1 局部光照和 BRDF

材质回答“光照射到表面后怎样分配方向”。BRDF `f_r` 把入射方向、出射方向和表面法线联系起来。渲染方程可以简写为：

```text
L_o(x, wo) = L_e(x, wo) + ∫ f_r(x, wi, wo) L_i(x, wi) cosθ dwi
```

PBR（基于物理的渲染）常用 base color、metallic、roughness、normal 等参数。金属和非金属的反射行为不同，roughness 越大，高光越宽。

### 5.2 阴影、全局光照和环境

阴影贴图快速但受分辨率、偏移和级联影响；光线追踪阴影更准确但更贵。环境光、间接反弹、屏幕空间方法和烘焙光照都在近似全局光照，使用时应知道它们对屏幕外物体、动态物体和时间一致性的限制。

颜色要区分线性空间和 sRGB。光照计算应在线性空间进行，显示或保存前再做色调映射和伽马编码；否则会出现亮度和曝光不正确。

## 6. 纹理、UV 和采样

UV 把曲面展开到二维图像。切缝减少展开畸变，但会导致接缝；岛的缩放影响纹素密度。纹理采样要处理过滤、mipmap、各向异性和地址模式，避免远处闪烁和近处锯齿。

法线贴图把切线空间中的小尺度方向变化编码进 RGB。它改变光照方向感，不改变几何轮廓；位移贴图才会改变实际表面。纹理压缩、虚拟纹理和 UDIM 是工程上管理大场景纹理的常见机制。

## 7. 几何处理和表示

建模中的常见操作包括布尔、细分、重网格、简化、平滑、法线修复、孔洞填补、去重顶点和重新三角化。每一步都可能改变拓扑、UV、材质边界和物理属性，因此应保留源网格或版本化中间结果。

LOD（多细节层次）用不同复杂度的网格适应距离和预算。几何压缩和网格量化需要权衡文件大小、误差和解码速度。点云、TSDF、占据场、SDF、神经隐式场和 3D 高斯是不同的空间表示：它们分别偏向采样、体积融合、表面查询或可微渲染。

## 8. 体积、烟雾和流体

体积不是一层表面，而是空间中有密度、温度、速度等场。渲染时沿射线积分吸收和发射。烟雾常用密度场，火焰常同时使用温度和黑体辐射近似。

流体求解通常遵循质量守恒和动量方程。不可压缩流体要求速度场散度接近零，工程上会通过压力投影修正速度。不同求解器可能使用 MAC 网格、粒子法（SPH/PIC/FLIP）或混合方法。网格分辨率、时间步长、边界条件和粘性决定稳定性与细节。

## 9. 动画、骨骼、粒子和模拟

### 9.1 关键帧、曲线和骨骼

关键帧给出少量时刻的值，插值曲线生成中间状态。骨骼动画用关节层级和蒙皮权重把骨骼姿态传给网格；反向运动学（IK）根据末端目标反推关节角。动画约束、空间切换和运动捕捉用于修正或重定向动作。

### 9.2 粒子

粒子是带有位置、速度、年龄、质量、颜色、半径等属性的样本，不等于最终画面中的小球。粒子系统通常包含：发射（出生）、更新（力和速度）、碰撞/约束、死亡、实例化或体积化输出。

```text
emission → forces → integration → collision → death/aging → render
```

粒子可以被渲染为点、精灵、实例网格，也可以作为流体、烟雾或布料求解器的输入。碰撞检测可用 SDF、体素、三角形或简化代理；时间步过大时会穿透碰撞体。

### 9.3 布料、刚体和软体

刚体强调质量、惯量和碰撞；布料强调拉伸、剪切和弯曲；软体还要描述体积保持、压缩和内部约束。求解器一般以离散时间步迭代约束，约束越硬、网格越密，越需要更多迭代或更小时间步。

## 10. 采样、数值稳定性和工程管线

抗锯齿、软阴影、景深、运动模糊和路径追踪都需要采样。随机采样带来噪声，低差异序列、重要性采样、时空复用和降噪降低方差。采样不足会产生闪烁，时间序列中还要检查历史缓存是否错配。

数值问题包括浮点精度、极小三角形、退化法线、穿透、爆炸和非确定性。常用手段有尺度归一化、epsilon、连续碰撞检测、限制最大速度、固定时间步、缓存中间场和记录随机种子。GPU 管线还要关注显存、带宽、同步、分支发散和批量提交。

一个可维护的离线/实时渲染管线通常包含：资产导入与校验、单位和坐标系转换、几何预处理、材质与纹理打包、缓存、渲染、合成、质量检查和版本记录。把模拟缓存和渲染缓存分开，可以避免每次改灯光都重算流体。

## 11. 你提出的 Houdini 思路：流体驱动粒子，再用 Vellum 做气球软体

你的设想可以拆成一条清晰的数据流：

```text
流体速度/碰撞场
        ↓
粒子发射与运动
        ↓
粒子-几何碰撞事件或接触区域
        ↓
传给气球几何的 temperature 属性
        ↓
属性传播 / 平滑 / 阈值判断
        ↓
删除、破裂或释放约束
        ↓
Vellum 软体继续求解
```

### 11.1 流体如何驱动粒子

在 Houdini 中，流体通常提供速度场 `vel`（或分量 `vel.x/y/z`）和碰撞 SDF。粒子可在 POP 网络中采样速度场，把采样到的速度作为加速度、目标速度或额外力。若要表现“流体冲击气球”，不要只把粒子位置复制到表面；应保留粒子速度、质量、半径和碰撞事件，必要时用 POP Collision Detect 或 SDF 距离判断接触。

粒子与气球网格之间可以用最近点、SDF、Ray 或 Point Deform 等方式传递接触信息。最近点只说明空间接近，不一定说明有真实碰撞；更可靠的做法是使用碰撞反馈、相对速度和接触持续时间共同判定。

### 11.2 Vellum 气球和约束

Vellum Balloon 本质上是布料/软体表面加上保持体积的约束。常见数据包括几何、约束几何（constraint geometry）、质量、厚度、弯曲/拉伸参数和压力或体积相关参数。气球是否鼓起、变软或破裂，取决于体积约束、压力、碰撞厚度、子步数和约束迭代。

如果温度只是视觉或逻辑变量，可以将它存为 point 属性并在 Vellum Solver 前后更新；如果温度影响材料强度，则应映射到约束的 stiffness、break threshold 或 pin 权重，而不是简单删除点。

### 11.3 temperature 属性如何传播

一种可控方案是：

1. 在粒子上定义冲击源 `temperature_source`，可由粒子密度、速度、接触时间或流体温度得到。
2. 用 Attribute Transfer、Attribute Blur、Volume Rasterize Attributes 或 SDF 距离衰减，把源值传到气球点。
3. 使用时间积分而不是每帧覆盖：

   ```text
   temperature_next = temperature_prev * exp(-decay * dt) + source * dt
   ```

4. 对温度做 clamp、平滑和滞回，减少阈值附近来回跳变。

属性传播要明确来源和目标的归属层级。粒子是 point，气球表面也可能是 point，但拓扑变化、重网格或 Vellum 输出后点号可能变化，不能把点号当成永久身份；需要用空间位置、id 或稳定的 rest 属性重新匹配。

### 11.4 阈值删除、破裂和“不要删太多”

直接使用 Blast 删除 `temperature > threshold` 的点，确实可以快速做出“烧穿”效果，但它会产生几个问题：网格洞边界不规则、Vellum 约束引用了已删除点、下一帧拓扑突变导致求解器爆炸、阈值抖动造成闪烁。

更稳健的层次是：

1. **逻辑层**：先生成 `hot` 组和连续的 damage 值，不立即删几何。
2. **材料层**：把 damage 映射为拉伸/弯曲/体积约束强度下降。
3. **破裂层**：当连续 damage 超过阈值且满足最小面积、最小持续时间时，只释放局部约束。
4. **拓扑层**：在安全阶段（例如求解前的明确断裂事件）切割或删除面，并重建约束。

如果必须 Blast，可以先用 Attribute Blur 形成连续场，再用分层阈值：`damage > 0.9` 才删除，`0.6 < damage <= 0.9` 只降低约束；同时用 connectivity、最小连通区域和组约束保护关键区域。对“过热导致气球漏气”，通常删面不如降低压力或释放局部 pin/tear 约束自然。

### 11.5 碰撞和时间步的风险

粒子速度很高时，离散碰撞会穿透气球。可增加 substeps、使用连续碰撞、增大碰撞厚度或限制最大速度。流体场、粒子和 Vellum 若使用不同时间步，需要统一采样时刻；否则温度和碰撞会出现一帧延迟。

模拟顺序也很关键：如果温度由本帧碰撞产生，通常在碰撞检测后更新；如果它影响本帧 Vellum 材料参数，则需要在求解前准备好，并接受至少一个子步的延迟，或把更新放入 solver 的可控回调中。

## 12. 一个可执行的 Houdini 原型流程

```text
1. FLIP/DOP 流体：输出 vel、temperature 或 density
2. POP Source：发射带 id、mass、v 的粒子
3. POP Advect by Volumes：采样流体速度
4. POP Collision Detect：记录接触、冲击速度、接触位置
5. SOP Solver：把接触事件转为 point/volume 的 source
6. Attribute Transfer 或 Volume Rasterize：传到气球 rest 网格
7. Attribute Blur + decay：得到稳定 damage/temperature
8. Constraint Properties：按 damage 降低 stiffness 或 break threshold
9. Vellum Solver：处理软体、碰撞、压力和撕裂
10. 最后再做局部重网格、删面和渲染缓存
```

建议先做一个最小实验：静态球、少量粒子、单一温度源，验证属性是否传到正确的点；再加入流体速度；最后才加入 Vellum 撕裂和拓扑变化。每一步把 `temperature`、`damage`、`hot` 组和约束强度可视化，避免把“属性没传到”误判为“求解器不工作”。

## 总结

3D 图形学不是一组孤立软件按钮，而是几何表示、坐标变换、可见性、光照材质、采样、动画和物理在同一条数据流上的组合。Houdini 的优势在于把几何和属性作为可追踪的数据流：流体提供速度和场，粒子携带离散事件，属性传播把事件变成连续表面信号，Vellum 再把信号映射为材料约束或破裂行为。对你的方案，最重要的工程原则是：先用连续的 `damage/temperature` 控制材料，再在受控时机改变拓扑；不要把一次阈值 Blast 当作完整的软体破裂模型。

## QA

### Q1：粒子和流体有什么关系？

粒子是离散样本，流体是连续场。粒子可以读取流体的速度场而运动，也可以反过来把粒子密度反馈到体积场；两者不是同一种数据结构。

### Q2：为什么 temperature 不建议直接等于“删除开关”？

因为温度通常是连续、带衰减和扩散的物理量。先转成连续 damage，再控制约束强度或释放约束，能减少阈值抖动、网格洞和求解器爆炸。

### Q3：Attribute Transfer 后数值不对，优先检查什么？

先检查属性归属（point/vertex/primitive）、源与目标的空间是否一致、搜索半径是否覆盖、目标是否有稳定的 `rest` 或 `id`，再检查是否被后续节点覆盖。

### Q4：Vellum 气球破裂一定要删面吗？

不一定。降低局部约束、释放 pin、降低压力或使用 tear 约束通常更稳定。只有需要真实拓扑洞时，才在受控阶段切割或删除几何。

### Q5：为什么模拟要增加 substeps？

当粒子或软体在一个帧间隔内移动太远时，离散碰撞可能直接穿透，约束也可能被跳过。更小的时间步能提高碰撞和约束的采样频率，但会增加计算成本。
